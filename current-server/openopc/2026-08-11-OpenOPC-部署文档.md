## ⚠️ 关键安全说明

本部署专门为 issue #38（project-local config attack）做了防御：

1. **容器 WORKDIR = /data/opc**（不是 `/app/source`），让 `_find_project_root()` 找不到 `pyproject.toml`，不会自动加载 `/app/source/.opc/config/*.yaml`
2. **OPC_HOME = /data/opc**（独立运行时配置，不读仓库内 `.opc/config/`）
3. **system_config.yaml** 显式设置 `load_project_mcp: false` + `load_project_llm_config: false`
4. **LLM key 仅通过容器 env 注入**，不进任何 `.opc/config/llm_config.yaml` 文件
5. **资源硬限制** 4G 内存 / 2 核 CPU，防止异常占用拖垮宿主
6. **端口仅绑 127.0.0.1**，必须经 nginx 反代才能从公网访问

## 6. nginx 反代配置（公网访问）

`/etc/nginx/sites-enabled/default` 末尾追加：

```nginx
# ===== openopc (OpenOPC 0.1.0) =====
# Container: openopc-app on host loopback :8765 (only bound to 127.0.0.1)
upstream openopc_app { server 127.0.0.1:8765; }

# SPA (App.tsx:76) hardcodes WS URL as ws://hostname:port/ws, ignoring /openopc prefix.
# Add /ws exact-match location to forward WebSocket upgrades to openopc 8765 via nginx.
location = /ws {
    proxy_pass http://openopc_app/ws;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 86400;
}

location /openopc/ {
    proxy_pass http://openopc_app/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

应用：`nginx -t && nginx -s reload`。

## 7. SPA WS 路径 patch（关键！必须做）

OpenOPC 的 Office UI SPA (`frontend_dist/assets/index-*.js`) 在 `App.tsx:76` 把 WebSocket URL **硬编码**为 `ws://${hostname}:${port||8765}/ws`——**忽略 `/openopc` 前缀，端口默认 8765**。在公网 nginx 反代下：

| 没 patch 时 | patch 后 |
|---|---|
| SPA 拼 `ws://101.33.212.119:8765/ws` | SPA 拼 `ws://101.33.212.119/ws` |
| 浏览器直连 8765（被防火墙挡） | 走 nginx → 反代到 `127.0.0.1:8765` |
| WebSocket 一直连不上 | 101 Switching Protocols ✅ |

**patch 命令**（容器内文件，必须用 `docker cp` 走 root 通道，uid 1000 节点用户 `sed` 会 Permission denied）：

```bash
# 1. 备份 + 提取旧字符串
docker exec openopc-app bash -c '
  cp /app/source/opc/plugins/office_ui/frontend_dist/assets/index-*.js /tmp/spa.bak.js
  grep -oE "function lee\(\)\{return.{0,200}" /app/source/opc/plugins/office_ui/frontend_dist/assets/index-*.js | head -1
'

# 2. 写到容器 /tmp（容器外 sed 不会受 node 用户权限限制）
docker cp <(cat <<'EOF'
old='function lee(){return`${window.location.protocol==="https:"?"wss":"ws"}://${window.location.hostname}:${window.location.port||"8765"}/ws`}'
new='function lee(){return`${window.location.protocol==="https:"?"wss":"ws"}://${window.location.host}/ws`}'
import re, pathlib
p = pathlib.Path("/app/source/opc/plugins/office_ui/frontend_dist/assets/index-XXXXXXX.js")
src = p.read_text()
assert src.count(old) == 1, f"匹配数={src.count(old)}，请先 grep 确认唯一"
p.write_text(src.replace(old, new))
print("OK")
EOF
) openopc-app:/tmp/patch-spa.py
docker exec openopc-app python3 /tmp/patch-spa.py

# 3. 验证（容器内 + 走 nginx 都应返回 /ws 无端口）
docker exec openopc-app grep -oE 'function lee.{0,150}' /app/source/opc/plugins/office_ui/frontend_dist/assets/index-*.js
curl -sS http://101.33.212.119/openopc/assets/index-*.js | grep -oE 'function lee.{0,150}'
```

> **⚠️ 容器内文件被改了，重启会丢！** 必须把 patch 写进 Dockerfile（推荐 `COPY --chmod=755 docker-entrypoint-spa-patch.sh /docker-entrypoint-initdb.d/` 思路）或启动脚本。临时解法：`docker commit openopc-app openopc:0.1.0-local-patched && docker compose down && docker compose up -d`。

## 故障排查

| 现象 | 原因 | 修复 |
|---|---|---|
| `uv run opc ui` 启动报错找不到模块 | 容器 WORKDIR 设错，回退到 `/app/source` 触发 issue #38 | 确认 `WORKDIR=/data/opc` |
| LLM key 没生效 | `.env` 文件权限不对 | `chmod 600 /root/.hermes/.env` |
| 端口 8765 已被占 | 别的服务占用了 | `ss -tlnp \| grep 8765` |
| 容器启动慢 | 首次跑 `uv` 装包 | 看 `/tmp/openopc-build.log` |
| 浏览器 WS 一直连接中转圈 | SPA 拼 URL 用了 `:8765` 端口 | 跑 §7 SPA patch |
| `docker exec sed -i ... Permission denied` | 容器是 uid 1000 node 用户 | `docker cp` 走 root 通道（见 §7） |
| SPA patch 后 `docker compose restart` 又失效 | 容器内文件改动没持久化 | `docker commit` 出新 tag 或写 Dockerfile |
| 聊天按钮无响应（WS 通但无流） | `_handle_session_send` 没接 engine | 0.1.0 已知问题，等上游；改用后端直接调 `engine.process_message` |
