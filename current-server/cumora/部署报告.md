## 📋 部署步骤实录

1. **DB 准备** — `createdb cumora`（root/root 用户，已有 postgres + redis 跑着）
2. **clone** — `git clone --depth 1 https://gh-proxy.com/https://github.com/yetone/cumora /data/cumora`（**62 MB**）
3. **.env** — 端口/数据库/Redis/OpenAI 占位/AGENT_RUNTIME_SECRET 高熵
4. **npm install** — ~6 分钟（645 个包，含 Capacitor/Electron/React/Tiptap/Yjs）
5. **tsx server/src/index.ts** — server 启动时**自动建 schema + seed**（6 agents / 3 humans / 9 conversations / 0 messages）
6. **vite build** — 9.8 秒，dist/ 输出 2.7 MB
7. **pm2 双进程**：
   - `pm2 start ./node_modules/.bin/tsx server/src/index.ts --name cumora-server`
   - `pm2 start ./node_modules/.bin/vite preview --port 5182 --host 0.0.0.0 --strictPort --name cumora-web`
8. **nginx 反代** — `/cumora/*` → 5182，`/cumora-api/*` → 5181，注入到 `/etc/nginx/sites-enabled/default` 在 `/python/` 块之前
9. **自验** — `/cumora/` 200 + 静态资源 200 + `<title>Cumora — where agent teams gather`

## ⚠️ 关键发现 & 坑

### 坑 1：GitHub 直连超时（TLS 握手失败）
- **症状**：`git clone https://github.com/yetone/cumora` 报 `GnuTLS recv error (-110)` 或 `connect failed after 135417ms`
- **根因**：本机出口到 github.com:443 HTTPS 握手不稳定（但 raw.githubusercontent.com 和 npm registry 通）
- **解法**：**走 `https://gh-proxy.com/https://github.com/yetone/cumora` 镜像**（国内服务器通用绕法）

### 坑 2：Vite dev EMFILE（too many open files）
- **症状**：`vite --port 5180` 启动后立刻报 `EMFILE: too many open files, watch '/data/cumora/vite.config.ts'`，pm2 反复重启 15 次
- **根因**：Vite dev 用 chokidar 全目录 fs.watch，超过 rootless 容器 ulimit
- **解法**：**`vite build` + `vite preview` 模式**（preview 不监控文件）+ ulimit 调高（备选）

### 坑 3：占位 OpenAI key 也能起 BYOA 服务（README 描述不准确）
- **README 说**："`OPENAI_API_KEY` is the only hard-required variable"
- **实际**：`server/src/env.ts` 里 `required('OPENAI_API_KEY')` **没 fallback**，没 key 直接 fail-fast
- **BYOA 模式 ≠ 不需要 OpenAI key**——BYOA 是**agent brain 不走 OpenAI**（走本地 CC/Codex），但 **server 自己的 small-brain triage gate 仍调 OpenAI**
- **本部署**：占位 key 让 server 启动，**triage 调用失败 = 所有 wake 直接放行给 big-brain engine**——BYOA 单用户场景下无害
- **未来要真跑完整 triage**：需要给 server 一个真实 OpenAI key（但本机无 OpenAI 订阅，按现状跑）

### 坑 4：nginx sites-enabled 备份文件被当 enabled 配置加载
- **症状**：`nginx -t` 报 `duplicate default server for 0.0.0.0:80`
- **根因**：直接 cp 备份到 sites-enabled/，备份文件也被 nginx include
- **解法**：备份用 `.bak` 后缀也仍会被加载，**必须挪出 sites-enabled 目录**（用 `.disabled` 或放到 /tmp）

### 坑 5：port 5180 被 DSH 占
- **症状**：cumora-web 第一次起 vite dev 失败（5180 被 DSH 用着）
- **解法**：改 5182（DSH 在 5180 是 8/15 部署时的硬编码，无法让）
