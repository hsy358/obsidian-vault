## 部署流程（耗时 ~50 分钟）

### 1. 抓文章 + 项目侦察（2 分钟）
- 公众号文章 ID `FOrYPzY2sY-iJgHkHGL1NQ` → GitHub `openJiuwen-ai/agent-studio`
- Apache-2.0 / 18 releases / 完整 docker-compose + 22 services

### 2. 环境准备（3 分钟）
```bash
sudo apt-get install -y openjdk-17-jdk-headless  # JDK 1.8 → 17
```

### 3. 源码下载（30 秒，**ghfast.top 镜像加速**）
GitHub 直连 git clone 极慢（10+ 分钟无进度）。改用：
```bash
curl -L -o /tmp/agent-studio.tar.gz 'https://ghfast.top/https://github.com/openJiuwen-ai/agent-studio/archive/refs/heads/studio-2.0.tar.gz'  # 23 秒完成 44.8 MB
tar xzf /tmp/agent-studio.tar.gz -C /data/agent-studio --strip-components=1  # 141 MB
```

### 4. 编译产物（package.sh 阶段，3 分钟）
```bash
cd /data/agent-studio && bash docker/package.sh  # mvn + pnpm install + 复制源码
```
- Maven 编译 backend (200+ jar): aliyun 镜像 886 KB/s
- Angular 编译 frontend (198 chunks, 121 秒)
- Python runtime 源码复制完成
- `source_hash.sh` 失败（源码无 `.git` 目录），但不影响产物

### 5. Docker 镜像 build（30 分钟）
```bash
bash docker/build.sh all  # 4 应用镜像 + grafana
```
**踩坑：grafana cli 装 victoriametrics-logs-datasource 卡 10+ 分钟**（国内访问 grafana plugin repo 慢）。
**解决**：杀掉 build，改跑 `bash docker/build.sh manager console runtime builder`（**只 build 必需 4 个，跳过 grafana**）。

最终 build 出 4 个应用镜像：
- studio-console: 821 MB
- studio-manager: 1.44 GB
- studio-runtime: 4.38 GB（含 transformers/pymilvus/volcengine SDK）
- studio-builder: 4.22 GB

### 6. 端口冲突排查（5 分钟）
第一次 `deploy.sh all` 失败：
- Redis 6379 → systemd redis-server 占 → 改 `REDIS_EXTERNAL_PORT=6388`
- MySQL 3306 → coze-mysql 占 → 改 `DB_PORT=3388`
- MinIO 9000/9001 → coze-minio 占 → 改 `MINIO_API_PORT=9088 / MINIO_CONSOLE_PORT=9089`

第二次启动 minio 仍失败（9001 已分配给老 minio），单独启动 `docker compose up -d minio minio-init` 成功。

第三次启动3 个 app 仍失败——`docker compose up -d` 默认行为是 pull 镜像，本地镜像不会被使用，去 daocloud 拉镜像返回 403。
**解决**：
1. `docker tag` 4 个镜像到 `docker.io/library/xxx` 默认命名空间
2. 启动加 `--pull=never` 标志 → 7 个容器全 healthy

## 风险与教训

### 教训 1：GitHub 直连 clone 极慢，用 ghfast.top 镜像
直连 `git clone` 10+ 分钟无进度（GitHub 限速）。改 `curl + ghfast.top` 镜像 **23 秒完成 44.8 MB**。**未来所有 GitHub clone 用 ghfast.top**：
```bash
curl -L -o /tmp/x.tar.gz 'https://ghfast.top/https://github.com/<org>/<repo>/archive/refs/heads/<branch>.tar.gz'
```

### 教训 2：Maven aliyun 镜像快，pip 国内慢
- Maven: `aliyun-public` 镜像 886 KB/s，下载 200+ jar 几分钟搞定
- pip (PyPI): 卡在 `transformers / pymilvus / volcengine-python-sdk` 这些大包上，每镜像 build 装 10+ 分钟

### 教训 3：0.1.0 项目早期阶段痛点：插件/工具国内访问慢
`grafana cli plugins install` 卡在境外 plugin repo 上，**无国内镜像**。
**解决**：跳过可选的 observability 服务（grafana），只 build 必需 4 个应用镜像。

### 教训 4：JDK 1.8 → 17 必须装，apt 自动切默认 java
旧 java 是 1.8（guyu 等老项目用的）。AgentStudio 要 17+。
- `sudo apt-get install -y openjdk-17-jdk-headless`
- apt 的 `update-alternatives` 自动切默认 java 到 17
- **副作用**：guyu 等依赖 java 1.8 的服务**会受影响**（但 guyu 是 Spring Boot 2 + JDK 8，**新 JDK 17 仍兼容**——但要观察几天）

### 教训 5：端口冲突排查
AgentStudio 默认端口（3306/6379/9000/9001/31111/31014/31015/80）全部跟现有服务冲突。
**容器内通信走 docker network hostname**（如 `mysql:3306`），**只改 host port 映射**（如 `3388:3306`）不影响容器内。

### 教训 6：docker compose --pull=never + docker tag 到 docker.io/library/
`docker compose up -d` **默认会去 docker registry 验证镜像**（即使本地有），被代理到 daocloud 后 403 Forbidden。
**两步解决**：
1. `docker tag studio-X:1.0.0 docker.io/library/studio-X:1.0.0` 让 compose 在 docker.io namespace 找到镜像
2. `docker compose -p deploy up -d --pull=never studio-xxx` 强制不 pull

### 教训 7：自定义 IMAGE_SOURCE=custom 比 offline 更简单
deploy.sh 提供 `IMAGE_SOURCE` 选项：`ghcr` / `dockerhub` / `offline` / `custom`：
- `offline` 模式要求 `images/*.tar` 文件（要 docker save 镜像到 tarball）
- `custom` 模式直接用 .env 的 `STUDIO_*_IMAGE` 标签，**不需要 tarball**
**推荐 custom**（前提是本地 docker 镜像已 build）

### 教训 8：deploy.sh all 包含 grafana 等可选服务，单独启动更可控
```bash
# 推荐分步启动（先 infra，再 app）
docker compose -p deploy up -d mysql redis minio minio-init
sleep 30  # 等 healthy
docker compose -p deploy up -d --pull=never studio-manager studio-runtime studio-builder studio-console
```
**不要**一次 `deploy.sh all`（会把 grafana + observability 也拉起来，国内访问慢）

| 症状 | 排查 |
|---|---|
| 公网打不开 | `ss -tlnp \| grep 32116` 看 nginx worker；`sudo nginx -t` 验配置 |
| 容器启动失败 | `docker compose -p deploy ps -a`；`docker logs deploy-studio-xxx` |

| pull 镜像 403 | 镜像 tag 缺失 → 跑 `docker tag xxx docker.io/library/xxx`；用 `--pull=never` 启动 |

| 想改源码 | `cd /data/agent-studio/<module>` + `git pull`（如果改远端）；本地源码已 141 MB 完整可改 |
