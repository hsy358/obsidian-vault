# Agno AgentOS - 部署方案分析

> **来源**：何大人 2026-07-25 12:08 转发 GitHub 链接 [agno-agi/agno](https://github.com/agno-agi/agno)
> **分析目的**：评估 Agno + AgentOS 部署可行性 + 给出当前服务器部署手册
> **关联文档**：[`/root/vault/current-server/AgentOS/README.md`](../../AgentOS/README.md)（具体部署步骤）

## 一、项目定位

**Agno** ≠ 单个产品名，而是两层：

| 层 | 名字 | 作用 |
|---|---|---|
| **SDK** | [agno-agi/agno](https://github.com/agno-agi/agno) | Python 库，定义 Agent/Team/Workflow，提供 100+ 集成工具 |
| **运行时** | **AgentOS** | 把 SDK 编写的 Agent 暴露为生产 REST API（含 MCP server） |

**部署目标 = AgentOS**。Agno SDK 只是它的依赖。
**部署模板 = agentos-docker**（自托管 Docker Compose；其他还有 Railway/AWS/GCP/Azure/Fly/Render/Modal/Helm）。

## 二、为什么值得关注

- **官方力推**：agno-agi 主仓库 README 唯一 get-started 路径就是 agentos-docker 模板
- **生产级 feature**：
  - **50+ REST endpoints**（含 SSE 流式 + WebSocket）
  - **JWT-based RBAC**（生产模式默认开启，**无 JWT 拒绝启动**——"安全默认"）
  - **MCP server**（`/mcp` endpoint，OAuth 2.1，claude.ai / ChatGPT web 可直连）
  - **OpenTelemetry tracing** + run history + audit logs
  - **100+ 集成工具**（GitHub / Slack / Postgres / ...）
  - **Cron 调度** + 后台 jobs
  - **多前端**：Slack / Telegram / WhatsApp / Discord / AG-UI / A2A
- **容器即部署**：compose.yaml + compose.prod.yaml，**不需要云厂商**，**VPS / 家用服务器 / 笔记本都行**

## 三、技术架构（来自 compose.yaml + compose.prod.yaml 实读）

```
┌──────────────────────────────────────────┐
│  agentos-api  (容器)                      │
│  ┌────────────────────────────────────┐  │
│  │ agnohq/python:3.12 镜像            │  │
│  │ uvicorn app.main:app --port 8000   │  │
│  │ /docs /agents /mcp /health endpoints│  │
│  └──────────────┬─────────────────────┘  │
│  depends_on: agentos-db                  │
│  extra_hosts: host.docker.internal       │
└──────────────┬───────────────────────────┘
               │ agentos 网络
               ▼
┌──────────────────────────────────────────┐
│  agentos-db   (容器)                     │
│  ┌────────────────────────────────────┐  │
│  │ agnohq/pgvector:18 镜像           │  │
│  │ Postgres 18 + pgvector 扩展       │  │
│  │ 端口 5432（容器内）/ 5432（dev）  │  │
│  │        127.0.0.1:5432（prod）     │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**核心镜像**：
- API：`agnohq/python:3.12`（容器内用 `uv pip sync requirements.txt --system` 装依赖）
- DB：`agnohq/pgvector:18`（自带 Postgres 18 + pgvector 扩展）

## 四、关键技术细节（从 README + compose 抠出）

### 4.1 环境变量（来自 example.env）

| 变量 | 必需性 | 默认 | 说明 |
|---|---|---|---|
| `OPENAI_API_KEY` | **必需** | 无 | OpenAI key（models + embeddings） |
| `RUNTIME_ENV` | 可选 | `prd` | `dev` 关 JWT；compose.yaml 写死 `dev`，compose.prod.yaml 写死 `prd` |
| `JWT_VERIFICATION_KEY` | **生产必需** | 无 | os.agno.com 生成的多行 PEM 公钥（必须用 `"..."` 引号包） |
| `JWT_JWKS_FILE` | 替代 | 无 | 同上，二选一 |
| `AGENTOS_URL` | 生产推荐 | `http://127.0.0.1:8000` | 公网 URL，scheduler + MCP 用 |
| `MCP_CONNECT_SECRET` | 可选 | 空 | 让 `/mcp` 变 OAuth 2.1 server，claude.ai/ChatGPT 直连（≥16 chars） |
| `PARALLEL_API_KEY` | 可选 | 无 | WebSearch agent 用 Parallel SDK |
| `DB_USER` / `DB_PASS` / `DB_DATABASE` | 内部默认 | `ai/ai/ai` | 生产**必改** `DB_PASS` |
| `ENABLE_DEPLOY_CHECK` / `EVALS_TAG` | 可选 | - | 调度 + 评测 |
| `SLACK_BOT_TOKEN` / `SLACK_SIGNING_SECRET` | 可选 | - | Slack 接口 |
| `AGNO_TELEMETRY=false` | 可选 | 开 | 关遥测 |

### 4.2 端口

| 服务 | dev host port | prod host port |
|---|---|---|
| agentos-api | `0.0.0.0:8000` | `0.0.0.0:8000`（同） |
| agentos-db | `0.0.0.0:5432` | `127.0.0.1:5432`（用 `!override` 标签重写） |

### 4.3 鉴权机制（核心安全特性）

- **dev** (`RUNTIME_ENV=dev`)：JWT 关闭，可裸访问 `/agents` 等
- **prd** (`RUNTIME_ENV=prd`)：
  - 无 `JWT_VERIFICATION_KEY` → **app 拒绝启动**（"safe default"）
  - `/health` + `/docs` 仍 public
  - `/agents` 等要 Bearer Token（从 os.agno.com 签发）
  - 2 种 token：用户 token（只能跑自己的 agent）+ admin token（读所有 session）

### 4.4 生产 vs 开发 差异（compose.prod.yaml override）

```yaml
# prod 用 `!reset`/`!override` 标签重写 dev 配置（要 Docker Compose v2.24.4+）
services:
  agentos-api:
    command: uvicorn app.main:app --host 0.0.0.0 --port 8000  # 去 --reload
    volumes: !reset []              # 去 bind mount（dev 热重载用）
    environment:
      RUNTIME_ENV: prd              # JWT 强制开启
      AGNO_DEBUG: "False"
      AGENTOS_URL: ${AGENTOS_URL:-http://127.0.0.1:8000}
      MCP_CONNECT_SECRET: ${MCP_CONNECT_SECRET:-}
  agentos-db:
    ports: !override                # 覆盖 ports 列表
      - "127.0.0.1:5432:5432"       # 仅 loopback（dev 是 0.0.0.0）
```

### 4.5 升级命令（生产）

```sh
git pull
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
# 仅改 .env 不改代码 → 去掉 --build
```

### 4.6 公网 URL 三种方式

```sh
# 临时（cloudflared 随机 URL）
cloudflared tunnel --url http://localhost:8000
# 临时（ngrok）
ngrok http 8000
# 稳定（Tailscale Funnel）
tailscale funnel 8000
```

## 五、当前服务器适配性评估

### 5.1 硬件（已有 101.33.212.119）

- 端口 80 nginx 已被 Dify 用 → 不能直接把 8000 给 nginx，需要挂 `/agentos` 路径
- 端口 443 已被 docker-proxy（Dify HTTPS）占
- 端口 3000 Langfuse、9385 RAGFlow、1455/3100 AgentSpace、8002 某 docker 服务、8080 Dify nginx（已占）
- **端口 8000 当前空闲** ✅
- **端口 5432 已被宿主机 Postgres 16 占**（Dify/RAGFlow 用）→ 必须避开

### 5.2 现有栈复用

- ✅ Docker Compose v2.40.3（≥ 2.24.4，`!reset`/`!override` 支持）
- ✅ 宿主机 Postgres 16（pgvector 扩展已有）—— **但建议用 AgentOS 自带容器**，避免 schema 冲突
- ✅ 宿主机 Redis（密码保护）
- ✅ 宿主机 nginx 80 + docker-proxy
- ❌ uv 没装（无所谓，容器内 `uv pip sync`）

### 5.3 端口分配方案

| 服务 | 容器端口 | 宿主端口 | 备注 |
|---|---|---|---|
| agentos-api | 8000 | **8000** | 直接绑 0.0.0.0:8000，nginx 反代 `/agentos` |
| agentos-db | 5432 | **15432** | 避开本机 5432（Postgres 16） |

### 5.4 公网访问方案

**推荐 nginx 反代**（已经有现成的）：
- 主域 `http://101.33.212.119/agentos` → `127.0.0.1:8000`
- 主域 `http://101.33.212.119/agentos/mcp` → `127.0.0.1:8000/mcp`
- API docs: `http://101.33.212.119/agentos/docs`
- health: `http://101.33.212.119/agentos/health`

**注意 `/mcp` 是 OAuth endpoint**，nginx 要保留 `Upgrade`/`Connection` 头 + 较长超时（SSE）。

## 六、风险与坑（来自文档 + 推测）

### 6.1 JWT 必填坑

**生产模式**必须 `JWT_VERIFICATION_KEY` 或 `JWT_JWKS_FILE`，否则**app 拒绝启动**。
这意味着：
- 部署前先去 os.agno.com 注册 → 拿公钥
- 或**先 dev 模式启动验证**，再切 prod
- 或用 `JWT_VERIFICATION_KEY=disabled` 之类？（需要确认文档）

### 6.2 DB 密码只读一次

**Postgres 只在 volume 首次初始化时读 `DB_PASS`**，后续改 `.env` 不会生效：
- 改密码：`docker compose exec agentos-db psql -U ai -c "ALTER USER ai WITH PASSWORD '<new>';"`
- 重置：`docker compose down -v`（**会 wipe 所有平台数据**）

### 6.3 Docker Compose 版本要求

`!reset` 标签要 v2.24+，`!override` 要 v2.24.4+。当前服务器 v2.40.3 ✅。

### 6.4 telemetry 默认开启

`AGNO_TELEMETRY` 默认发事件（不含 prompt/output）。如要关：`AGNO_TELEMETRY=false`。

### 6.5 OPENAI_API_KEY 必需

容器启动会调用 OpenAI（即使是 health check 也可能要 key）。如果只想试运行，要先去 openai 注册免费 key（$5 credit）。

### 6.6 Live AgentOS Connections 是付费功能

os.agno.com 配 JWT 时是 paid feature，用 `PLATFORM30` 优惠码免一个月。
**绕过方法**：可以跳过 os.agno.com，用自己的 JWT 工具链签发 token（要 `JWT_JWKS_FILE` + 自己管密钥）。

## 七、与德勤 / 工作流的相关性

AgentOS 是 **"AI Native 组织 Workspace" 的候选 stack**：
- **多 agent + workflow + 工具集成** ↔ 德勤 AI Native MVP 的 multi-agent orchestration
- **JWT-based RBAC + 多租户** ↔ 咨询公司的多客户隔离
- **MCP server** ↔ 跟企业内部系统集成（HR / 项目管理 / 工时）
- **OpenTelemetry tracing** ↔ 可观测性 + 可审计
- **Cron 调度** ↔ 自动化报告 / 数据同步

但：
- ⚠️ Agno 是 Python-only，**企业级 .NET / Java 集成不强**
- ⚠️ MCP server 用 OAuth 2.1，但企业 SSO（SAML / OIDC）需要额外集成
- ⚠️ telemetry 走 agno 自己服务器，企业合规要关掉

## 八、决策清单（给何大人）

| 决策 | 默认 | 备选 |
|---|---|---|
| 部署模式 | **prod**（已熟悉 JWT） | dev（无鉴权，仅本地玩） |
| 公网 URL | **nginx 80 反代** `/agentos` | cloudflared 隧道 |
| DB host port | **15432**（避开本机 5432） | - |
| API host port | **8000** | 改 18000 |
| JWT key 源 | **os.agno.com 生成**（试用 PLATFORM30） | 自签 + JWKS |
| MCP server | **开**（设 `MCP_CONNECT_SECRET`） | 关（仅本地用） |
| OpenAI key | **填已有** 或新建 | 暂时不填（容器能起，但 health check 可能报 401） |
| Telemetry | **关**（合规） | 开 |
