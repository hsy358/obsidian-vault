## 三、nginx 反代关键修复（2026-08-08）

### 修复前症状

- 浏览器 `http://101.33.212.119/qm-web/` → 显示 "404 This page could not be found"
- 日志显示 `/me`、`/v1/agents/search` 等请求都返回 404 + 398KB 大小（Dify SPA 的 404 页面）

### 根本原因

**4 个 nginx location 缺失**：

1. `location /web-ui/` — web-ui 容器 SPA 直连（portal 308 后浏览器跳转到 `/web-ui/`）
2. `location /web-ui/assets/` — web-ui 静态资源直连
3. `location ^~ /v1/` — web-ui 内部 fetch `/v1/agents/search` 等需要打到 core 9100
4. `location = /me` — web-ui 内部 fetch `/me` 是 web-ui 自己的端点（需要 portal 注入 portal identity token 后转 web-ui）

**关键约束**：
- web-ui 自己的 `/me` 端点（9102）需要 portal identity token 验证
- portal 只在代理 `/web-ui/...` 时注入 portal identity token
- 所以 nginx `/me` 必须转 portal → portal 注入 token → 代理到 web-ui

### 修复后 nginx 片段（加入 `/etc/nginx/sites-enabled/default` 的 QM 段）

```nginx
# === web-ui 静态直连（2026-08-08 修复假 404）===
location /web-ui/assets/ {
    proxy_pass http://127.0.0.1:9102/assets/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
location = /web-ui/favicon.svg {
    proxy_pass http://127.0.0.1:9102/favicon.svg;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
}
location = /web-ui/manifest.json {
    proxy_pass http://127.0.0.1:9102/manifest.json;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
}
location /web-ui/ {
    proxy_pass http://127.0.0.1:9102/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}

# === QM web-ui 内部 fetch 的 API 端点 ===
location ^~ /v1/ {
    proxy_pass http://127.0.0.1:9100$uri$is_args$args;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_redirect off;
}
location ^~ /api/v1/ {
    proxy_pass http://127.0.0.1:9100$uri$is_args$args;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_redirect off;
}
location = /me {
    # /me 是 web-ui 自己的端点, 需要 portal identity token 验证
    # 调 portal /web-ui/me, portal 会验证 session + 注入 portal identity token 后代理到 web-ui
    proxy_pass http://127.0.0.1:9101/web-ui/me;
    proxy_http_version 1.1;
    proxy_set_header Host $http_http;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Cookie $http_cookie;
    proxy_redirect off;
}
```

## 三.2、/api/* 修复（2026-08-08 第二次）

### 现象

登录后 QM Web UI 主页显示 OK，但所有菜单显示 404 / 403：
- `GET /api/contexts` → 404
- `POST /api/projects` → "HTTP 404"（截图显示）
- `GET /api/sessions` → 404
- 所有 `/api/*` 端点都失败

### 根本原因

nginx `/api/` 段原本指向本体工作站 19080，但本体工作站实际 API 路径在 `/api/v1/` 之外没暴露（`/api/health`、`/api/user` 等 404），而 web-ui 期望所有 `/api/*` 路径打到 web-ui 9102 容器。

### 修复

```nginx
# 替换 /api/ 段: 由 ontology 19080 → portal 9101/web-ui/api/
location /api/ {
    proxy_pass http://127.0.0.1:9101/web-ui$uri$is_args$args;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Cookie $http_cookie;
    proxy_redirect off;
}

# 替换 ^~ /api/v1/ 段: 由 core 9100 → portal 9101/web-ui/api/v1/
location ^~ /api/v1/ {
    proxy_pass http://127.0.0.1:9101/web-ui$uri$is_args$args;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Cookie $http_cookie;
    proxy_redirect off;
}
```

### 为什么 `proxy_pass` 到 portal 而不是 web-ui

跟 `/me` 同理：web-ui 验证身份需要 portal identity token，但 portal 只在代理 `/web-ui/*` 时注入 token。所以 nginx 必须把 `/api/*` 也转 portal，portal 注入 token 后再代理到 web-ui 容器。

### POST 接口 cross-origin 403

portal `sameOriginRequest()` 检查 POST 必须有 `Sec-Fetch-Site: same-origin` + `Origin` 匹配 portal PUBLIC_URL。浏览器 fetch 默认就带这些 header，但**如果 curl 测试不带就 403**。nginx 默认透传所有客户端 headers。

### 已知兼容性问题

- **`/api/v1/sessions`、`/api/v1/health/ready` 等是 ontology workspace 的路径**，UI 上是 ontology web 容器 (3100) 通过 `/api/v1/*` 调用 ontology api 容器 (8080)。现在 nginx 把 `/api/v1/*` 转到 web-ui，导致 ontology workspace 端口 19080 直接访问正常，但通过 nginx 80 进去会 404。**变通**：ontology workspace 改用 `/ontology-api/v1/*` 前缀，或者用户直连 ontology 19080
- **web-ui ↔ core 兼容性**：`/api/files/upload`、`/api/turn` 等会代理到 core `/v1/*`，core 9100 部分端点返 401 unauthorized（需要 source-auth header，不是 portal 身份）
