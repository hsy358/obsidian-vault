## 五、关键问题解决方法

### 5.1 假 404（web-ui 内部 fetch 全部 404）

**症状**：打开 `/qm-web/` 看到 "404 this page could not be found" 或 "Your session ended"。

**根因**：nginx 缺 4 类 location。web-ui 容器内的 JS 用相对路径 fetch `/me`、`/v1/agents/search` 等 API 端点，nginx 收到后没匹配 location → 落到 default → Dify 8080 → 404 + 398KB SPA HTML。

**解决方法**：加 `location /web-ui/`、`location /web-ui/assets/`、`location = /me`、`location ^~ /v1/`、`location ^~ /api/v1/` 全部转到 portal (`/web-ui/...` 路径让 portal 注入 portal identity token)。

### 5.2 "Your session ended" + 跳登录

**症状**：登录后看到 "Your session ended" SPA 页面，浏览器立即跳 `/auth/login`。

**根因**：web-ui 服务器 `/me` 端点需要 **portal identity token** 验证（`AUTH_MODE=portal` 因为 `CORE_SIGNING_SECRET` 已设）。nginx 把 `/me` 直连 web-ui 时没注入 portal identity token → web-ui 返 401 → SPA 显示 "session ended"。

**解决方法**：nginx `/me` 必须转 portal 9101 的 `/web-ui/me`，portal 注入 portal identity token 后再代理到 web-ui 容器。

### 5.3 创建项目"HTTP 404"

**症状**：登录后点击 "New project" → 输入名字 → 提交后 "HTTP 404"。

**根因**：nginx `/api/` 段原本指向 ontology 19080，但 ontology 实际只在 `/api/v1/health/ready` 这一个路径暴露 API，其他 `/api/*` 都 404。QM Web UI 期望所有 `/api/*` 打到 web-ui 9102。

**解决方法**：nginx `/api/`、`/api/v1/` 段全部改为转 portal 9101（`proxy_pass http://127.0.0.1:9101/web-ui$uri$is_args$args`），让 portal 注入 portal identity token 后转发到 web-ui，web-ui 收到后代理到 core `/v1/*`。

### 5.4 POST 接口 "cross-origin request refused"

**症状**：curl 测试正常，但浏览器 POST 返 403 "cross-origin request refused"。

**根因**：portal `sameOriginRequest()` 对 POST 要求 `Sec-Fetch-Site: same-origin` + `Origin` 匹配 portal PUBLIC_URL。curl 默认不设这些 header → 403。**浏览器 fetch 默认会带**，所以**用户实际访问不受影响**。

**解决方法**：nginx 默认透传所有客户端 headers，不需要额外配置。CLI 测试时手动加：
```bash
curl -X POST -H "Sec-Fetch-Site: same-origin" -H "Origin: http://101.33.212.119" ...
```

### 5.5 "login session expired — please try again"

**症状**：输入邮箱后回到 `/auth/callback` 报错。

**根因**：portal OIDC 临时 session（`portal_oidc_tmp` cookie）TTL = 10 分钟。用户从 `/auth/login` 跳到 magic link 邮件，**超过 10 分钟没点回来** → 临时 session 过期。

**解决方法**：**这是用户操作问题**，**重新登录**即可。10 分钟内要点邮件。

### 5.6 /api/v1/* 与 ontology 路径冲突

**症状**：nginx 80 入口访问 `/api/v1/health/ready` 返 404（非 ontology 200）。

**根因**：nginx 把 `/api/v1/*` 改成了走 web-ui（web-ui 没 ontology 路径，返 404）。

**解决方法**：ontology workspace 需要 `/api/v1/*` 时，**直接走 ontology 19080 端口**：`http://101.33.212.119:19080`。或者 ontology 改用 `/ontology-api/v1/*` 前缀。

### 5.7 chat 模块 "couldn't reach"

**症状**：登录后菜单都正常，但 chat 发消息 "couldn't reach"。

**根因**：**开源版 QM Web UI 期望 OpenAI-style API**（`/v1/agents/search` 等），**core 9100 路由能命中但返 401 unauthorized**（core 需要 source-auth header，不是 portal 身份）。这是 web-ui ↔ core 兼容性边界问题。

**解决方法**：
- 走 **portal admin + core API 直调**：`http://101.33.212.119/qm/`（portal admin）能 normal 用
- **CAM chat**：可用 web-ui 项目内的 chat 走 `/api/turn` 端点（web-ui 代理到 core `/v1/turns`）—— 但这个 `/v1/turns` 要 core 支持
- 如需 chat 完整可用，需要给 core 写 OpenAI-style `/v1/agents/search` 适配层
