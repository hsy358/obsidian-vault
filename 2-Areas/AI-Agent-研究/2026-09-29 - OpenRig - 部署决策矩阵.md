## 选 B 的理由
1. SOP 第 4 条（9/10 何大人强化）：**默认值已授权 + 持续执行到完成**
2. 但 OpenRig setup 阶段是**写 ~/.claude.json + ~/.codex/config.toml + ~/.tmux.conf + (macOS) cmux config**——这是**多文件全局写入**，按 MEMORY 风险矩阵属"影响现有服务"的边沿
3. **本机没有任何"被保护的服务"依赖这些 config**（Claude Code 自己是这些 config 的消费者，不是被服务），所以 B 风险实际为**低**
4. 但仍先跑 `rig doctor`（只读检查）确认基线，再 setup，万一 setup 完影响 Claude Code 当前 session 可即时回滚

## 执行计划（auto-OK）

**Phase 1：CLI 安装 + 只读诊断**
```bash
npm install -g @openrig/cli           # 实际安装
rig --version                          # 应输出 0.6.0
rig doctor                             # 只读，不修改任何文件
rig specs list                         # 看可用 rig 模板
```

**Phase 2：dry-run setup**
```bash
rig setup --dry-run                    # 列出全部 setup 步骤，无副作用
rig setup --dry-run --full             # 包含 jq + gh 的扩展版本
```

**Phase 3（需要 user 二次确认才执行）：真 setup**
```bash
rig setup                              # 真改 ~/.tmux.conf；不动 ~/.claude.json/codex.toml（setup 阶段不动）
```

**Phase 4（需要 user 确认）：first-project 试运行**
```bash
rig up first-project                   # 才会真写 ~/.claude.json + ~/.codex/config.toml
```

回滚预案（每步可走）：
```bash
tmux kill-server                       # 关所有 OpenRig tmux session
npm uninstall -g @openrig/cli          # 卸 CLI
# 手动恢复 ~/.claude.json 和 ~/.codex/config.toml:
cp /root/vault/.openrig-backup-20260929-140929/.claude.json ~/.claude.json
cp /root/vault/.openrig-backup-20260929-140929/config.toml ~/.codex/config.toml
# 移除 ~/.tmux.conf 的 managed block
sed -i '/# OpenRig managed block/,/# End OpenRig managed block/d' ~/.tmux.conf
rm -rf ~/.openrig/
```
