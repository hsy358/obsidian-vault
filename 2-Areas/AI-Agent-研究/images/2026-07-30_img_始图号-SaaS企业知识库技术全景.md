  【2. 三类 RAG：能力递进，不是版本替换】（三栏对比表）
  - 标准 RAG | 事实问答：核心=切片→检索→重排→生成；擅长=局部事实、语义引用、高频问题；更新=向量索引需重新构造语料；代价=低延迟、成本可控；短板=缺乏跨文档关系与复杂任务拆解
  - GraphRAG | 关系推理：核心=实体、关系、社区、图检索+问答；擅长=全局主题、关联发现、关系检索；更新=依赖可编辑图谱、社区合并与社区重算；代价=构建、维护和评测成本高；短板=不天然能应对指令与事实溯源
  - Agentic RAG | 检查与行动：核心=规划→多轮检索→工具调用→校验；擅长=多跳问答、多源拼接、任务执行；更新=依赖协调调度索引与工具的新鲜度；代价=延迟、成本、权限和稳定性风险；关系=可编排 标准 RAG 与 GraphRAG
  底部结论：「企业常见组合：标准 RAG 做默认通道，GraphRAG 处理关系问题，Agentic RAG 只在复杂任务中按需调用」

  能力维度（行）vs RAG 类型 + SaaS 平台（列）：局部事实问答+引用 / 跨文档关系 / 全局主题 / 多步规划与工具执行 / 自动检索·摘要·导航 / 权限授权·版本·审计·修订 / 企业权威来源
  难度判断：低 / 复杂 / 依赖不愿 / 取决于不配合度 / 平台能力

  【4. LLM Wiki 派生知识视图与更新机制】
  - 适用场景：角色理解成本
    · 快速生成目录、摘要、架构说明与学习路径
    · 帮助新员工和团队成员快速理解角色与协同
    · 适合代码库、公开资料、稳定文档的探索
  - 使用边界：不直接充当事实来源
    · 价格可被各专题生成中的观点或关联错误影响
    · 构思、存档、词典、订单等事实回答回到原始系统
    · 权限、删除传播、责任人与审计属于平台治理能力
  - 更新机制：实时增量与页面级生成后再同步
    一次更新通常包含变更检测、检索索引更新、受影响页面重生成三个环节。底层索引可以增量更新，生成层可能按周期、批次或子任务逐项"页"摘要来扩展。公开文档只写"regenerate"时，能不根据此判断改变文章覆盖密度；也不根据新旧任务页面增删。完整的更新能力还包括低级联动：删除传播、权限同步、失效页面和生成流程的闸板。

  【5. 对 SaaS 知识库的冲击：功能商品化、治理成为护城河】
  - 被快速商品化：自动目录与页面生成、摘要、标签、关系推荐、跨链接与问答、基础权限与可问
  - 仍难替代：多源串联与数据治理、SSD、权限模型与权限细则、版本、审计、修订与责任人、实时权限、删档维护与质量评测
  - SaaS 厂商的竞争点会从"有没有 AI 问得"转向"答案是否在正确粒度"——基于最新、可追溯、经治理的知识

  - 部门研究与知识助手 | 中等 | 适合作为生产端，治理需外接

  - 强监管场景合规固话库 | 低 | 不宜独立承担

**四个关键判断（图中明确写出）**：

1. **Obsidian 是上游生产工具**，可成为企业组件，但**不等于权威底座**
2. **Agentic RAG 可编排**标准 RAG + GraphRAG（不是替代）
3. LLM Wiki **是理解层 / 导航层**，不是新的事实源
4. **最终体验可同时调用**治理、检索、推理与行动

### 板块 2：三类 RAG 能力递进

| 类型 | 核心 | 擅长 | 更新 | 代价 | 短板 |
|---|---|---|---|---|---|
| **标准 RAG** | 切片→检索→重排→生成 | 局部事实 / 语义引用 / 高频问题 | 向量索引需重建 | 低延迟 / 成本可控 | 缺跨文档关系 & 复杂任务 |
| **GraphRAG** | 实体+关系+社区 / 图检索+问答 | 全局主题 / 关联发现 / 关系检索 | 图谱可编辑 / 社区合并 & 重算 | 构建+维护+评测成本高 | 不天然应对指令 & 事实溯源 |
| **Agentic RAG** | 规划→多轮检索→工具→校验 | 多跳问答 / 多源拼接 / 任务执行 | 协调索引+工具新鲜度 | 延迟 / 成本 / 权限 / 稳定性风险 | — |

**企业常见组合**（原图底部）：标准 RAG 做**默认通道**，GraphRAG 处理**关系问题**，Agentic RAG 只在**复杂任务中按需调用**。

### 板块 4：LLM Wiki 适用场景 + 更新机制

**适用场景**：
- 角色理解成本（快速生成目录、摘要、架构说明、学习路径）
- 帮助新员工 / 团队成员快速理解角色与协同
- 适合代码库 / 公开资料 / 稳定文档的探索

**使用边界**（重点！）：

> LLM Wiki **不直接充当事实来源**。
> - 价格可被各专题生成中的观点 / 关联错误影响
> - 构思、存档、词典、订单等事实回答必须回到**原始系统**
> - 权限 / 删除传播 / 责任人与审计 **属于平台治理能力**

**更新机制**：实时增量 + 页面级生成后再同步 = 三个环节：

1. 变更检测
2. 检索索引更新（底层可增量）
3. 受影响页面重生成（按周期 / 批次 / 子任务逐项"页"摘要）

**完整更新能力还包括**：删除传播、权限同步、失效页面、生成流程闸板。

### 板块 5：对 SaaS 知识库的冲击

| 被快速商品化 | 仍难替代 |
|---|---|
| 自动目录与页面生成 | 多源串联与数据治理 |
| 摘要 | **SSD**（Single Source of Duty？） |
| 标签 | 权限模型与权限细则 |
| 关系推荐 | 版本 |
| 跨链接与问答 | 审计、修订与责任人 |
| 基础权限与可问 | 实时权限 |
|  | 删档维护与质量评测 |

**核心论断**：

> SaaS 厂商的竞争点会从「**有没有 AI 问得**」转向「**答案是否在正确粒度**」——基于最新、可追溯、经治理的知识。
