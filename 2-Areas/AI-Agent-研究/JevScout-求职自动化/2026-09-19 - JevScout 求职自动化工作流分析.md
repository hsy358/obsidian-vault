# JevScout 求职自动化工作流分析

> **来源**：hqman 在 Pi Coding Agent 视频里展示的实战 demo
> **GitHub**：https://github.com/hqman/JevScout
> **作者**：hqman（Pi Coding Agent 官方核心贡献者之一）
> **核心标语**：*"Chrome sees and acts. Jev decides. The host CLI runs one command."*

---

## 一、JevScout 是什么

一个**自动化求职技能包**（Demo MVP），基于 Pi Coding Agent 构建。它能：

- 打开任何公司官网（如 openai.com）
- 让 Chrome 自动浏览页面（**可见非 headless**，可观察）
- 把每个链接/岗位调给 **Jev（TypeSafe System One）** 打分筛选
- 主 LLM 永远不直接决定"点什么"——决策权交给专用打分模型

### 核心架构

```
┌─────────────┐  CDP  ┌──────────┐  API  ┌──────────────┐
│  Host CLI   │◄──────┤  Chrome  │       │ Jev (打分)   │
│  (jjh run)  │──────►│  可视化  │       │ TypeSafe S1  │
└─────────────┘       └──────────┘       └──────────────┘
       │                                        ▲
       └────── Pi Coding Agent 编排 ────────────┘
```

- **jjh（host CLI）**：跑 `uv run jjh run --url <公司>` 一行命令启动
- **jjh 直接控制 Chrome via CDP**（不需要 Chrome DevTools MCP，可选）
- **可选 Jev API key**，没 key 加 `--mock` 也跑得起来

## 二、关键命令行速查

| 命令 | 作用 |
|---|---|
| `uv run jjh run --url https://openai.com --query "Applied AI Engineer, Codex"` | 跑全流程 |
| `uv run jjh run --companies openai --query "..."` | 简化写法 |
| `uv run jjh run --mock --max-pages N --tab reuse` | 无 API key 跑 |
| `uv run jjh log` | 看历史 |
| `uv run jjh report` | 生成报告 |
| `uv run jjh start --mock` | 启动 CDP 服务 |
| `uv run jjh step --page <fixture.json>` | 单步调试（用 mock page） |
| `uv run pytest -q` | 跑测试 |

**测试夹具**：项目自带 `tests/fixtures/openai_home.page.json`、`openai_careers.page.json`、`openai_job.page.json` 三个快照。

## 三、为什么这个架构牛

### 1. "决策/执行"分离
- **Chrome** 只负责"看 + 动"（纯执行器）
- **Jev** 只负责"打分 + 决策"（专用模型，token 省）
- **Host CLI** 只负责"编排"（不参与决策）

→ **三方解耦**，主 LLM 不被"点哪个链接"这种低价值决策拖累。

### 2. 可观察性
- **可见 Chrome**（不是 headless）—— 你能盯着看 agent 在干什么
- 测试夹具支持**单步回放** —— 出错可重放

### 3. 可移植
- "任何公司主页都能跑"—— 不依赖特定招聘平台（Greenhouse/Lever/Workday 都能爬）
- `--companies openai` 只是 alias

### 4. 安全 + 经济
- 默认无 Jev key 也能用（mock 模式）
- 决策模型比通用 LLM 便宜 1-2 个数量级

## 四、对何大人的求职场景适配

### ✅ 核心论点：直接套到 3 个求职项目上

| 项目 | 目标 | 用 JevScout 怎么改 |
|---|---|---|
| **求职-德勤** | AI Native Workspace 岗位 | `--url deloitte.com/careers --query "AI Native Agent Workspace"` |
| **求职-DJI** | 大疆 AI/机器人 | `--url dji.com/careers --query "AI Engineer Robotics"` |
| **求职-AI-工程师** | 全网撒网 | 跑 `--companies openai,anthropic,dji,deloitte --query "AI Engineer"` |

### 5 步即可落地

```bash
# 1. clone
git clone https://github.com/hqman/JevScout ~/JevScout
cd ~/JevScout

# 2. 装依赖
uv sync

# 3. 配 .env（mock 模式无需 key）
cp .env.example .env

# 4. 启动可见 Chrome，跑德勤
uv run jjh start --mock
uv run jjh run --url https://www.deloitte.com --query "AI Native Workspace Agent"

# 5. 看报告
uv run jjh report
```

### 🎯 进阶：接 Hermes 学习循环

JevScout 是 **无状态**的（每次跑都从零开始）。如果接上 Hermes 的学习循环，可以变成：

```
JevScout 发现新岗位 → Hermes 记忆 → 下次自动优先展示相似岗位
                                ↓
                          自动改写简历段落
                                ↓
                          投递状态跟踪
```

→ 这就是 **"求职 while you sleep"** 完整闭环（Substack 上一篇文章讲的就是这个思路）。

## 五、给何大人的核心洞察

1. **架构思路值得抄**：决策模型（TypeSafe/Jev）+ 执行器（Chrome）+ 编排器（host CLI）的三层分离，是任何"长链路自动化任务"的通用模板。求职只是 demo case。

2. **德勤 MVP 可以借这套**：你之前说要做的"执行器抽象层"—— JevScout 就是个**最小可运行参考实现**。比 LangGraph adapter（414 行那个）更轻量、更易理解。

3. **mock 模式是加分项**：意味着求职场景可以**离线 demo 给德勤看**（不带任何商业 API key），降低首次接触门槛。

4. **跟 Hermes 的互补点**：JevScout 解决"找 + 筛"，Hermes 解决"学 + 记 + 改简历"。**两个组合才是完整求职 agent**。
