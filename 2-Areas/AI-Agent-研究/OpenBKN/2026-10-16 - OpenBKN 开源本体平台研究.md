## 一、项目概览

**OpenBKN** = Open Business Knowledge Network

定位：本体驱动的业务知识网络平台。通过本体建模，把散落在文档、系统、流程、规则、专家经验里的数据逻辑，转化为 AI Agent 能理解、执行、验证的业务知识网络。

核心理念：不只是生成答案，是产出可执行、可追溯、可验证的业务价值。

官网：https://openbkn.ai

## 四、6 大核心模块详解

### 4.1 BKN Engine（知识网络引擎）
核心：把业务对象、关系、动作、概念组转化为领域知识网络，支持查询/分析/Agent调用/业务应用开发。

**本体四要素（与 Palantir Foundry 完全同构）：**

| 要素 | OpenBKN 术语 | Palantir 术语 | 说明 |
|---|---|---|---|
| 实体 | 对象类 (Object Type) | Object | 人/物/订单/设备 |
| 关系 | 关系类 (Link Type) | Relationship | 工厂→拥有→产线 |
| 动作 | 行动类 (Action Type) | Action | 订单→消耗→物料 |
| 概念 | 概念组 (Concept Group) | — | 业务语义分组 |

### 4.2 VEGA Engine（数据虚拟化引擎）
连接、模型、视图与统一查询。把数据库和数据视图组织成可被知识网络理解、搜索、绑定业务语义的资源。

### 4.3 Context Loader（上下文加载器）
面向智能体的上下文组装，三阶段：
1. **Recall** — 语义召回
2. **Coarse Ranking** — 粗排
3. **Fine Ranking** — 精排

解决 Agentic RAG 的精确度/一致性/可解释性问题。

### 4.4 Execution Factory（执行工厂）
工具、算子与技能（SKILL 包）管理。

当前已发布的 SKILL 包全部是**供应链决策**场景：
- supply-en-sales-signing（销售签约）
- supply-en-production-schedule（生产排程）
- supply-en-demand-fulfillment（需求履行）
- production-schedule-backward（齐套倒排）
- demand-fulfillment-risk-summary（风险汇总）
- demand-fulfillment-requirement-check（需求可接受性检查）
- demand-fulfillment-capacity-analysis（产能分析）

### 4.5 BKN Safe（安全治理）
ISF 级别的安全体系：身份、权限、策略、审计。

### 4.6 BKN Trace（可观测性）
链路追踪、指标、证据链式可观测。

## 五、BKN Studio 前端能力

Web 控制台提供统一工作空间，覆盖：

**业务知识建模：**
- 管理知识网络、对象类型、关系类型、行动类型、概念组
- 绑定业务对象到数据资源视图，建立业务语义与数据实体的映射
- ContextLoader 调试台验证知识网络在 Agent 检索和工具调用中的行为

**数据资源治理：**
- 创建和管理数据连接
- 扫描和维护数据目录、数据资源、数据视图
- 配置全文和向量索引

**工具能力生产：**
- 管理算子、工具、工具箱、能力
- 从 OpenAPI 或 cURL 导入接口能力
- 预览、调试、发布、导出工具能力

**模型管理：**
- 大模型和小模型配置
- 测试连接、设置默认模型、查看模型监控

**Agent 调试：**
- 对话调试和工具调用
- 查看工具调用过程、延迟、token 使用量
- MCP 工具列表和 API Key 管理

## 六、与 Hermes Agent 的关系

```
Hermes Agent v0.14              OpenBKN
─────────────────────────────────────────────────────────────
业务语义建模                    →  BKN Engine（对象/关系/行动类）
执行器抽象层                    →  Execution Factory（SKILL包/算子）
RAG Context 组装                →  Context Loader（recall→粗排→精排）
可观测性                        →  BKN Trace
安全治理                        →  BKN Safe
Agent 调度                      →  bkn-sdk（统一接口）
Web 控制台                      →  BKN Studio（React）
```

**关键结论：两者是互补路线，不是竞争路线。**
- **OpenBKN** 侧重本体建模 + 知识网络 + 数据虚拟化
- **Hermes** 侧重工作流编排 + 多 Agent 协作 + 执行调度
- 理想形态：**Hermes 作为执行器，OpenBKN 作为业务语义层**

## 七、部署要求（当前服务器不满足）

| 项目 | 当前服务器 | OpenBKN 最低要求 |
|---|---|---|
| CPU | 2 核 | 2 核（勉强达标）|
| 内存 | 3.6 GB（可用 2.1 GB）| 16 GB+（全套数据服务）|
| 磁盘 | 59 GB（已用 88%，剩 7 GB）| 100 GB+ |
| Kubernetes | ❌ 没有 | 必须（kubeadm 或 k3s）|
| Go | ❌ 没有 | 需要 |
| Helm | ❌ 没有 | 必须 |

**全套数据服务（必须）：** MariaDB + Redis + Kafka + OpenSearch + BKN Foundry 各微服务 → 至少 16 GB 内存 + 50 GB 可用磁盘。
