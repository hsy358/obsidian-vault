# 零信任 Agent 平台推荐架构详解

## 核心理念

> Agent 在沙箱里运行，与外部的每一次交互都经过网关，网关只受控于控制平面的策略。
> 参考：Google / AWS / Microsoft / Anthropic / OpenAI 等企业 Agent 平台实践。

---

## 架构总览：控制平面 + 三大网关

```
┌─────────────────────────────────────────┐
│         AI 控制平面（PDP）                │
│  注册表 / 身份委托 / 策略决策 / 配置版本    │
│  发布门禁 / 预算配额 / 审批服务 / 紧急停止  │
└────────────┬────────────────────────────┘
             │ 策略下发
    ┌────────┼────────┐
    ▼        ▼        ▼
┌──────┐ ┌──────┐ ┌────────┐
│入口   │ │工具   │ │模型    │
│网关   │ │网关   │ │网关    │
│PEP   │ │MCP    │ │PEP    │
└──┬───┘ └──┬───┘ └───┬────┘
   │        │         │
   └────────┴────┬────┘
                 ▼
         ┌───────────────┐
         │ Agent 运行时   │
         │ (沙箱 microVM)│
         └───────┬───────┘
                 ▼
         ┌───────────────┐
         │   模型池       │
         │ 闭源+开源+定制 │
         └───────────────┘
```

---

## 一、控制平面（PDP）

| 模块 | 职责 |
|------|------|
| 注册表 | Agent、工具、Skills、模型、外部 Agent、负责人、版本、风险等级 |
| 身份与委托 | Agent 独立身份令牌；用户+Agent+范围+时效 |
| 策略决策 | 策略即代码（Cedar/OPA），参数级可测试 |
| 配置与版本 | 提示、技能、工具描述、路由规则，全部版本化 |
| 发布门禁 | 评估通过才生效；灰度发布，一键回滚 |
| 预算与配额 | 按团队/Agent/任务设 Token 与成本上限 |
| 审批服务 | 高风险动作推送 IM 审批，超时默认拒绝 |
| 紧急停止 | 一键吊销身份令牌、冻结 Agent、回滚版本 |

---

## 二、三大网关（均为 PEP + OTel）

### 入口网关（Inbound Gateway）
- SSO 认证 → 委托令牌 → 输入护栏 → 会话路由/限流
- A2A 入境站点（校验外部 Agent）
- 事件接入（Webhook/定时/数据变更）

### 工具网关（MCP Gateway）
- 只暴露已注册工具与 Skills，参数级授权
- 凭据注入（Agent 看不到密钥）
- 高风险 → 审批挂起
- 返回清洗（剥离可链指令、敏感冗长）

### 模型网关（Model Gateway）
- 统一 API（兼容主流模型协议）
- 路由（速度/敏感度/成本/时延）
- 配额 + 缓存 + PII 脱敏
- 计量-降级（按租户分级、故障切换）

---

## 三、Agent 运行时

- **编排者 Agent**：理解目标、拆解任务，优先用工作流
- **Harness 循环**：收集上下文 → 决策 → 行动 → 验证
  - 记忆服务（会话/长期记忆，按用户与租户隔离）
  - 持久执行（检查点、断点续跑、审查挂起点）
  - 代码与浏览器沙箱（microVM，访问只走代理白名单）
- **子代理 × N**：独立上下文、并行执行、只回传精炼结论

---

## 四、模型池三层

| 类型 | 示例 | 用途 |
|------|------|------|
| 前沿闭源 | Claude / GPT / Gemini | 复杂规划与推理 |
| 私有推理集群 | Qwen / DeepSeek / GLM / Kimi（vLLM/SGLang）| 成本优化 |
| 批处理 | 离线评测/数据处理 | 闲时算力半价 |
| 定制小模型 | 微调/蒸馏 | 高频任务 |

---

## 五、四大落地场景

1. **上下文服务**：MCP — 业务语义层、权限感知检索、知识图谱、Skills 库
2. **企业系统 MCP 化**：ERP / CRM / HR / ITSM / 代码库 / 数据库 / 邮件-IM
3. **外部 Agent A2A**：校验签名的 Agent Card，不开私有接口
4. **互联网与 SaaS**：带代理访问，域名白名单，只放不可信输入

---

## 六、六大黄金规则（Rule 1-6）

| # | 规则 | 说明 |
|---|------|------|
| 1 | 唯一出入口 | Agent 不直接连模型/工具/数据/外网，一切经网关 |
| 2 | 决策与执行分离 | 控制平面决策，网关执行；模型"想搞"不等于"能搞" |
| 3 | 一切皆注册、皆版本 | 未注册不可调用，任何变更要过评测 |
| 4 | 双重身份、最小权限 | 用户+Agent 委托身份，令牌短、授权小 |
| 5 | 会话即沙箱 | 运行时无状态、用完即弃，状态从外部存储 |
| 6 | 遥测与成本内建 | 每个请求带租户/Agent/任务标签，全链路可追溯可分账 |

---

## 七、改进飞轮（OTel 统一上报）

```
采集（每次调用均为 span，带租户/Agent/任务标签）
  → 轨迹库（可检索、可回放、与审计关联）
  → 评测（离线索集/榜单、线上 LLM 评委）
  → 归因（上下文缺失？工具描述不清？模型能力不足？）
  → 优化（改提示/工具/Skills/路由）
  → 发布（经门禁写到控制平面）
```

## 八、对德勤 MVP 的参考价值

**直接可借鉴的组件：**

| 德勤 MVP 现状 | 架构图建议 | 对应组件 |
|---|---|---|
| Hermes Agent（编排者）| → | Agent 运行时编排者 |
| OpenClaw / AgentRouter（执行器抽象层）| → | Agent Runtime（Harness 循环）|
| 尚未建立 | **入口网关**（认证/委托令牌/输入护栏）| 缺失，需补充 |
| 尚未建立 | **工具网关 MCP** | 缺失，需补充 |
| 尚未建立 | **控制平面**（注册表/策略/配额/审计）| 部分缺失 |

**关键差距：**
- ❌ 无显式入口网关（认证/委托/护栏）
- ❌ 无 MCP 工具网关
- ❌ 无控制平面（注册/策略/配额/审计）
- ⚠️ 改进飞轮（OTel）尚未建立
