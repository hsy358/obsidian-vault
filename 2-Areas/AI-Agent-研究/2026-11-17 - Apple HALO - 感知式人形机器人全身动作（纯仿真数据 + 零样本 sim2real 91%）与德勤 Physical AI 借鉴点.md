# Apple HALO 分析（2026-11-17）

> **一句话**：苹果把"人形机器人数据瓶颈"用**纯仿真合成**打穿了 —— 1000 套程序生成的住宅、300 小时
> 第一视角「图像+语言+全身动作」三元组语料，训练出三层全机载栈（编排器 / 动作生成器 / 感知式跟踪器），
> 在**从未扫描、从未建图、训练时没见过**的 6 个真实家庭环境里做 360 次试验，**单任务成功率 91%**（仿真同样 91%），
> 复合多任务 70%。代码全量公开，但**许可是 Apple 专有协议，不是 MIT/Apache**。

## 1. 核心机制

### 1.1 三层机载栈（这是最值得抄的骨架）

| 层 | 频率 | 模型 | 输入 | 输出 | 跑在哪 |
|---|---|---|---|---|---|
| **Orchestrator 编排器** | ~0.5 Hz | VLM（本地 **Qwen3.6-35B-A3B**，4-bit MLX，可切云端 frontier 模型） | 自由语言指令 + 第一视角视频 | **有序子任务序列**（每步一个技能 + 一个对象） | Mac mini M4 Pro 64GB |
| **Motion Generator 动作生成器** | 3 Hz | **冻结的 Qwen3.5-2B VLM 编码器** + **从头训练的 DiT 解码器**（8 block / width 512 / 8 head，flow matching，推理 15 步 Euler） | 当前子任务 + 第一视角 RGB | **5 秒 × 30Hz 全身运动计划**（每帧 29 关节角 + 骨盆 3D 平移 + 4D 四元数 = 36 维，相对骨盆系） | Mac mini M4 Pro（`halo_serve` 与编排器共服务） |
| **Motion Tracker 跟踪器** | 50 Hz | RL 训练的低层策略（本体感知 student，深度可选） | 运动计划 + **第一视角深度** + 本体感知 + IMU | 关节位置目标（PD 执行） | 机器人本体 **Jetson Orin NX**（C++ / PREEMPT_RT） |

**分工一句话**：前两层解决"语义"（是哪把椅子？），第三层解决"物理"（椅子到底在哪儿，重心怎么转移）。

### 1.2 数据引擎：把"人力"换成"算力"

```
任务 prompt + 关键帧姿态
  → 运动分段（walk forward / turn around / sit on chair）
  → Kimodo 运动扩散模型逐段生成（每段出 N 个候选）
  → 前向运动学几何验证器打分（脚滑 / 穿地 / 腾空帧 / 关节限位）→ 留最优
  → Infinigen 程序化生成 1000 套住宅（客厅/办公室/卧室）
  → SE(2) 采样放置轨迹 + 目标资产，避碰（轨迹/资产/家具三方不碰）
  → Isaac / MuJoCo 回放渲染第一视角（OAK-1W 鱼眼）+ 视觉域随机化
  → 产出两套数据：给 generator 的「渲染 episode」、给 tracker 的「运动片段」
```

关键工程细节（值得抄）：
- **运动与渲染解耦**：每条 episode 由「随机种子 + 轻量放置记录」确定 → 可换分辨率/换相机内参/换物理引擎**重渲染**，不必重生成运动。
- **几何验证器即质量闸门**：扩散模型只做运动学，不保证物理可行 → 用**前向运动学规则**直接判废（脚滑/穿地/腾空），而不是留到物理 rollout 里再抓。
- 规模：语料 **300 小时 episode**，合成耗时 **48 小时 / 250 张 H100**；generator 训练 **64 张 B200**，tracker 训练 **4 张 H100**。

### 1.3 跟踪器三阶段训练（成熟范式，可直接搬到我们自己的执行器训练）

1. **特权专家（PreRL）**：每个技能训一个 PPO 专家，能看到完整仿真状态 + 地形高度图 + 未来 10 帧计划；输出 50Hz 关节目标。
   - 关键补充：**纯姿态模仿奖励不够**（姿势完美但箱子没推动 = 失败，位运动力学奖励检测不到）→ 物体类技能追加"手部接近度 + 物体位移"奖励项。
2. **多教师蒸馏（DAgger）**：特权专家 → 单一 student（只看 onboard：本体 + IMU + 计划 + 深度图）。混合师生 rollout；每个仿真实例只由对应专家监督，**避免多专家动作冲突被平均掉**。
3. **多 critic 微调（PostRL）**：蒸馏受限于教师上限 + 部分可观测有残差 → 直接对 student 上 RL。**多 critic PPO**：actor 共享，每个技能一个独立 critic（用 Phase-1 专家初始化），各自归一化 advantage，避免高回报尺度的技能主导梯度。

### 1.4 sim2real 的两处硬功夫

- **执行器物理建模**：从电机转子惯量**解析推导各关节 PD 增益**，保证全关节自然频率与阻尼比一致；动作按关节力矩上限缩放；随机化命令延迟模拟硬件；奖励里**直接惩罚膝关节的过大负机械功率**（防止策略依赖仿真里被静默裁剪、真机却给不出的力矩）。
- **深度流不用原生深度**：绕过 D435i 自带深度（噪点/空洞多），把**原始双目红外**喂给 TensorRT 立体匹配模型，在 Jetson 上跑出 30Hz 干净深度。

## 2. 消融数据（引用时直接用这些数字）

**训练环境数量**（Sit 任务，100 个留出仿真环境，各 10 次）：

| 场景数 | 成功率 | Δ |
|---|---|---|
| 1,000 | 84% | — |
| 100 | 81% | −3 |
| 10 | 64% | −20 |
| 1 | 43% | −41 |

→ **环境多样性比动作数量更值钱**：1 → 100 是 +38 分，100 → 1000 只 +3 分。性价比拐点在 ~100 套。

**其余消融**：

| 项 | 配置 | 成功率 | Δ |
|---|---|---|---|
| 连续性 | 训练时前缀条件化（本文方案） | 84% | — |
| | 推理时 RTC（real-time chunking） | 66% | −18 |
| | 不用连续性机制 | 24% | −60 |
| 生成器解码器 | flow matching | 84% | — |
| | 回归式解码器 | 19% | −65 |
| 跟踪器 | 带深度 | 84% | — |
| | 去掉深度（纯本体） | 74% | −10 |

→ **异步生成下的接缝连续性是最容易翻车的地方**：用推理时 guidance 去补（RTC）既不保证连续、又加延迟；正确做法是**训练时把已承诺执行的 P=15 帧（0.5s）当 clean token 喂进去**，只去噪剩下 135 帧，让连续性内化进网络。

**成功率总表**（单任务 6 任务 × 100 仿真环境 / 6 真实环境，各 10 次 = 6000 仿真 + 360 真机试验）：

| 任务 | 仿真 | 真实 |
|---|---|---|
| Go-To | 98% | 92% |
| Sit | 84% | 85% |
| Door（侧身过半开门） | 91% | 93% |
| Crouch | 95% | 100% |
| Crawl | 84% | 90% |
| Push | 93% | 88% |
| **单任务均值** | **91%** | **91%** |
| 多任务均值 | 69% | **70%** |

## 3. 硬件与部署形态（工程基线，可抄）

- 机器人：**Unitree G1，29 DoF**，两处改装 —— 头部支架装 **OAK-1W** 相机，后背包装 **Mac mini M4 Pro 64GB**。
- 感知与控制**跨两台机器、异步级联、ZeroMQ 打通**：
  - 外环：OAK-1W 120° RGB（1280×800 @30fps）→ Mac mini → 编排器 + 动作生成器 → 运动计划作为**设定值**；
  - 内环：Jetson Orin NX 上 C++ 实时进程（**PREEMPT_Rt 内核 + 无锁 triple buffer**，控制环永不阻塞）吃计划 + D435i 55° 下视深度（424×240 @30fps）→ 关节指令。
- **本地优先 + 可选增强**：编排器默认本地 4-bit 小模型跑在 `halo_serve`（与 generator 共服务引擎），**断网可用**；需要更强推理时**可切云端 frontier 模型 API**。
- 运行时：模拟闭环 `system/run_sim.py`（MuJoCo），真机闭环 `system/run_real.py`，带实时 web viewer。

## 5. 论文自曝的局限（**比 91% 更有价值的情报**）

1. **任务设计仍要人写**：新技能仍需人工写 prompt + 编排关键帧 → 技能库增长速度 = 一个人的编写速度。
2. **没有触觉**：视觉不提供接触感知，物体出画或被遮挡后策略不知其存在 → 接触密集任务性能下降。
3. **生成器 ↔ 跟踪器接口很窄**：跟踪器只跟随运动计划，**不知道这个计划是为了什么**（不共享意图/语义）。
4. **编排层相对简单**：技能一多就需要更"agentic"的编排。
5. **复合任务不独立**：Door→Go-To 链式成功率 71% < 单任务之积 89% → 根因是**上一个子任务的结束姿态**（base 位置与朝向）会让下一个目标**落在视野外**（真实 Crouch→Go-To→Push 失败的 5 次里有 3 次是"蹲完头转 away，箱子根本没进视野"）。作者建议补 **search / turn-in-place** 等基础恢复行为。

## 6. 对德勤 / NemoClaw Physical AI 的借鉴点

> 前提不变（2026-06-29 决策）：**Hermes Agent v0.14 是德勤 Agent 框架唯一选择**；开源项目只作技术借鉴，不做产品二选一。

| # | 借鉴点 | 落点 | 价值 |
|---|---|---|---|
| B1 | **"仿真即数据引擎"作为交付叙事** | NemoClaw Physical AI 提案 v2 的"为什么可行"章节 | 客户最怕的是"没有真机数据交付不了"；HALO 证明**不需要真机数据、不需要现场扫描**，语料随算力线性扩展 —— 这是对政务/金融客户最有说服力的一条 |
| B2 | **三层接口可作我们 Physical AI 执行器抽象层的接口参考** | 语义子任务 → 5s 全身运动计划（36 维/帧）→ 关节目标（50Hz） | 与 DSH 的 Capability Seam 三角色同构：**定义能力 / 提供能力 / 消费能力**；我们照此设计"每种 harness 可插拔"的物理执行器边界 |
| B3 | **跨设备分层部署形态** | 边缘主机（编排+生成）+ 本体算力（实时跟踪） | 正对 MEMORY 里"**整套系统可以单独部署**"的交付目标；也是给客户画部署拓扑图的标准范式 |
| B4 | **实时链路的工程纪律** | PREEMPT_Rt + 无锁 triple buffer + ZeroMQ 异步级联 | 我们做实时交付时的硬指标基线，避免"Python 一卡就抖" |
| B5 | **本地优先 + 可选云端增强** | 断网可运行 + 需要时切云模型 | 对政务/金融客户的**离线与降级**诉求直接可用；跟我们"本地小模型 + 可选强模型"的思路一致 |
| B6 | **评估口径模板** | 单任务 91% / 多任务 70% 分开报；仿真与真实分开报 | 客户会问"到底能不能用" —— **诚实分层报数**比只报 91% 更能建立信任（抄我们的方案评估章节格式） |
| B7 | **负面结论直接进排期估算** | "技能库扩展速度 = 人写任务的速度"；"复合链不独立，要补恢复行为" | 写 Physical AI 实施计划时，**排期不能按"机器人会干活"算，要按"人写任务 + 补恢复行为"算** |
| B8 | **许可红线** | 不 fork、不再分发；只借鉴方法与接口，实现自研 | Apple 专有许可，**不进客户交付物、不进开源组件清单** |

**可选深挖方向**（如果何大人要往 Physical AI 交付推进）：
- 抄 **训练时前缀条件化**（异步生成的接缝连续性）—— 这个模式在**任何**"生成式计划 + 实时执行"的场景都通用，不止机器人；
- 抄 **多 critic PPO + 特权专家→蒸馏→微调**三阶段 —— 这是我们自己的策略模型（若有）也能复用的训练配方；
- 抄 **环境数量 vs 成功率的边际曲线**（1/10/100/1000）—— 客户问"要不要多采点数据"时，用这条曲线回答"加场景比加动作便宜"。
