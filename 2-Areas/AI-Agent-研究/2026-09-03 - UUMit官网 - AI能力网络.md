## 🤖 标准化能力栈（Agent Card → A2A → MCP）

UUMit 把 Agent 协作拆成 4 步，和 Google 的 A2A 协议、Anthropic 的 MCP 协议一致：

1. **Agent Card** — 标准化能力描述（"我能干什么、收多少钱、有什么约束"）
2. **Discovery** — 智能能力发现（按需求匹配最合适的 Agent）
3. **A2A** — 自动建立协作（Agent 间握手、调用、结算）
4. **MCP** — 连接工具与数据（标准化工具调用协议）

> 适用于工作流（来自官网首页）：**WorkBuddy / LobsterAI / OpenClaw / Codex / Marvis**
> 👉 这是关键的横切点：UUMit 把 OpenClaw 当成「可对接的执行器」之一。

## 💡 我的判断（4 条）

### 1. UUMit 是「发现层 + 撮合层」，不是「执行层」
它解决的是**「我有什么需求，谁能干，找谁干，干完付款」**——是网络层。
OpenClaw / Codex / Claude Code 是「执行层」，解决「具体怎么干」。
两者**不冲突、可叠加**：执行器跑在 OpenClaw 上，但 OpenClaw 也可以通过 A2A 接入 UUMit 接单。

### 2. 与德勤 MVP 的对位（强相关，可立刻借鉴）
德勤 AI Native MVP 现在关心的是「组织 Workspace + Agent 智能体平台」，UUMit 直接给出了**「Agent 在工作流里如何被自动发现 + 撮合 + 结算」的端到端样板**。

**最值得抄的 3 个机制**：
1. **Agent Card** — 把德勤的 MVP 每个 Agent 都做成标准化描述（能力、定价、SLA、约束）→ 可被内部 / 客户方 Agent 自动发现
2. **小龙人式统一入口** — 用一个 AI 调度员接收所有"说一句话"的需求，匹配并分发（德勤 MVP 的"一句话办业务"按钮）
3. **UT 化结算 / 钱包** — 把每次 Agent 调用 / 每份交付都按统一代币结算（不一定是真代币，但"内部账户余额"必须有）

### 3. 与 OpenClaw 的横切（立即可做）
UUMit 把 **OpenClaw 列在适用工作流首页**——意味着 UUMit 团队对 OpenClaw 已经有一定了解（很可能是看到了 hermes-chat / AgentRouter / AgentSpace 1455 端口部署这件事）。
可探索路径（不需要立即动手，先看）：
- UUMit 提供 A2A discovery endpoint → OpenClaw AgentRouter 注册一个执行器 → OpenClaw 接 UUMit 任务
- 也可反向：UUMit Agent 通过 MCP 调用 OpenClaw 内部 Skills

### 4. 不是开源项目、不是 AGI、不是产品替代
UUMit 是个**商业平台**，商业模式是「撮合收佣金 + 数据接口抽成 + 算力调度差价」。
对何大人来说，**最大价值是「拿来对位、抄设计机制、做局部借鉴」**，不是「替代 Hermes 或 OpenClaw」。
不冲突决策：参考 MEMORY.md "开源研究边界（2026-06-29 何大人明确）"。
