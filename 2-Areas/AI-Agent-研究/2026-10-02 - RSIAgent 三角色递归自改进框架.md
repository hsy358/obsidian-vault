# RSIAgent — 三角色递归自改进框架

**仓库**: [github.com/AetherLabsAI/RSIAgent](https://github.com/AetherLabsAI/RSIAgent)
**Star**: 453 ⭐

## 定位

> **训练无关（training-free）的递归自改进框架** — 模型参数全程固定，通过 broad-then-deep 自主探索构建可复用记忆，实现对新数字环境的适应。

## 三角色架构

| Agent | 职责 |
|---|---|
| **Curriculum Agent** | 选择信息量最大的探索任务，基于已有知识决定是否继续练习 |
| **Actor Agent** | 通过可执行 Python/Bash 程序与环境交互，执行后从 Verified 反馈中提炼经验并更新记忆 |
| **Verifier Agent** | 独立检查任务需求和环境结果，Ground 学习过程；无法读取 Actor 的私有推理或记忆 |

## 两阶段探索 + 测试时复用

```
Phase 1: Broad Recursive Self-exploration (BRS)
→ Curriculum Agent 提出多样化项目
→ Actor Agents 并行执行，Verifier Agents 检查
→ 共享起始记忆，完成后 Actor 顺序整合经验

Phase 2: Deep Recursive Self-exploration (DRS)
→ 针对性尝试暴露弱点和脆弱成功
→ Curriculum Agent 选择聚焦练习
→ 每个验证过的经验在下一步之前更新记忆

Phase 3: Test-time memory reuse
→ 用冻结记忆指导任务执行
→ 与 Verifier Agent 交互，循环 action-verification
→ 官方密封评估在执行和验证后进行
```

## 失败分析（三个瓶颈）

论文发现三个改进边界：
1. **练习可能错过相关弱点**
2. **验证可能接受不完整的工作**
3. **记忆可能保留错误规则**

→ 探索质量、验证质量、记忆整合质量比练习量更重要。

## 对德勤项目的参考价值

- **三角色 Agent 协作** → 德勤 MVP 的 Executor Router 可借鉴：Curriculum（调度）+ Actor（执行）+ Verifier（验收）三权分立
- **记忆固化机制** → RSIAgent 的 Phase 1/2 探索记忆 → Phase 3 冻结复用，与德勤 Workspace 的上下文持久化高度相关
- **模型参数固定** → 不改模型权重，靠记忆和探索流程实现能力提升，德勤 Hermes 执行器设计可借鉴
- **失败分析** → 德勤交付质量管控可借鉴：验证层质量 > 练习量
