## 1. superdesigndev/loopany（124★）—— Skill 层

**slogan**：*"An agent skill for long-horizon work and self-improvement"*

**背景**：
- 出自 **crewlet.io**（"self-improving company" —— 一个 Agent 跑公司）
- loopany = 从 crewlet 蒸馏出的**可移植 substrate**（持久化记忆 + 自迭代层），可被任意 harness 复用

**核心机制**：
- **Long-cycle tasks**：跨 session 保留任务状态、产出、未结事项 —— 解决"Agent 完成任务就忘，下次从零开始"
- **Self-learning**：每个完成的任务写 outcome → reflect loop 蒸馏 beliefs → 提议 skill 改动 → 用户接受/拒绝 → diff 进 skill 文件并 commit
- **技术栈选择**：markdown + frontmatter = source of truth；append-only JSONL = reference graph；**没有数据库**（SQLite 索引是 derived artifact，可随时删）
- **可插拔**：README 明确写 *Any agent harness (Claude Code, Hermes, OpenClaw, Codex, custom) can attach this CLI and inherit a persistent, self-iterating brain*

**当前状态**（CHANGELOG）：
- v0.1.0：单用户 dogfood 可用；自迭代 loop 已 ship；bundled domain packs（CRM/ads/content/metrics）设计但未移植

**灵感来源**：
- **GBrain**（Garry Tan）：架构同源，loopany 答"我做了什么/效果/下一步"，GBrain 答"我知道什么"
- **Karpathy LLM Wiki**：markdown-as-agent-memory 的 mental model

## 2. superdesigndev/loopany-platform（288★）—— 平台层

**slogan**：*"Run your company in loops, Loop Anything"*

**架构**（极清晰，三段式）：
```
Server (loopany.ai / self-host)   ← HTTP poll
   schedules · stores · auth · notifies
   ZERO LLM · ZERO code-exec
                                   
Daemon (@crewlet/loopany)   ←→   Local coding agent
   on YOUR machine              (Claude Code / Hermes / Codex / ...)
   runs + reports
```

**Server 绝不跑 LLM、不执行用户代码** —— 这是关键设计原则：
- 控制面（调度/存储/认证/通知）和执行面（agent 实际跑任务）严格分离
- Credentials / files / tools **永远在你机器上**，只 sync 你选择回传的 artifact

**6 个核心 feature**：
1. **Scheduled agent loops** —— cron 或 one-shot；可一直 open（监控）或 closed（达到目标自结束）
2. **BYOA execution** —— 跑你机器上的 agent，server 零 LLM/零 exec
3. **Self-improving loops** —— evolve pass 回顾 run history，**自动 sharpen brief、distill state、refine generative dashboard**
4. **Deterministic pre-stage** —— agent 之前先跑便宜的 mechanical 工作，失败才 fallback 到 agent 带上下文
5. **Teams + notifications** —— 多用户 dashboard + 团队频道（Telegram / 飞书 / 失败告警）
6. **Template market** —— code health / shipping / growth / ops / personal routines 模板市场

**Self-host**：
- pnpm 装 → `pnpm dev` → http://127.0.0.1:3000（embedded pglite Postgres，零外部 DB）

**安全提示**（README 醒目位置）：
> *"Loopany is still an early-stage project. The daemon runs with fairly high permissions on your machine — it executes your coding agent with your credentials — and we are continuously hardening security."*

## 3. ssochi/LoopAny —— 独立项目（同名不同家）

**定位**：AI Code Agents 自动产品迭代框架 —— Agent 自主完成**设计 → 开发 → 测试 → 体验优化**全流程。

**核心哲学**：
- **AI-friendly 接口必须是 CLI/API**（不是 GUI）
- **CLI 不代表简陋** —— 可以承载极复杂业务逻辑
- **前后端解耦**：CLI 验证核心逻辑后，UI shell 是后期的事

**示例**：以"Slay the Spire 2"为例，loopAny 可独立完成所有卡牌逻辑、数值平衡、战斗结算，最终产出**可玩的 CLI 版本**；之后再包一层 UI。

**与 superdesigndev/loopany 的关系**：**无关**，纯同名巧合。ssochi 这个更像"auto-coding agent"，superdesigndev 是"agent 长期记忆 + 编排"。

## 🔍 跟德勤项目的对应关系（不主动挂钩，列给你判断）

> 按 MEMORY.md 偏好不强挂钩，但 loopany 明确把 OpenClaw/Hermes/Codex 列为可插拔 harness，跟**德勤 M6 执行器抽象层**目标高度同源，列出来供你判断是否要纳入借鉴清单。

| 德勤目标 | loopany 对应实现 | 借鉴价值 |
|---|---|---|
| **执行器抽象层**（M6 任务） | loopany CLI 通过"skill + markdown substrate"附加到任意 harness | ✅ 设计哲学完全同源（**vendor-neutral BYOA**） |
| Hermes / OpenClaw / Codex / Claude Code 都接 | loopany README 明列 4 个 harness 都可 attach | ✅ 验证可行性，不是纸面设计 |
| 控制面/执行面分离（**server zero-LLM zero-exec**） | superdesigndev 整套架构就是这个 | ✅ 安全模型参考，credentials 不离机 |
| 任务状态跨 session 持久化 | loopany markdown + JSONL substrate | ✅ 不依赖重型 DB，**轻量可移植** |
| **Self-improving loop**（自动演化） | evolve pass review run history → sharpen brief | ⚠️ 是德勤 MVP 可选 v2 能力 |

**潜在风险**（也写在这里供后续判断）：
- daemon 高权限跑 coding agent —— 这条**写进 AgentSpace 安全 SOP**
- v0.1.0 早期版本，bundled domain packs 还没移植
