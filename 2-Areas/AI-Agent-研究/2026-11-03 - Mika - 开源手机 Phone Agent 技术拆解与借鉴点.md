# Mika：开源手机 Phone Agent 拆解

> ⚠️ **地址纠错**：何大人转来的 `github.com/mika-proj/mika` **是 404**（不存在）。
> 真实地址：**https://github.com/wangzan101/Mika**（作者 王赞，Apache-2.0，Android 11+，2026-10-30 开源）
> 二手文章常把 repo 名编错，以官方 README 为准。

## 一、定位

> "An AI assistant on your phone: say what you need, and it works your apps and the web until it's done."
> **在隐藏的后台屏上干活，你可以继续用手机。** 复用你现有的登录态，**无 Root、无需电脑**。

对比豆包手机助手：**豆包靠手机厂商给系统级权限，Mika 不依赖厂商**。

## 二、技术内核（比二手转述有价值得多）

### 1. 后台虚拟屏（不抢主屏焦点）
- 通过**安卓无线调试**启动一个**具备 Shell 权限的辅助进程**，在手机上创建**一块看不见的虚拟屏**，让微信等 App 在上面运行
- Android 12 起可操作其他 App；**Android 14+** 后台虚拟屏才能真正独立工作、不抢占主屏输入焦点
- 辅助屏可以点开看实时画面（live view）

### 2. 感知双通道（关键设计）
| 通道 | 手段 | 特点 |
|---|---|---|
| 快通道 | **无障碍服务读控件树**（按钮/文字/输入框） | 快、准、省 token |
| 兜底通道 | **本地 OCR 或视觉模型看图操作** | 控件识别不了时接管 |

> 这就是 **GUI Agent 的通用范式：结构化感知优先，视觉兜底**。
> 和他 600 页工程里"结构化 spec 优先、截图 diff 兜底"是同一套思路。

### 3. 动作与能力
- 动作：点击 / 滑动 / 输入 / 启动 App / 分享文本
- **内置"桌面级浏览器"**：保持登录态、读页面、下载上传、**自动放慢节奏模拟真人**降低风控；**遇验证码/阻塞页交给你**
- **每个对话一个 Linux 沙箱**（arm64）：跑 Python / Node / shell
- **定时与条件任务**："每天早 8 点看天气，下雨才告诉我"
- **知识文件（knowledge files）**：内置 App/网站使用知识 + how-to skills（改设置、PDF 处理、查清一件事、消息邮件、写技能）

### 4. 人在环的设计（★ 值得抄）
| 机制 | 说明 |
|---|---|
| **默认 Ask 模式** | **只在花钱（下单/支付）前问你**，其他直接做；可切 Autonomous 模式 |
| **登录/验证码/支付 → 交人** | 不自己碰资金与身份 |
| **随时插话 / 停止** | 任务运行中可补充或纠正；**停止后报告"做到哪了"**，说"继续"从断点接着来 |
| **悬浮胶囊** | 任意界面唤起；**双击 = 把当前屏幕发给它**（"这个怎么回"） |
| **长按说话** | 手机原生语音识别 |

### 5. 从电脑派任务（★ 对何大人最有用）
> "AI tools on your computer can hand Mika tasks through **CLI + Skill or MCP**"
> - 一条 `adb forward` + 令牌即可，不经数据线直连
> - 电脑里的 Claude / Codex / Cursor 通过 MCP 给 Mika 派任务、查进度、拿结果
> - 连安装都可以让电脑上的 Agent 照 `install-with-agent` 文档自动完成

### 6. 自学习
> "Remembers the preferences you tell it, and **turns tasks it finishes into skills** so next time is faster and steadier."
> → **完成的任务沉淀为 skill** = Loop Engineering 的"知识沉淀循环"的现成实现。

## 三、对何大人当前项目的借鉴点

### P0 · Forge 编排层（直接可用）

| 借鉴 | 落法 |
|---|---|
| **Executor 契约应含三件事：派任务 / 查进度 / 拿结果** | 何大人现在的 Forge 只定义了"输入 spec + 基线图，输出分支 + PR"。**Mika 的 MCP 契约补上了"查进度"** —— 这正好是 Watchdog 停滞检测需要的接口（Worker 主动报心跳，比外部轮询更省） |
| **默认 Ask 模式** | 人工介入点从 6 个收敛为：**默认不问，只有"不可逆/花钱/越权"才问**。他的 H1~H6 里，H4/H5/H6 可降级为"进面板等人有空看"，**只有设计冲突裁定是必须当场问的** |
| **"停止后报告做到哪了，继续接着来"** | Assignment 断点续跑的标准语义（可抄进 `forge/domain/assignment`） |
| **完成任务→沉淀成 skill / knowledge file** | **Forge 的错误库与成功模式，应直接落成 `forge/knowledge/*.md` 可版本化文件**，让下一个分片的 Agent 直接读 —— 这比"每次重新踩坑"快得多 |

### P1 · 产品形态（做看板/交付物时直接用）

| 借鉴 | 说明 |
|---|---|
| **"你在前台用手机，Agent 在后台屏干活，干完通知你"** | 这就是"不用人一直盯着"的**物理形态**。他的 600 页工程同理：**Agent 在 worktree 跑，人在看板看** —— 看板应像 Mika 的悬浮胶囊：**随时能插话纠正**（不只是只读） |
| **双击把当前屏幕发给它** | 看板的"截图直接问"模式：人看到差异图，一键丢给 Agent 修 |

### P2 · GUI Agent 范式（客户场景）

- 政务/金融客户常有"App 端数据核对 / 后台巡检 / 政务 App 自动填报"需求
- **可借的范式**：结构化感知优先（无障碍控件树 / API）+ 视觉兜底 + 人掌钱与验证码 + 每次操作留审计
- **Mika 可作为德勤"Agent 能力边界"案例**：一个"能力很强但权限面极大"的真实样本，用来讲清"为什么企业交付必须收窄权限"

### P3 · 真机视觉回归（可选的远期增强）
- 若交付含移动端 H5/App：Playwright 模拟 ≠ 真机。**用真机 + MCP 派任务做视觉验收**是可行路径
- 代价：设备管理、真机一致性差 → 建议只在"关键 5% 页面"上用真机抽验，别全量

## 四、安全与合规（★ 必须先看，涉客户时是红线）

### 技术面（第三方实测发现）
| 问题 | 后果 | 对策 |
|---|---|---|
| **明文 HTTP 全局允许** | 非 TLS 服务商下，**API Key 与对话内容在局域网可见** | 测试机可玩，主力机别在 Mika 干活期间登录支付/IM |
| **`base_url` 任意填写，模型列表还能下发 `base_url` 覆盖调用目标** | 等于把屏幕内容与截图交给那台主机 | 只连可信服务端 |
| **沙箱开联网 = 数据外带通路**（默认断网 + seccomp 封得很死） | 主动放开即成外带通道 | 保持默认断网 |
| 首次需开**开发者选项 + 无线调试 + 无障碍** | 权限面极大 | 用备用机 |
| HyperOS 上"无障碍未运行"是**假警报**（状态判定滞后） | 误判/误修 | 真关一次再真开一次（系统设置界面操作才有效，adb 循环无效） |

### 合规面（时代周报等报道）
- **无障碍权限已成灰产目标**：自动抢单、验证码盗取（短信到达数百毫秒内完成登录/转账）、免密支付盗刷
- 现实案例：凌晨 2:50–5:51 被盗刷 162 笔共 80868 元
- **广东标准**：明确**禁止**智能体利用无障碍权限操作第三方 App
- **中国软件行业协会**新标准：从"双重同意"转向强调"**用户可控**"
- 学界主张：AI 代理已是"独立行为主体"，需新的治理规则

> 🚨 **对德勤 / 金融政务客户的红线**：
> **无障碍全局操控 + 复用登录态 + 明文 HTTP 这三件套，绝对不能进客户生产环境。**
> 若客户要 GUI Agent，交付形态应是：**受控 UI 自动化 + 人工确认不可逆动作 + 全量审计日志 + 权限最小化（按任务临时授权，而非常驻全控）**。
> Mika 更适合作为**能力演示与范式参考**，而不是可直接部署的交付件。

## 五、要不要试？

- ✅ **可以试**：备用机 / Android 14+ / 有开发者选项；先只用"聊天 + 内置浏览器 + 沙箱"，**不配手机操控**（这样不碰无障碍与登录态，风险最低）
- ❌ **不建议**：主力机 + 日常支付账号；以及任何客户生产环境
- 📌 若只为借鉴：**README + `docs/computer.en.md`（MCP/CLI 派任务）+ `docs/features.en.md` + `docs/modes.en.md`（Ask/Autonomous）** 这四份就够

## 六、一句话

> Mika 的真正贡献不是"能操控手机"，而是把 **Phone Agent 的完整范式**摆了出来：
> **后台隔离屏（不抢焦点）+ 结构化感知优先/视觉兜底 + 默认 Ask 模式 + 任务沉淀成 Skill + 通过 MCP 被编排**。
> 其中 **MCP 派任务契约** 与 **Ask 模式** 两条，正好补上何大人 Forge 编排层缺的两块。
