# Jev ② Cron 优先级接入完成

> 实操日期：2026-09-22 15:50
> 接续：上一轮 ① Prom 间 Jev 过滤（9/9 通过）
> 决策来源：今日 MiniMax Token Plan 见底导致 5 个股票 cron 反复重试

## 一、核心问题

5 个股票 cron（持仓 K 线、盘前/早间/午盘/截图）已在 09-21 删除以止损 token 消耗。  
MEMORY.md 标记的**重新创建 SOP** 要求「升级套餐 + 拿到完整配置后再弄」。

**根治问题** = 在 cron 重启前，部署一个**优先级 wrapper**，下次 token 见底时自动跳过低优 cron，**而不是反复重试**。

## 二、解决方案

#### 设计

每个 cron 跑前先过 Jev Noul（yes/no）：
- `noul >= 0.5` → 跑
- `noul < 0.5` → skip（exit 0 但不执行下游）
- **fail-open**：Jev 本身出错 → 默认跑（不误杀 cron）

#### 状态信号

* `api_error_recent` — vault-sync.log 有无 2056 / Token Plan 标记
* `urgency` — 调用方声明（high / medium / low）
* `user_recent_active_min` — MEMORY.md mtime 估算
* `business_hour` — 当前是否 9-15 点

#### Jev 指令设计要点**（这次调试关键发现）

* ❌ **失败模式**：复杂 state JSON + 多规则 instruction → Jev 给 1.000（保守"全部跑"）
* ✅ **成功模式**：**聚焦 state**（只说"现在发生了什么"）+ 简洁指令（只问"是否跑"）
* 状态字段命名 .noul，**不是 .answer**（NoulAnswer 的字段名是 .noul）

## 三、落地文件

位置：`/root/.openclaw/workspace/skills/jev-filter/`

* `jev_cron_decide.py` — wrapper 主体
  - `collect_signals()` — 收 4 个运行时信号
  - `decide_with_jev()` — 调 Jev Noul，返回 0-1
  - `log_decision()` — 写 `/var/log/jev-cron/<cron_name>.log`（audit 用）
  - CLI: `python3 jev_cron_decide.py <cron_name> --urgency <h/m/l> --command '<real cmd>'`
* `cron_decide_demo.py` — 4 场景验证

## 四、测试结果

```
场景                                                期望    Jev 评分  实际
[1] stock_kline_daily (high urgency, 健康时段)         run     0.820    run    ✅
[2] stock_intraday_early (medium urgency, 业务时段)    run     0.700    run    ✅
[3] stock_intraday_lunch (medium urgency, API 见底)    skip    0.160    skip   ✅ ← 问题重现被解决
[4] low_priority_summary (low urgency, 凌晨)           skip    0.160    skip   ✅

准确率：4/4 = 100%
```

#### 关键发现

| 现象 | 含义 |
|---|---|
| **场景 3 评分 0.16** | API 见底时 Jev 强烈倾向 skip，今日踩的坑能被直接拦截 |
| **场景 4 评分 0.16** | 低优 + 深夜 + 用户睡，Jev 一致判 skip |
| **场景 1/2 评分 0.7-0.8** | 正常情况 Jev 倾向 run，**不会误杀** |
| **平均延迟** | 单次 312ms 左右（同一 SDK 同一延迟特性） |

## 五、用法（未来重建 stock cron 时）

```bash
# 原 crontab：
0 9 * * 1-5 python3 /root/.../stock_kline.py

# 用 wrapper 后：
0 9 * * 1-5 /usr/bin/python3 /root/.openclaw/workspace/skills/jev-filter/jev_cron_decide.py stock_kline_daily --urgency high --command 'python3 /root/.../stock_kline.py'
```

或者更轻的写法（不要审计 log 时）：
```bash
0 9 * * 1-5 bash -c '/root/.openclaw/workspace/skills/jev-filter/jev_cron_decide.py stock_kline_daily --urgency high && python3 /root/.../stock_kline.py'
```
