# AI提效20%，为什么让我累了100%？当 Agent 可以无限并行，人类的注意力、睡眠和恢复能力却成了真正的瓶颈
最近我看了一场演讲，题目叫 《Your Attention Is the Bottleneck, Not Your Agents》， 主讲人是 WorkOS 应用 AI 团队的 Zack Proser。

演讲里有一句话让我印象特别深：今天的 Agent 已经可以持续运行、并行处理任务，甚至自主读取工单、修改代码、运行测试、验证结果。 但人的神经系统没有因为模型升级而升级。Agent 可以无限扩张，人类的注意力却是硬约束。

这与我最近的状态高度一致。

自从大量使用 Claude Code、Cursor 以及各种 Agent 工具后，我好像突然拥有了十几个数字员工。 调研 Agent 在搜索资料，写作 Agent 在整理文章，开发 Agent 在改代码，另一个 Agent 又在生成方案。 每个窗口看起来都在推进，产出也确实比过去多了。

但奇怪的是，我并没有获得十倍生产力。对于排版、摘要、格式转换、初步研究和高度重复的任务，AI 的提效非常明显； 可一旦进入产品判断、架构设计、战略分析、复杂写作这类高脑力工作，真正的净提效可能只有一小部分。 “20%”是我的体感，并不是一个适用于所有工作的统一研究结论。

更明显的变化是：**我比以前更累了。**

我开始强迫自己晚上十点前睡觉，主动中断和 AI 的连接。因为只要继续坐在电脑前，我就总觉得还有一个结果没看、 一个 Agent 可以再启动、一个问题还能再深入一点。工具不会累，也不会主动提醒你下班。

01

## 现状：AI 为什么一边提效，一边让人更累？

### 1. 我们常常只计算了“生成速度”

AI 确实可以提效，但不同研究给出的结果差异非常大。

一项针对 453 名专业人士的受控写作实验发现，使用 ChatGPT 后，完成时间减少约 40%，输出质量提高约 18%。 这很可能就是很多人记忆中“18%”的来源——但这里的 18% 指的是质量评分提升，并不是所有知识工作的平均提效。

另一项研究观察了 5,179 名客服人员，生成式 AI 让人均问题处理效率提高约 14%； 新手和低技能员工的增益达到约 34%，但对经验丰富、表现最好的员工影响很小。

更值得注意的是，METR 对熟悉自身代码库的资深开源开发者进行随机对照实验时发现： 使用当时的 AI 编程工具后，开发者完成任务反而多花了 19% 的时间。 有趣的是，他们主观上仍然觉得自己快了约 20%。

AI 带来的“产出很多、推进很快”的感觉，不等于端到端交付成本真的下降。

### 2. 高脑力工作的瓶颈从执行转向了判断

过去完成一项工作，我主要经历：理解问题、思考、制作结果。

现在则变成：拆任务、准备上下文、选择模型、启动 Agent、观察过程、回答追问、比较版本、核验事实、 修正偏差、做最终判断。

AI 减少了一部分亲手制作的劳动，却增加了大量监督性劳动。 尤其在高脑力任务中，真正稀缺的不是“再生成一版”，而是判断哪一版值得相信、哪里存在盲点、最终应当承担什么责任。

AI 净效能公式

AI 净效能 ＝ 自动化收益 − 编排成本 − 验证成本 − 切换成本 − 返工成本

重复、标准、容易验证的任务，自动化收益远大于后面的成本；复杂、模糊、依赖隐性知识的任务， 编排、验证和返工成本可能吞掉大部分收益。

### 3. Agent 的产出速度，可能超过人的验收速度

我们可以同时启动十几个 Agent，但无法同时认真判断十几个复杂结果。

每当一个 Agent 完成任务、另一个 Agent 提出澄清问题、第三个 Agent 发来测试失败通知， 人的注意力都会被从当前任务中抽离。大量工作看起来在并行，真正的人类思考却被切成了碎片。

工作中断研究发现，在中断更多的工作日，知识工作者对自身表现的满意度更低，情绪耗竭更高； 随机对照研究也显示，多任务和并行任务会提高主观压力，并激活部分交感神经系统反应。

### 4. AI 还会制造“诱发需求”

过去写一篇文章很费时间，所以我会谨慎选择题目。现在生成一个框架只需要几分钟，于是我会同时打开更多选题， 再生成更多版本，再做更多比较。

AI 降低了启动任务的门槛，却没有降低最终判断的成本。节省出来的时间没有自动变成休息， 而是被更多新任务重新填满。

你并不是拥有了十几个成熟员工，而是突然成为了十几个能力不稳定、随时需要指导的数字实习生的直属经理。

## 自我评估：你现在处于哪一种注意力风险状态？

为了避免只凭“我很累”的模糊感受判断，我尝试建立一个简单模型：

注意力风险指数

R ＝ T × A × H

T：工作负荷　A：Agent 编排负荷　H：人体脆弱度

之所以使用乘法，是因为三者会相互放大：复杂任务本身未必危险，多个 Agent 本身也未必危险； 但当复杂任务、频繁打断和睡眠不足同时出现时，风险会迅速上升。

说明：这是一个用于管理工作方式的启发式模型，不是经过临床验证的医学诊断量表。

### T：工作负荷，评估任务本身

每项按照 1—5 分判断：

- 重复程度：高度重复为 1，几乎每次都不同为 5；
- 问题清晰度：目标和输出明确为 1，目标本身模糊为 5；
- 复杂程度：单步骤为 1，跨系统、跨角色、多约束为 5；
- 隐性知识：很少依赖背景为 1，高度依赖经验与组织语境为 5；
- 验证难度：对错容易判断为 1，没有统一答案为 5。

### A：Agent 编排负荷，评估你如何使用 AI

- 同时运行数量：只运行 1—2 个为 1，多窗口、多 Agent 并行为 5；
- 打断频率：集中查看为 1，随时被结果和追问打断为 5；
- 上下文成本：一次说明即可为 1，需要反复解释为 5；
- 输出稳定性：质量可预测为 1，每次差异巨大为 5；
- 自动验证能力：系统可自检为 1，几乎全部依靠人工为 5。

### H：人体脆弱度，评估身体与恢复状态

- 睡眠质量：充足、规律、连续为 1，长期不足或破碎为 5；
- 精神压力：轻松稳定为 1，持续紧张、无法停机为 5；
- 身体信号：没有明显不适为 1，频繁出现不适为 5；
- 恢复能力：休息后容易恢复为 1，休息后仍然疲惫为 5；
- 生活节律：工作边界稳定为 1，吃饭、运动和睡觉都被工作侵占为 5。

1—24 分：绿色区

25—59 分：黄色区

应立即降低高脑力任务并发，恢复睡眠和生活边界。身体持续不适时应及时就医。

### 一个更简单的快速自检

下面十句话中，有多少符合你最近的状态？

- 我每天同时运行多个高脑力 Agent；
- 一个结果没看完，另一个结果又来了；
- 我总觉得还有任务可以再启动；
- 我花了大量时间比较 AI 版本，而不是做最终决策；
- 我经常重复解释相同背景；
- 我在散步、吃饭、睡前仍然检查 Agent；
- 我睡够了时间，但睡眠不连续或醒来仍然很累；
- 我比以前产出更多，却没有更强的完成感；
- AI 节省的时间，总会被新的工作填满；
- 即使没有紧急任务，我也很难主动停止工作。
如果其中多数已经成为常态，你的问题可能不是“还不够熟练”，而是工作系统已经让人的验收能力长期超载。

## 解决方案：用“滤、限、验、学、断”重建 AI 工作流

Zack Proser 在演讲中提出了信号层、语音优先、远程控制、多级验证、历史对话复盘和健康设备接入等方法。 这些建议非常有价值，但我认为还需要重新组织，并加入一个视频里没有充分强调的原则：**限制并发。**

### 第一步：滤——让 AI 过滤信息，而不是制造更多信息

不要自己不断翻 Slack、邮件、群聊、Linear、GitHub 和 Agent 日志。 让 AI 先完成去重、分类、优先级判断和摘要，只把真正需要人类决定的事项交给你。

信号层的目标不是让你更快地阅读全部信息，而是让更少的信息进入你的大脑。

### 第二步：限——限制人类判断任务的并发量

Agent 可以无限并行，但人类的判断任务必须限流。

我建议设置三种上限：

- **Agent 并发上限：**同一时间只运行少量高脑力任务；
- **人工验收上限：**同时等待你判断的结果，不超过两三个；
- **在制品上限：**旧任务没有验收完成前，不轻易启动新任务。
真正应该监控的不是“我今天启动了多少 Agent”，而是“现在有多少任务正在等待我的判断”。 这个队列一旦持续增长，就说明 Agent 产能已经超过了人的验收能力。

### 第三步：验——把验证交给系统，把例外交给人

视频里的多级验证门禁，是最值得复制的做法之一。

- **代码层：**自动运行 Lint、Build、单元测试；
- **功能层：**让 Agent 操作浏览器，走完整流程；
- **审查层：**使用独立审查 Agent 或明确规则进行对撞；
- **人工层：**人只处理高风险、无法自动判定的例外。
AI 工作流成熟的标志，不是人检查得更快，而是大量低价值检查不再进入人的注意力。

### 第四步：学——让重复解释逐渐消失

Claude Code 等工具会保留历史对话。可以定期让 Agent 分析：

- 哪些背景被反复解释；
- 哪些错误总在重复；
- 哪些任务消耗了大量思考和沟通；
- 哪些检查仍然需要手工完成。
然后把这些内容沉淀成项目规范、模板、Skill、MCP 工具和自动校验。 好的 AI 工作系统，应该让重复沟通逐渐减少，而不是让人永远充当 Agent 的保姆。

### 第五步：断——主动切断和 AI 的持续连接

这是我认为最重要的一步。

过去我们会因为“干不动了”自然停止。现在 Agent 可以继续运行，人失去了自然的停止信号。 所以休息必须被主动设计，而不能等待工作自己结束。

- 设置停止启动新任务的固定时间；
- 睡前 1—2 小时不再审查 Agent 输出；
- 关闭非紧急通知，不在床上处理任务；
- 散步、吃饭、洗澡时，不把自己变成远程值班员；
- 每天保留一段彻底不使用 AI 的时间。

## 我的个人选择：把健康放在效率之前

我现在越来越相信，AI 时代最重要的能力之一，不是如何让更多 Agent 二十四小时工作， 而是如何强迫自己停下来。

我给自己设置了几条生活边界：

- **固定早睡：**晚上尽量在十点前睡觉，不为等待 Agent 结果继续熬夜；
- **优先完整睡眠：**关注规律、连续和醒来后的恢复感，而不只计算总时长；
- **坚持运动：**通过走路、拉伸和力量训练，把注意力从屏幕拉回身体；
- **设置离线场景：**吃饭、散步和睡前不再处理 AI 任务；
- **重视身体信号：**持续疲劳、心慌、胸闷或其他明显不适时，优先休息和就医。
医学上，目前没有足够直接的证据证明 AI 工具本身会造成所谓“神经损伤”或直接导致心脏疾病。 更严谨的链路是：高并发 Agent 工作方式增加认知负荷与持续唤醒，职业压力与工作中断进一步影响睡眠； 长期睡眠不足、睡眠不规律和恢复不足，则与多种心血管和代谢风险相关。

美国心脏协会强调，健康睡眠不仅是睡够几个小时，还包括持续性、规律性、时间安排、白天清醒程度和主观满意度。 对多数成年人而言，每晚通常需要 7—9 小时睡眠。

我不能证明自己的每一次不适都由 AI 导致，但它至少迫使我重新审视： 我是否正在用睡眠、节奏和恢复能力，为一种并不确定的效率提升买单？

## 写在最后

AI 的问题不是没有提效，而是它把生产瓶颈从执行能力转移到了人类注意力。

当组织和个人仍然用“无限并发”的方式使用 Agent 时，节省下来的时间会被更多监督、判断和验收任务重新填满。 工具越快，人反而越容易忘记自己的上限。

所以真正成熟的 AI 工作方式，不是让 Agent 二十四小时不停工作， 而是让人类仍然保有停止工作的能力。

保护自己的注意力、睡眠和恢复能力，不是拒绝效率，而是让效率可以持续。

## 📝 小助分析（2026-07-24）

### 核心论点（一句话）

AI 把生产瓶颈从「执行能力」转移到了「人类注意力」。Agent 产能可以无限扩张，但人的验收/判断/睡眠/恢复是**硬约束**。当你用「无限并行」模式使用 AI 时，生成端提效被验收端超载抵销，**净提效可能反而是负的**。

### 三个最值钱的洞察

1. **可量化的注意力风险模型 `R = T × A × H`**（任务负荷 × Agent 编排负荷 × 人体脆弱度，乘法关系 = 相互放大）
   - 不是模糊的"我很累"，是 1–5 打分能直接出颜色区（绿/黄/红）
   - 配套 10 题快速自检 + 三轴量化打分表
   - **这一个模型就是文章的 ROI 主体**

2. **"3 个上限"是硬约束，不是软建议**
   - Agent 并发上限：高脑力任务少量
   - 人工验收上限：同时等待你判断的结果 ≤ 2–3 个
   - 在制品上限：旧任务不验收完，不启动新任务
   - 监控指标应该从"今天启动了几个 Agent"换成"现在有几个任务在等我的判断"——这是从 **throughput 思维** 切换到 **queue 思维**

3. **"滤 / 限 / 验 / 学 / 断"五步 SOP**
   - 滤（让 AI 先过滤，不要自己翻 Slack/GitHub/Linear）
   - 限（限并发）
   - 验（验证系统化：Lint/Build/单测/独立审查 Agent/人工只管例外）—— 这是 ROI 最高的杠杆
   - 学（重复解释 → 沉淀为 Skill/MCP/项目规范）
   - 断（主动断连：睡前 1–2 小时、吃饭散步洗澡不值班）
