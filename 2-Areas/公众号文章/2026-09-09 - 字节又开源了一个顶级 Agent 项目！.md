# 字节又开源了一个顶级 Agent 项目！
![](https://mmbiz.qpic.cn/sz_mmbiz_png/ULE52ybiacSs64E33dUUvqib1O2DxN2BT1RGx3py7cDibCvDgKwJ4RNwiaWeoT2zPSYBUMsibhnYeHhnGNksPsalKKibgiaxicOIkhOa8RcDuhMu41E/640?wx_fmt=png&from=appmsg)

> 字节又开源了 OpenViking 这个狠角色，GitHub 上 35K+ star，就是冲着 Agent 记不住事这个老毛病来的。它把记忆、资源、技能全都摆进一个虚拟文件系统里，跨会话也能召回之前的偏好和经验，还能把这套记忆接给 Claude Code、Codex 这类主流 Agent。这篇文章带你在自己服务器上跑起来，亲眼看看记忆怎么落盘、怎么被召回。

## 简介

OpenViking 是面向 AI Agent 的开源上下文数据库。记忆、资源、技能统一存放在 `viking://` 协议下的虚拟文件系统里，和查黑盒向量库不同，Agent 用 `ls`、`tree`、`find` 这类熟悉的操作浏览自己的上下文。内容写入时会被处理成 L0 摘要、L1 概览、L2 详情三层，按需加载省 token；每次检索都留下目录浏览轨迹，结果不对能回溯到具体路径。

围绕这套文件系统，OpenViking 还有几个关键特性：

- **目录递归检索**：先定位得分最高的目录，再逐层下探，结果连同周边上下文一起返回；
- **会话沉淀记忆**：会话结束后异步把用户偏好和 Agent 经验写成长期记忆，下次对话自动召回，跨会话不失忆；
- **多 Agent 共用**：同一份记忆通过插件、MCP、SDK 接给 Claude Code、Codex、Cursor 等外部 Agent，跨项目共用。

## 安装及配置

> 下面以一台 Linux 服务器（192.168.3.101）为例，从写配置文件、拉起 Docker 容器，到打开 Web Studio 完成连接和用户配置，把 OpenViking Server 完整跑起来。

- 创建配置文件ov.conf，并复制到指定目录，这里复制到`/mydata/openviking`目录下；

```
{  "server": {    "host": "0.0.0.0",    "port": 1933,    "root_api_key": "abc123456efg",    "public_base_url": "http://192.168.3.101:1933"  },  "storage": {    "workspace": "./data",    "agfs": { "backend": "local" },    "vectordb": { "backend": "local" }  },  "embedding": {    "dense": {      "api_base": "https://dashscope.aliyuncs.com/compatible-mode/v1",      "api_key": "<你的阿里云百炼 API Key>",      "provider": "openai",      "dimension": 1024,      "model": "text-embedding-v4"    }  },  "vlm": {    "api_base": "https://dashscope.aliyuncs.com/compatible-mode/v1",    "api_key": "<你的阿里云百炼 API Key>",    "provider": "openai",    "model": "qwen3-vl-plus"  }}
```

- 配置一共四块，这里 embedding 和 vlm 都走阿里云百炼的 OpenAI 兼容接口，一个 API Key 够用：
- `server`：定义服务监听地址、端口和管理密钥，其中 `public_base_url` 让服务端在上传文件时能回一个客户端可达的地址；
- `storage`：指定记忆和向量数据落在容器内的位置；
- `embedding`：向量模型，负责把文本转成可检索的向量；
- `vlm`：多模态大模型，负责生成摘要、理解内容，也是后面 VikingBot 的思考模型。
- 使用如下命令下载镜像；

```
docker pull ghcr.io/volcengine/openviking:latest
```

- 下载完成后使用如下命令运行镜像；

```
docker run --name openviking \  -p 1933:1933 \  -v /mydata/openviking:/app/.openviking \  -d ghcr.io/volcengine/openviking:latest
```

- 之后通过浏览器验证服务状态；

```
curl http://192.168.3.101:1933/health
```

- 返回 `status: ok`、`healthy: true`，并带出服务版本和 `auth_mode`，说明服务已经正常起来了；

- 打开Web Studio前端，Studio 是 OpenViking 自带的 Web 控制台。首页是仪表盘，展示上下文数据量、Token 用量、检索次数这些统计；左侧导航分成工作区、活动、设置、资源四个区，工作台、检索、技能、会话、用户管理、Agent 接入等入口都在这里。地址：http://192.168.3.101:1933/studio

![](https://mmbiz.qpic.cn/sz_mmbiz_png/ULE52ybiacSvFaeNUgJysiaIuxh5y1BDwCTHxhQAmMmoAvaKRPJUmMZY7Tp35QFOhKZOIF2jdKibNDWSVziaG9ibJhpZ1y0yB48s7JrPKjFvu7icE/640?wx_fmt=png&from=appmsg)
- 进入「连接设置」，在“Root 或管理员 API 密钥”一栏填入 ov.conf 里的 `root_api_key`。填对之后下方“控制台权限”会显示正常，说明管理面已经通了。此时页面还会提示“还缺少用户 API 密钥”。管理密钥只管管理操作，工作台和数据接口需要绑定用户身份的用户密钥，这就引出下一步；

![](https://mmbiz.qpic.cn/sz_mmbiz_png/ULE52ybiacSs2jOxsvPaMoEeQK0yYHiaiatdicaVTzSb3UhF2Urmaqo24kbVapTW6x3icqjZNGWxuEs5wibDHicQKXqvDxfn95nerERtxs4qFmMbwY/640?wx_fmt=png&from=appmsg)
- 在「用户管理」里点“新增用户”，填用户名（这里是 macro）、选角色（user），创建后会生成一把用户 API 密钥，记得保存。把它回填到连接设置的“用户 API 密钥”栏，数据访问就通了。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/ULE52ybiacSu9IIFYO4pWpTdVvjNU193CZeLqwQhicRx3J9BUh0rYrPF4SrAiaICKXZHZ4niboPcAVea3GoVPuRyibh41Y2QfM5bnPnpsg0gttzY/640?wx_fmt=png&from=appmsg)
- 此时就可以让Agent在工作台开始工作了，工作台分三栏：左边是上下文树，`user` 下放个性化记忆、`resources` 放 Agent 可引用的外部资源；中间浏览 `viking://` 目录内容；右边是会话区，可以在“终端”和“Agent”两种模式间切换。Agent 的工具调用会和左侧目录联动：它操作了哪个 `viking://` 文件，点一下就能在左边定位、中间打开。

## 使用

> 控制台跑通之后，用内置的 VikingBot 来体验核心能力。下面用一个最简单的例子演示跨会话记忆：先让 Agent 记住一件事，再开一个全新会话考它，最后到终端里看看这条记忆到底存成了什么。

- 在工作台中可以使用VikingBot进行工作，例如输入`记住我的职业：Java开发工程师`，Agent 收到后会调用 `openviking_memory_commit` 把这条偏好写进记忆，回复里给出记忆的 Memory URI，告诉你它存到哪了。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/ULE52ybiacSsVFrdXBRwVMQfeRk6jenOic6XNgBCFycibDFQZXWq86nmm36TH9TyZibuyT3rTgaMKq6fuIIIe6LutBpXUYlebj0gOlHtZ1HU1nk/640?wx_fmt=png&from=appmsg)
- 在新会话中提问`我的职业是什么`，新会话里 Agent 对你毫无印象，但它会先调 `openviking_search` 去记忆里检索，再回答“你的职业是 Java 开发工程师”。这条信息不在会话历史里，是 Agent 从 OpenViking 召回的，跨会话记忆就这么生效；

![](https://mmbiz.qpic.cn/sz_mmbiz_png/ULE52ybiacSsWXQOCpvGavas9ZqFfMgXyIpCnf6InkTicyXxIibIgYricRx3ABCz0Q76trQsMgq4BnKJoJvFdSBCGGCB5Jnp8qlv3eA9ialXHO9Y/640?wx_fmt=png&from=appmsg)
- 切到终端模式执行 `/search 职业`，会列出命中的资源、记忆、技能，每条都带着 `.abstract.md`、`.overview.md`、`profile.md` 这样的文件名和 L0/L1/L2 层级、相似度 score。左侧上下文树也能一路展开到 `user/macro/peers/macro/memories/profile.md`，预览里就是明文的“职业：Java开发工程师”。记忆以明文文件落盘，看得见、摸得着。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/ULE52ybiacStsgEsOVib97iatgr1nc0jWX4KW6CAiap18uh1W2CooFv9ibnI6vaNOUNLb0ZHh4Pm85kTFc1EiaNg01uxmypvLykGoWOQ8eyEJ03Ls/640?wx_fmt=png&from=appmsg)

## AI Agent支持

OpenViking 不只是给自家 VikingBot 用的，它把记忆能力开放给了主流 Agent。官方接入页列了一串：Claude Code、Codex、OpenClaw 等等，再加上通用的 MCP 方式（TRAE、Cursor 等）和 SDK（Python、LangChain 等）。

接入流程也给了三步：先启动自部署的 OpenViking Server，再跑一条安装脚本把 Claude Code 接进来，重启后就能用。也就是说，前面这套服务不光能在控制台里玩，还能给你日常用的 Coding Agent 装上长期记忆。

![](https://mmbiz.qpic.cn/mmbiz_png/ULE52ybiacSueWic0LtqlJice0BHMBlWyz1mrJWunpicMShEcGISia2JLrdA7HU8tnOmhSHOQsA4lCrSNkicBGIqmUkgAXiaVX4ZdK4Amo7WA20kAs/640?wx_fmt=png&from=appmsg)

## 总结

一圈体验下来，OpenViking 给人的印象是把上下文当工程对象来对待。部署很轻，一条 docker run 就把服务、控制台、VikingBot 一起带起来。记忆、资源、技能摊在 `viking://` 文件系统里，召回了什么、存到了哪，打开控制台一目了然。再加上插件、MCP、SDK 这些接入方式，这套记忆还能接进 Claude Code、Codex、Cursor 等一众 Agent。

如果你也受够了 Agent 换个会话就失忆，或者想给手里的 Coding Agent 补一块可观察、可管理的长期记忆，OpenViking 值得花半小时部署起来玩玩。
