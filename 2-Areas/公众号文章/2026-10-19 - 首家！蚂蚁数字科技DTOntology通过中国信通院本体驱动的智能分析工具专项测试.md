# 首家！蚂蚁数字科技 DTOntology 通过中国信通院本体驱动的智能分析工具专项测试
近日，在中国信息通信研究院（以下简称“信通院”）组织的本体驱动的智能分析工具专项测试中，**蚂蚁数字科技旗下 DTOntology 本体智能平台顺利完成了专项测试的全部内容，成为了首家完成此项测试的企业。**

**本体驱动的智能分析工具标准介绍**

随着数字化转型的深入推进，企业数据规模呈指数级增长，传统数据分析工具面临数据孤岛难以打通、语义鸿沟无法跨越、分析结果浅层化、决策缺乏可解释性等核心痛点。大模型技术的普及虽然显著提升了数据分析的交互体验，但在领域知识沉淀、逻辑推理严谨性、结果可靠性等方面仍存在明显短板。

在此背景下，中国信通院联合50余家企业的90余位专家，共同编制完成了《本体驱动的智能分析工具技术要求》，**蚂蚁数科作为核心参编单位之一**。标准包含数据与语义映射、本体构建与管理、智能分析与推理、智能交互应用、安全合规、平台保障与持续优化等6大能力域，20余个能力项，60余项能力要求。

中国信通院长期深耕智能分析领域标准化工作，已围绕该方向构建了覆盖"工具能力—智能体能力—性能评测"的多层次标准体系，并依托系列标准开展了多轮企业评测，积累了丰富的标准化实践经验和行业共识基础。累计目前，已完成智能分析领域二十余项工具产品评测。

**蚂蚁数科本体智能平台 DTOntology**

DTOntology 是蚂蚁数字科技面向企业自主研发的本体建模与安全语义查询一体化平台，采用"**数据源层—数据管道层-本体层—AI 应用层**"四层架构，向下连接企业存量数据，向上服务智能体与业务应用。平台以本体为核心组织企业的数据、口径、规则与动作，将经验性的业务约定固化为机器可读、绑定权威数据源的语义资产，支撑从理解、决策到行动的完整闭环。

**1. DTOntology 的核心能力**

**·**  **本体建模**：业务层定义实体、属性与术语，数据层管理数据集、维度与指标，两层通过显式映射关联——同一物理表可承载多个业务对象，同一业务对象亦可关联多个数据源，按业务视角组织取用。平台支持从业务资料中智能产出候选实体与关系，由业务专家逐条确认后入库；"知识注入"机制参照已有本体约束生成，避免新增口径与存量资产冲突。口径变更全程纳入版本管理，支持快照、结构化 Diff 与回滚。

**·**  **本体语义问数**：自然语言首先进入本体检索，再由系统显式路由至四类处理路径——指标取值类问题进入取数，计算类请求进入只读计算，任务执行类请求进入受控行动，知识类问答进入语义直答。知识检索采用本体检索增强生成（OAG）管道，支持广度扩展、因果链、演化树与跨域关联四种图遍历模式，沿语义关系逐层扩展相关节点，而非依赖文档碎片的概率匹配。

**·**  **受控执行**：只读的 Function 与产生副作用的 Action 严格分离——只读类查询可随时调用；写操作执行前必须通过 dry-run 预演，风险等级较高的动作自动转入人工审批，全程留存审计记录。前置条件以 Petri 网形式化表达，支持以 Facts 形式批量注入验证。模型的职责止于陈述意图；是否执行、如何执行，均由规则体系判定。

**·**  **安全治理与权限合规**：行级、列级权限控制与动态脱敏贯穿取数与执行全链路，全链路血缘与审计体系保障 AI 安全边界可控；分析结论携带权限与前置条件回到执行链路，确保越权或条件不满足的请求在执行入口被阻断。

**·**  **高质量数据集与血缘**：主动元数据引擎与字段级血缘自动追踪，数据质量持续观测与预警，为 AI 应用提供稳定、可靠、可溯源的数据供给。

**2. DTOntology 的核心优势**

**·**  **可核验：从演示材料到可核验项。** 能够生成 SQL 的产品并不罕见，能够稳定通过 70 项逐项核验的产品则相对有限。面向能力清单的认证可以通过演示材料完成，而专项测试要求每一能力项都有可触发的行为与可复查的痕迹。这也是衡量平台是否"本体驱动"的分界标准：后续解析、计算与执行是否实际引用了本体中登记的定义——若定义仅被登记而未被系统实际引用，其产出仍是一组静态文档；唯有被持续引用并能追溯，才构成可运行的本体。

**·**  **语义统一：一次登记、统一引用。** 企业级 AI 应用的短板具有结构性：输出依赖统计推断，而企业场景接近零容错。症结不在模型能力，而在缺乏"语义锚点"——"华南区"对应哪些维度、"毛利率"按何口径计算未经统一登记，智能体各自算出的数值均可自洽却相互矛盾。DTOntology 将业务口径分歧由反复澄清转为一次登记、统一引用，扩大模型规模无法解决的结构性问题由此获得工程解。

**·**  **可拒绝性优先于应答能力。** 仅具备应答能力的智能体门槛并不高，企业真正关注的是执行边界的可靠性。工程实践归纳出三类典型幻觉：动作幻觉——调错工具或传错参数；状态幻觉——臆造系统已处于某状态、跳过前置校验；路径幻觉——发明业务上不存在的捷径。三类幻觉恰好对应平台的三项执行约束：工具与参数受 Function/Action 类型约束，系统状态由 Petri 网前置条件核验，执行路径由规则体系限定。仅有成功应答，尚不足以证明系统具备在应拒绝时拒绝的能力——**"可阻断且可解释为何阻断"，是企业选择执行型智能体平台时最具区分度的检验维度。**

**·**  **端到端可审计。** 结果返回时附带完整推理链路——命中的术语、映射的字段、生成的 SQL 与执行耗时，逐环节可回放、可审计。数字可追溯至口径定义，建议可回溯至证据来源，写操作先经规则与授权校验，被拒绝的动作具备可解释的理由。

**3. 测试案例：从自然语言到可审计结果**

以业务人员输入"上月华南区哪些门店毛利率低于大盘"为例。

系统首先完成术语检索："毛利率"命中术语定义，"华南区"经维度值映射锚定至具体字段取值，"上月"解析为时间范围；检测到计税口径存在含税与不含税两套定义时，先执行澄清，再继续解析。

四路路由判定进入取数路径，问题被编译为一条携带口径约束的 本体语义SQL，通过本体引擎翻译为物理SQL，以只读方式执行。结果返回时附带完整推理链路——命中的术语、映射的字段、生成的语义 SQL、物理SQL 与执行耗时，逐环节可回放、可审计。

传统流程下，这一需求通常对应一张排期数天的取数工单；在本体驱动路径下，提问至获得结果以秒计。后续追问"那华东呢"，系统沿用已澄清口径直接扩展分析——本体语义问数链路至此完整贯通。

**本体项目落地实践**

**实践案例（一）：1688 Zeus 企业经营场景的生产级落地**

**问题起点：通用大模型"读过万卷书，但从未上过一天班"**

Zeus 是 1688 打造的组织级 Agent 协作平台，核心能力是把模糊的业务事项转化为可执行、可追踪的工作流。它要解决的问题很直接：通用大模型有海量世界知识，但唯独不懂这家企业——口径、策略、客户、做事方法，都是从未被写进任何公开语料的**组织隐性知识**。

落到业务现场，痛点集中在三类：

**·**  **口径缺失**："严选渗透率"在不同团队里算法不同——有人按 GMV 算，有人按订单数算。同一个问题问下去，Agent 会拿到 5 个不同数字，各部门数据对不上，汇报反复返工。

**·**  **业务对象认知缺失**：Agent 不知道"客户"在 1688 的语义——是买家还是卖家？是 KA 商家还是中小商家？同一个"客户"在不同业务线指向完全不同的实体，回答张冠李戴。

**·**  **经验无法传承**：上次选品为什么选了 A 没选 B？为什么这个客户被降级？决策背后的"为什么"从未被结构化记录，新人无法继承老人经验，同类决策每次从零开始。

一句话概括：**通用大模型是"读过万卷书但从未上过一天班的实习生"——它什么都知道一点，但唯独不知道你的企业怎么运作。本体就是给这个实习生装上"组织记忆"。**

以严选渗透率为例，口径登记后先固定客户范围、统计周期、交易范围与退款处理方式，再分别汇总分子与分母后相除——**不能直接平均各笔交易的比率，分母为零时保留不可计算的空值**。此后每一条任务沿用的都是同一份定义，而不是各自重写一遍公式。

**让 Agent"做"而不只是"说"：六道防线**

Agent 能生成看起来很专业的建议，但"说"和"做"之间隔着一条鸿沟——在企业生产环境中，一个不安全的执行动作比不执行更危险。Zeus 针对执行风险设置了六道防线（对应标准中"安全合规"能力域）：

**·**  **幻觉执行** → 每个动作带前置条件校验 + 证据链要求 + 人工审批卡点；Agent 输出不是"终稿"，而是"待审批的工单"。

**·**  **权限失控** → 明确定义 Agent 权限边界：可执行操作清单 + 前置条件 + 人工复核约束；高危动作（如冻结额度、诉讼启动）**强制双人复核**。

**·**  **不可审计** → 全链路审计留痕：操作账号 + 时间戳 + 操作对象 + 关联任务 ID + 模型版本 + 规则版本 + 数据快照版本，**三年可回放**。

**·**  **不可回滚** → 任务流支持状态追踪与回滚：每个动作有执行状态（待审批 / 执行中 / 已完成 / 已回滚），错误动作可拦截和回滚。

**·**  **不确定时编造** → 动态层硬约束：数值无法从数据源获取时，**必须返回区间 + 置信度 + 转人工，禁止点估计编造**（拒答红线）。

**·**  **执行与理解脱节** → 执行协同层让 Agent 不只生成内容，而是真正进入工作流执行并回收结果。

**关键洞察**：超过 89% 的任务由 Agent 自动完成，非工作时段任务占比过半——这部分是**纯增量**。Agent 真正成为"你下班了它还在干"的 7×24 同事。

Zeus 交付的不是一个 AI 工具，而是一个越用越懂业务的组织操作系统——**本体是它的认知底座，Agent 是它的执行手脚，三层递进是它的落地路径**。

**实践案例（二）：企业信贷风控场景的合规化落地**

企业信贷风控检验的是合规红线：收入、流水、工薪数据散落多系统，隐性关联与担保循环难以识别，预警误报引发"预警麻木"。在本体出现之前，业界已有四类技术路线，但都只能解决局部问题：

**·**  **RAG**：检索到什么算什么，担保圈环路等隐性关联不会写在文档里，且存在流水数字被"圆滑编造"的幻觉；

**·**  **Text2SQL**：能做表 JOIN，但难以完成图遍历，口径歧义会直接写进 SQL；

**·**  **纯知识图谱**：有语义层但缺动作层和动态层，知道"A 担保 B"，却不知道"担保 + 商票逾期 + 流水下滑"组合应触发什么动作；

**·**  **传统数仓 + BI**：表格思维，做不了多层穿透与环路检测，只能描述现状，难以解释原因和推演风险传导。

**因此，只有本体能同时承载语义层、知识层、动作层和动态层**，把数据、口径、规则、推理与证据链统一起来，支撑信贷风控从"查数报表"走向"可信推理与可解释决策"。

**本体三层建模**

**·**  **语义层**：登记 6 域 24 类实体与 15 类关系，收入等术语标注多口径与仲裁优先级（**财报＞发票＞流水**）；

**·**  **动作层**：20 项 Action 与 22 个 Function 绑定前置条件与权限，关联方穿透不超过 5 层，V3.0 级欺诈须双人尽调；

**·**  **动态层**：17 条规则与 9 项约束守住底线——数值不可得时仅以区间加置信度转人工、禁止编造，全程留痕、**三年可回放**。

**事理图谱传导走查**

静态知识图谱擅长回答"A 是谁""A 和 B 什么关系"，却无法回答"接下来会发生什么""风险会沿哪条路径传导"。当"A 企业商票逾期"这一事件被系统捕获后，本体推理引擎自动触发传导规则，沿股权链、担保链、供应链进行多跳传播，定位受影响的下游企业。传导过程并非简单的关系扩散，而是**含有逻辑依赖的因果传递**——每个事件节点都保留起因事件的关键要素，使系统不仅能判断"风险可能传导到哪些企业"，还能解释"为什么传导、依据是什么"，形成可审计的推理链条。

更进一步，事理图谱能够识别"担保 + 商票逾期 + 流水下滑"这类**组合事件的叠加效应**，在条件不充分时主动标注不确定性或拒答，避免给出误导性结论。

**本体可持续保鲜：生产环境下的长期可靠性**

本体构建不是一次性工程。一个在生产环境中服务 Agent 的本体，如果缺乏持续的维护和演化机制，会以比脏数据更隐蔽的方式迅速"腐烂"——概念过时、关系失真、规则失效，而 Agent 仍会基于这些陈旧知识给出看似合理实则错误的结论。

蚂蚁数科在本体保鲜上的核心思路，是构建**治理闭环与智能体运行时的双循环架构**：

**·**  **治理闭环侧**：本体演化遵循"**提取 → 暂存 → 更新 → 奖励计算 → 晋升**"的渐进式流程，新知识先进入暂存区，经过验证和评分后才正式融入本体，避免低质量知识污染生产环境；

**·**  **运行时侧**：Agent 的检索结果和推理结论被反馈回本体层，驱动结构自适应调整——检索命中率高的概念关系得到强化，频繁引发错误推理的路径被标记和修正。

概念漂移检测、多源冲突消解、Schema 版本管理与增量更新共同保障：本体演化时已有 Agent 的推理能力可以平滑迁移，不会因本体更新导致现有业务中断；历史推理记录保留完整链路，可按版本回放。

**大模型驱动的智能数据分析工具（ChatBI）测试简介**

大模型对BI的赋能是Data+AI融合发展的必然趋势，也是大模型应用落地实践中最具价值的场景之一。大模型可以准确理解用户数据分析需求，将自然语言拆分为具体的分析任务、转化为可执行的数据查询操作，降低数据使用门槛；同时也能有效整合企业数据资源，消除数据孤岛，并助力多模态数据的价值挖掘，助力企业以较低的技术门槛，高效地开展具备一定深度的数据分析，赋能业务洞察与精准决策。在此背景下，为进一步推动大模型在数据分析领域标准化的发展，中国信通院联合业界50余家企业的100余位专家，共同研制完成了《大模型驱动的智能数据分析工具技术要求》标准，标准包含数据准备能力、大模型智能分析能力、智能交互能力、分享协作能力、集成部署能力、安全管理能力等六大能力域，18个能力子域，54个能力项，目前已有十六家企业完成此项评测，基于此标准的专项评测与信创评测报名火热进行中。

标准框架

**数据智能体（Data Agent）测试简介**

智能体（AI Agent）凭借其在规划决策、记忆、工具使用等方面的出色能力而备受瞩目。目前，众多企业正在积极推进智能体在数据分析、数据开发、数据服务等数据工作中的实践应用，数据智能体（Data Agent）这一概念也应运而生，相关工具平台产品持续完善，成为智能时代连接数据和智能的关键桥梁。中国信通院联合50余家企业的100余位专家共同编制完成了《数据智能体（Data Agent）技术要求》标准，标准包含数据集成、任务规划与执行、数据分析场景化适配、自我进化、运维评测及集成、安全管理等六大能力域，27个能力要求，70余项能力细则。目前已有数巅科技、中信建投证券、东方金信等企业完成评测，基于此标准的专项评测与信创评测报名火热进行中。

**数据智能体（Data Agent）性能测试简介**

数据智能体（Data Agent）是专精于企业数据工作的智能体系统。数据分析智能体以“可对话的自主数据分析师”为技术定位，支持用户以自然语言提问获取数据，并提供数据解读、波动归因等洞察能力，帮助用户提炼高价值的业务洞察并生成可行动建议。通过将用户用自然语言提出的数据分析需求转化为可执行的数据问题，数据分析智能体能够在零散、庞杂、多来源的数据基础上，自主规划并执行包含数据整合、清洗、建模、推理、挖掘与验证在内的完整深度分析闭环过程，最终生成具备研究深度的分析成果；并将分析结果以最合适的形式（例如结构化的分析报告）有效地呈现给用户。在数据分析智能体技术落地应用的过程中，计算分析的准确率、分析报告可读性、归因逻辑可解释性、业务建议可执行性、系统的稳定性等性能因素对用户的信任度和系统可用性的影响至关重要。为解决性能基准缺失引发的信任问题，中国信通院牵头联合30余家企业的50余位专家完成了《数据分析智能体性能测试规范》标准的编制工作。本项工作旨在建立科学合理的评价体系，全方位评价数据分析智能体的生产级可用性。目前已有火山引擎、易能安科等企业完成评测，基于此标准的专项评测与信创评测报名火热进行中。
