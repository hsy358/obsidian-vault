# GitHub 2.3万 Star！百度开源 Unlimited-OCR，让 AI 一次读懂100页 PDF！
科研人每天面对最多的文件，可能不是 Word，而是PDF。

论文、专利、Supplementary Information、药物活性表格……真正麻烦的不是“看不懂”，而是：

怎么把 PDF 里的信息批量提取出来？

尤其是药物化学论文，一篇文章里可能同时包含化合物编号、IC50、Ki、Kd、靶点、SAR 表格和二维结构。人工一篇篇整理，不仅慢，还特别容易出错。

最近，百度开源的Unlimited-OCR在 GitHub 已获得超过2.3 万 Star。

它值得关注的地方在于：它想做的已经不只是传统 OCR，而是让 AI直接解析复杂、甚至多页的长文档。

## 一、不只是“识字”，而是解析整篇 PDF

传统 OCR 更像：

-

```
图片 → 文字
```

但科研论文远比一张图片复杂。

一篇 PDF 可能同时包含标题、双栏正文、表格、公式、图片、图注以及几十页连续内容。

Unlimited-OCR 强调的是：

-

```
One-shot Long-horizon Parsing
```

也就是长文档解析。

简单来说，它希望从：

-

```
PDF → 结构化文档
```

而不是只输出一堆散乱文字。

目前官方已经支持单图片、多图片和多页 PDF。PDF 可以先自动转换为页面图片，再进行连续解析。

这对扫描论文、专利和无法直接复制文字的 PDF 尤其有用。

## 二、对科研人，真正有价值的是“数据提取”

例如一篇药物化学论文中有这样的表格：

普通 OCR 即使把所有数字识别出来，也可能把行列关系打乱。

而文档解析模型不仅识别文字，还会尝试理解页面布局和内容结构。

这意味着未来可以构建这样的流程：

-

-

-
-
-
-

```
论文 PDF↓Unlimited-OCR↓提取 Compound ID、IC50、Ki、Kd、靶点、实验条件↓整理为 CSV / Markdown↓建立自己的药物活性数据库
```

对于需要批量做文献调研、SAR 分析或者机器学习数据整理的人来说，这比单纯“把 PDF 转成文字”有意义得多。

## 三、还能进一步提取化合物结构吗？

这里需要注意：

Unlimited-OCR 并不是专门的化学结构识别工具。

论文里的二维化学结构，要真正转换成 SMILES，仍然更适合交给 DECIMER、MolParser、OSRA 等 Optical Chemical Structure Recognition 工具。

但两类工具组合起来，就很有意思了：

-
-
-
-
-
-
-
-
-
-
-
-
-
-
-

```
药化论文 PDF↓Unlimited-OCR 解析正文和表格↓得到 Compound ID + IC50/Ki/Kd↓定位对应二维结构↓DECIMER / MolParser↓SMILES↓RDKit 标准化、去重、计算性质↓Compound–Structure–Activity 数据集
```

继续往下甚至可以连接 QSAR、分子聚类、虚拟筛选、Docking，以及 REINVENT4 等分子生成工具。

换句话说：

Unlimited-OCR 可以成为“科研 PDF → 化学数据”的第一道入口。

## 四、可以部署到自己的 GPU 服务器

Unlimited-OCR 目前已经支持 Transformers、vLLM 和 SGLang。

因此它不仅可以拿来跑几张图片，还可以部署成实验室内部的 OCR 服务。

例如：

研究人员上传几十篇 PDF↓GPU 服务器自动解析↓输出 Markdown / 文本 / 表格↓大模型继续做信息提取↓进入本地科研数据库

对于需要处理几百甚至几千篇论文的团队，这类工作流的价值会更加明显。

过去 OCR 解决的是：

-

```
Image → Text
```

而 Unlimited-OCR 这类模型开始尝试解决：

-

```
Document → Structured Data
```

对于普通用户，这可能只是“PDF 解析又多了一个工具”。

但对于药物研发、化学信息学和文献挖掘来说，它更值得期待的方向是：

-

```
PDF → 化合物 → 活性数据 → SMILES → 数据库
```

如果这条流水线真正跑通，我们以后整理一篇药化论文，可能不再需要对着表格一个数字一个数字地复制。

科研 PDF，也开始真正进入“机器可读”的时代。
