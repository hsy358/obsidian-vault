# StaffDeck

StaffDeck是一套面向企业的数字员工构建与管理平台，帮助专业员工将工作经验、业务流程和判断标准固化为可以持续工作的数字员工，接手重复性任务，并将个人能力沉淀为可复用、可迭代、可追溯的组织资产。StaffDeck由面壁智能，东北大学-面壁智能数据智能联合实验室，清华大学THUNLP实验室，OpenBMB与AI9Stars联合研发，面向希望将 AI 从个人效率工具升级为组织生产力的企业与机构。

# 四、功能概述

# 核心亮点

- **数字员工构建与管理**将专业员工的经验、流程和判断标准固化为拥有岗位、工号、能力档案和工作记录的数字员工；支持能力成长、权限隔离及发布复用。
- **状态机驱动的流程型技能**通过自然语言生成结构化 SOP，以状态机保证复杂流程准确执行；支持多个流程实时切换、上下文保留、可视化编辑、版本管理和分支演化。
- **文档结构感知的知识检索**基于文档、章节、页面和摘要等层级构建可导航索引，让数字员工先判断信息可能位于哪里，再逐层定位原文；支持知识分桶、定向检索、来源引用和检索调试。
- **自主执行与持续迭代**通过 HTTP API、MCP 和定时任务执行真实业务操作，并结合长期记忆、完整 Trace、真人接管、用户反馈和反馈分析形成持续迭代闭环。

# 核心流程

- **创建数字员工**设置职位、岗位边界、服务风格、创建者与访问范围。
- **配置员工能力**从广场复制或自行创建知识库、通用技能、SOP 与工具，不修改广场原件。
- **发起会话**从数字员工广场或员工列表进入；发送首条消息后持久化正式 Session。
- **执行并观测**在执行记录中查看流式意图、检索、技能、工具、校验和回答事件。
- **必要时介入**继续排队请求、取消运行、转人工或处理待回答内容。
- **持续运营**利用记忆、反馈、对话日志和定时任务长期优化员工能力。

## 📝 小助分析（2026-07-24）

### 项目一句话定位

**StaffDeck**（AGPL-3.0，OpenBMB + 面壁智能 + 清华 THUNLP + 东北大学数据智能联合实验室）是**「组织视角」**的数字员工构建与管理平台——把"专业员工的经验 / 流程 / 判断标准"固化为拥有工号 + 岗位 + 能力档案 + 工作记录的数字员工，本质是 **AI 资产化 / 能力沉淀** 而非单纯的"个人效率工具"。

### 四大核心亮点（架构信号）

| # | 能力 | 技术含义 | 德勤 MVP 借鉴价值 |
|---|---|---|---|
| 1 | **数字员工档案**（工号、岗位边界、能力档案、权限隔离、发布复用） | "员工"是 1 级实体，不是 Chatbot | ✅ **高**——Hermes 的 Agent Profile 应当升级为"员工级档案" |
| 2 | **状态机驱动的流程型技能**（NL → SOP + 状态机；多流程切换 / 上下文保留 / 可视化编辑 / 版本管理 / 分支演化） | 自然语言→结构化+强一致性 | ✅ **高**——状态机是 Hermes 已有的，但要借鉴"分支演化 / 可视化编辑" |
| 3 | **文档结构感知的知识检索**（章节/页面/摘要层级索引 → 先判断"信息在哪"再逐层定位 → 知识分桶 + 定向检索 + 来源引用 + 检索调试） | 不是 RAG，是 **RAG 2.0：导航式检索** | ✅⭐ **极高**——这正是 Dataview/Datacore 的延伸方向 |
| 4 | **自主执行与持续迭代**（HTTP API + MCP + 定时任务 + 长期记忆 + Trace + 真人接管 + 反馈分析闭环） | 完整"运行 + 观测 + 反馈"链路 | ✅ **高**——Mem 里 Hermes dispatcher 60s tick 已有，但反馈分析 dashboard 缺 |

### 单端口技术选型亮点

- **单端口部署**：FastAPI 同时提供 UI + API + Swagger（5173）—— 部署、demo、调试门槛极低
- **OpenAI 兼容 API**：**不绑定供应商**，模型路由完全可插拔（和 Hermes v0.14 设计同源）
- **AGPL-3.0**：⚠️ **商用注意**——网络服务交付场景下传染性强；企业内部使用风险可控

### 关键判断（产品线决策，2026-06-29 已锁定）

✅ **StaffDeck 是「组织视角」的平台外壳，Hermes / OpenClaw 是「执行器内核」**——
- StaffDeck：组织资产化（数字员工 + 知识 + SOP 沉淀） → **平台层**
- Hermes v0.14：单 Agent 自主执行 → **执行器层**
- AgentRouter：多执行器适配 → **适配层**
- 三者关系 = **皮 + 核 + 适配**，**不是替代关系**

### 借鉴清单（5 条，立刻能动手）

1. **Agent Profile 升级**：Hermes 的 Agent 元信息 → 升级为"工号 + 岗位边界 + 能力档案 + 权限隔离"
2. **状态机编辑器可视化**：StaffDeck "可视化编辑 / 版本管理 / 分支演化" 是 Hermes dispatcher 缺失的能力——可以研究其实现
3. **RAG 2.0 方向**：从"全文检索"升级到"章节级导航式检索"——和 Datacore 配合，给德勤 MVP 文档类 Agent 用
4. **反馈分析 dashboard**：补一块"用户反馈 → 改进点 → Skill 更新"的闭环 UI（目前 strategy_improvements 是手写版）
5. **单端口部署模板**：5173 单端口 + FastAPI 同时 UI/API/Swagger 是个成熟模式，可以照抄到德勤 MVP 的 demo
