AI 做 PPT，真正困难的从来不是“生成几页文字”，而是能不能把内容结构、视觉设计与可编辑性同时做好。最近我整理了 10 个能与 Codex、Claude Code 等 AI 编程智能体配合使用的 PPT 项目，它们看似都在“生成 PPT”，走的却是三条完全不同的路线。

想让 AI 操作桌面 PowerPoint

需要实时修改旧稿或批量操作，优先看Office 自动化类。

02

PART

网页演示：视觉与舞台体验优先

WEB SLIDES · HTML PRESENTATION

SKILL 1
#### guizang-ppt-skill

它的特点不是“能生成幻灯片”，而是对视觉风格和叙事节奏有很强的约束。它主要生成单文件 HTML 横向翻页演示，同时覆盖 PPT 配图和多平台封面。

项目提供电子杂志与瑞士国际主义两套视觉系统，并强调亮暗页交替、章节页穿插和版式节奏，避免整套演示重复同一种卡片结构。

适合场景

个人演讲、趋势分享、方法论发布，以及需要同步制作封面的内容。

**一句话评价：**适合把 PPT 当作一套视觉作品来做。

SKILL 2
#### next-slide

它的核心主张很直接：你的下一份演示，不一定非得是 PowerPoint。它输出零依赖的单文件 HTML，浏览器直接打开即可播放。

项目提供深色、浅色、编辑风、大胆风、复古风、艺术风和文化风等多个家族，拥有50 多种视觉预设，并支持中英文内容。

适合场景

快速提案、创意分享、线上演示，以及需要大量风格探索的内容。

**一句话评价：**想快速试出“这次演示该长什么样”，它很顺手。

SKILL 3
#### html-ppt-skill

它更像一套完整的 HTML 演示工作室，提供丰富的主题、页面布局、整套模板和动画效果，全部基于静态 HTML、CSS 与 JavaScript。

突出亮点是演讲者模式：独立窗口可同时显示当前页、下一页、演讲稿与计时器，而且预览与观众页面使用同一套渲染逻辑。

适合场景

课程演示、技术大会、产品路演，以及需要逐字稿和计时的正式分享。

**一句话评价：**它把浏览器演示从“能播放”推进到了“能正式上台讲”。

SKILL 4
#### revealjs-skill

它基于成熟的 Reveal.js 框架，支持主题、动画、代码高亮、演讲者备注、多栏布局和图表，并加入页面溢出检查，减少文字裁切和内容塞不下的问题。

项目还覆盖 PDF 导出、幻灯片截图和浏览器内文本编辑。相比强调“视觉惊艳”的项目，它更像一个成熟、可扩展的工程化底座。

适合场景

技术课程、开发者分享、代码讲解，以及需要图表与演讲者备注的内容。

**一句话评价：**技术演示要稳定、可维护、方便扩展，它是很实用的选择。

SKILL 5
#### frontend-slides

它强调“先看，再选”，会先生成多个动态封面预览，让用户看过效果后再决定整套演示的方向。最终输出是零依赖单文件 HTML。

固定的 1920×1080 舞台会整体缩放，确保不同屏幕上的版式关系稳定；同时要求形成清晰的视觉个性，尽量避免千篇一律的 AI 味。

适合场景

品牌发布、创意提案、作品展示，以及对动态效果和视觉个性要求较高的演示。

**一句话评价：**它把风格选择从“猜”变成了“看着选”。

03

PART

原生 PPTX：编辑与正式交付优先

NATIVE PPTX · EDITABLE DELIVERY

SKILL 6
#### anthropics/skills/pptx

它面向原生 PowerPoint 文件，覆盖 PPTX 的创建、编辑、读取和质量检查。更值得关注的是一套完整的制作纪律：字体层级、页面留白、布局多样性、图像与图表使用，以及逐页视觉审查。

它特别强调第一版通常不应被视为最终版，必须经过渲染、检查和修正，再完成交付。

适合场景

商务汇报、客户交付、内部报告，以及需要在PowerPoint 中继续修改的项目。

**一句话评价：**价值不只是生成 PPTX，更在于把“生成后必须检查”写进流程。

SKILL 7
#### MiniMax-AI/pptx-generator

它基于 PptxGenJS，覆盖新建、编辑和读取 PowerPoint 文件，并对封面、目录、章节页、内容页和总结页等标准页面类型做了清晰划分。

每页可以拆成独立模块，最后统一编译成完整 PPTX；主题对象负责控制颜色、字体和视觉规范，适合把演示文稿做成可重复生成的工程产物。

适合场景

批量报告、标准化企业模板、自动化周报月报，以及需要代码化维护的 PPTX。

**一句话评价：**适合把 PPT 生产流程做成可复用的流水线。

SKILL 8
#### powerpoint-skill

封面里写成了 powepoint-skill，正确项目名应为 powerpoint-skill。

它明显偏向技术和学术场景，支持 PptxGenJS、原生 OMML 数学公式、LaTeX 公式渲染，以及 Graphviz、Mermaid、TikZ 等图表与结构图工具。

优势是复杂公式和技术图示，代价是依赖较多、环境配置更重。面对论文、算法和科研汇报时，它的专业价值会非常明显。

适合场景

论文答辩、科研报告、算法讲解，以及含有大量公式和技术结构图的演示。

**一句话评价：**普通 PPT 用它有点重，科研和技术汇报用它正合适。

SKILL 10
#### ppt-master

它可以接收 PDF、Word、PPTX、网页和 Markdown 等多种来源，先整理内容，再进入策略、设计规范、页面执行与视觉检查。

项目采用 SVG 作为重要中间表达，并支持导出可编辑 PPTX，同时覆盖模板、品牌预设、图表组件、图标库、动画、旁白与视频导出。它以阶段化确认和质量检查换取稳定性。

适合场景

正式路演、品牌汇报、复杂长篇演示、多来源资料整合，以及需要多轮打磨的项目。

**一句话评价：**它更像一支虚拟 PPT 团队，而不是简单的页面生成器。

04

PART

Office 自动化：直接操作真实 PowerPoint

LIVE OFFICE · DESKTOP AUTOMATION

SKILL 9
#### mcp-server-ppt

严格来说，它不是普通的“生成 Skill”，而是一套PowerPoint MCP Server 与命令行工具。

它通过 Windows 上的 PowerPoint COM API，让 AI 直接控制真实软件：创建和移动页面、修改文本、添加形状与图片、生成图表和表格、设置动画和转场、编辑备注、操作 VBA，并导出 PDF、图片或视频。

最大差异是所见即所得。限制也很明确：只适合 Windows，而且必须安装桌面版 PowerPoint。

适合场景

修改现有 PPT、批量替换内容、实时调整页面，以及自动化 Office 操作。

**一句话评价：**如果目标是让 AI 成为 PowerPoint 操作员，它比单纯的生成器更对路。

05

PART

到底怎么选？记住这四条

DECISION GUIDE · 选择方法

1先看交付格式：浏览器播放或导出 PDF，优先看 HTML 路线；客户要继续修改，优先看原生 PPTX；AI 要操作正在打开的 PowerPoint，就选 MCP 自动化。

2再看内容类型：视觉叙事可看 guizang-ppt-skill、next-slide 或 frontend-slides；技术课程可看 revealjs-skill 与 html-ppt-skill；科研公式与技术图表可看 powerpoint-skill。

3生成成功不等于交付完成：文字溢出、字号过小、页面重复、图片错位和风格漂移，必须通过渲染、截图与逐页检查解决。

4最强的是组合：先整理内容，再用网页演示 Skill 探索视觉方向，最后根据交付要求决定导出 PDF，还是重建为可编辑 PPTX。

工具负责能力，工作流负责质量
