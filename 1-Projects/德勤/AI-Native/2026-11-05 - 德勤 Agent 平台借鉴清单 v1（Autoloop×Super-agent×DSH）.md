# 德勤 Agent 平台借鉴清单 v1

> **前提（2026-06-29 决策，不变）**：**Hermes Agent v0.14 是德勤项目 Agent 框架的唯一选择**。
> 本文所有开源项目只作**技术借鉴**，不做产品二选一。
> 目标形态一句话：**小内核 + 厚治理**。

---

## 0. 本清单的三条来源

| 来源 | 贡献什么 | 本机验证状态 |
|---|---|---|
| Agent Autoloop（KKKKhazix） | 内核纪律：确定性派活、零出站网络、厂商中立、事件溯源、跳数熔断、注入防护、工程测试法 | ✅ **已本机实跑跑通全闭环**（2026-11-05，见实跑记录） |
| DeepSeek Super-agent（dsh-superagent-prototype） | 治理层：Policy/Mandate/Ticket 领域模型、注意力经济学、observe 灰度、Router/Worker 分层 | 📄 读码分析（研究原型，未实跑） |
| DeepSeek Harness / Cordis（DSH） | 可插拔执行器：Capability Seam 三角色、Profile/Bundle 配置行打包 | 📄 读码分析 |

## 1. 目标架构（建议落点）

```
┌───────────────────────────────────────────────────────────┐
│ 治理层（借鉴 Super-agent）                                  │
│  Policy 版本化 · Mandate 不可变 · Ticket/Assignment · observe 灰度 │
├───────────────────────────────────────────────────────────┤
│ 内核层（借鉴 Autoloop · 小、确定性、零出站）                  │
│  收事件 → 按规则分活 → 派给 Agent → 记每一步                  │
│  事件溯源日志 · 唯一写入点+单事务 · 跳数熔断 · 指令数据分离      │
├───────────────────────────────────────────────────────────┤
│ 执行层（已定）                                             │
│  Hermes Agent v0.14 + 执行器抽象层（每种 harness 可插拔）        │
├───────────────────────────────────────────────────────────┤
│ 适配层（可插拔）                                            │
│  事件源 · Agent 适配器 · 通知通道 · CI/CD 交付                 │
└───────────────────────────────────────────────────────────┘
```

## 2. 内核下限清单（**这 8 条不可砍**，砍了安全评审就过不了）

| # | 基线 | 来源 | 验收方式 |
|---|---|---|---|
| 1 | **唯一写入点 + 单事务 + Outbox** | Super-agent | 所有状态变更走一个事务；外部副作用提交后才执行 |
| 2 | **授权不可变 + 规则版本化** | Super-agent | 任一轮可回答"谁在什么规则版本下批准了什么范围" |
| 3 | **指令数据分离 + 事件字段白名单** | Autoloop | 外部文本只落文件不进提示词；事件带 `cwd`/`agent`/`access` 直接拒收 |
| 4 | **跳数熔断（TTL）** | Autoloop | 层数 > 8 自动停派 + 告警；人工介入与定时复查不清零 |
| 5 | **事件溯源日志 + 一条命令查清来龙去脉** | Autoloop | `why <轮次>` 类命令输出完整链路（实测可用） |
| 6 | **核心零出站网络** | Autoloop | 内核只依赖 `node:crypto` + `node:sqlite`，零 http client |
| 7 | **厂商中立接口** | Autoloop / DSH | 内核只认 `{name, use, access, command?}`，不认 Claude/Codex/Hermes |
| 8 | **首投 observe 灰度** | Super-agent | AI 生成的规则/策略首次上线只记录不执行，人核对后放开 |

> 这 8 条是**验收基线**，不是愿望清单。每条都对应可演示的证据。

## 3. P0 —— 直接进 MVP（成本低、收益高）

| # | 借鉴点 | 落点 | 来源 | 备注 |
|---|---|---|---|---|
| P0-1 | **Router/Worker 分层，Router 无执行权** | 执行器抽象层之上加轻量 Dispatcher，**只认路由不认工具** | Super-agent | 结构上做不到，比 prompt 叮嘱可靠；消除"活太小不委派"的长尾 |
| P0-2 | **事件先代码过滤、后模型判断** | 事件入口做信噪比过滤（告警/工单/CI） | Super-agent | Router 决策成本实测 6.4s → 1.6s，缓存 token 省 23% |
| P0-3 | **注意力经济学作为设计原则** | 每条消息/面板元素都要能自证价值 > 它消耗的注意力；聊天回复 ≤100 字；面板只留"需要人处理" | Super-agent | 可直接写进**交付验收标准**与 UI/IM 交付规范 |
| P0-4 | **按影响停手，不按努力停手** | 做到"可评审"为止；需业务决策就停，一次只问一个结构化问题 | Super-agent | 金融/政务里"该问"比"做完"更重要 |
| P0-5 | **指令数据分离 + 字段白名单** | 内核提示词只含校验过的类型/编号/链接 | Autoloop | 客户安全评审的硬要求 |
| P0-6 | **跳数熔断** | 编排层默认参数：层数 > 8 停派并告警 | Autoloop | 防止 Agent 互相唤醒烧额度 |
| P0-7 | **配置手册写成"给 AI 读的"** | 交付物配套 SKILL.md 形态的配置指南，让实施期由 Agent 帮客户生成规则 | Autoloop | **显著降低实施成本** |
| P0-8 | **observe 首投灰度** | 客户环境上线前先只记录不执行 | Super-agent | 直接写进交付方案 |
| P0-9 | **事件合并（复用同一轮 + lane 分线）** | 同一交付物上的连续事件合并成一轮，避免多 Agent 同时改同物 | Autoloop | 实测其源码 `enqueue()` 确实复用同 rule+lane 的排队 run |
| P0-10 | **零出站网络的内核** | 核心不出网，联网能力全在适配层 | Autoloop | 便于金融/政务网络分区审查 |

## 4. P1 —— 改造后抄

| # | 借鉴点 | 落点 | 来源 |
|---|---|---|---|
| P1-1 | **Policy 版本化 + Mandate 不可变** | 授权底座（**已升为 P0 级要求**，见 §2-2） | Super-agent |
| P1-2 | **Ticket / Assignment 领域模型** | Ticket 自己定状态不跟随执行器；Assignment 生命周期内可多个 → 天然支持换执行器/重试 | Super-agent |
| P1-3 | **授权极简**：拒绝 Principal/Membership 实体，跨源身份映射是 prompt 文本 | 授权模型省掉一整个权限子系统 | Super-agent |
| P1-4 | **Watchdog 独立 session** | 长周期交付的停滞检测 + 自然语言诊断 | Super-agent |
| P1-5 | **工程测试方法论** | 交付验收测试方案：随机化仿真（20 万步）、强杀 1000 次、种子可复现、benchmark 达标线 | Autoloop |
| P1-6 | **Plugin/Bundle = 打包配置行而非代码** | "每个组件独立可部署 + 模块化打包"的落地形态 | DSH |
| P1-7 | **Capability Seam 三角色** | 执行器抽象层的接口定义：Service Definition / Provider / Consumer | DSH |

## 5. P2 —— 抄思想不抄实现

- 「**不为主体**」：主体是事件元数据，跨源身份映射是 prompt 文本
- **文档渐进式编号**（000→008，每篇只建立在前面的概念上）→ 德勤交付文档/技术方案模板
- 「**不要用它来制造产量**」→ 交付方对客户的责任话术
- 「**事件 → 派活 → 执行 → 交付 → 批奏折**」→ 对客户讲"人在环"的叙事框架
- 「**一次只问一个具体问题**」→ 交互规范

---

## 6. 明确不抄

| 不抄 | 原因 |
|---|---|
| Autoloop 的「rules.json 即全部授权」 | 无版本、无审计、无准入分级 → 金融/政务过不了安全评审 |
| Autoloop 依赖「本机已登录的 CLI Agent」 | 客户服务器上不成立，须切 API Key 模式 |
| Autoloop 的事件轮询/Webhook 具体实现 | 用我们自己的 Source 抽象 |
| Super-agent 的飞书/GitHub 双通道实现 | 客户渠道不同，**Source 抽象该抄** |
| Super-agent 的 TypeScript + DSH Bundle 技术栈 | 德勤在 Hermes v0.14 之上 |
| Super-agent 的 Router session 规模上限问题 | DeepSeek 自己也没解，等社区方案 |
| 两个项目的具体代码 | 只借鉴机制与范式 |

**内核原型开发中发现并修复的两个真实缺陷**（已回写本清单第 4 条的实现细则）：

1. **熔断必须是链级状态，不能是轮次级** —— 轮次级熔断会因 parent 链断裂而被绕过，Agent 可无限自我唤醒。
2. **合并维度（lane）与链标识（chain_key）必须正交** —— 混用会导致跳数永远停在 1，熔断形同虚设。
