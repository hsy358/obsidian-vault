V1.0 产品设计定稿
适用对象：产品负责人、研发经理、后端与前端研发、测试及安全治理人员。
本设计用于建立 OUTIS 的组织隔离、项目协作、跨组织委外和 Agent 执行授权规则。目标是在少量人员与多个数字员工协同的条件下，减少重复授权，并明确每一次信息访问和业务动作的边界。
采用组织管身份与治理、空间管工作组织、项目管协作授权、受限工作包管局部隔离、Task 默认继承的结构。人和 Agent 均具有稳定身份，参与项目不自动获得全部数据、工具或审批权。

# 1 设计结论与基本原则
权限模型首先回答四个问题：谁，对什么资源，执行什么动作，在什么条件下。前端用少量角色和权限包简化配置，后端按明确的资源、动作和条件执行判断。
新组织建立独立的逻辑租户边界，而非强制独立数据库。项目有唯一所属组织；跨组织参与通过显式共享实现，不改变资源归属。
空间不自动扩大项目数据权限。项目默认仅项目成员可见；其他空间可以引用同一项目，但引用不复制、不迁移、不扩权。
普通工作包和 Task 继承所在协作范围的业务权限。受限工作包不继承普通项目内容权限，单独管理成员。知识库、源文件、外部系统及凭据仍有独立授权。
配置权、授予权、内容权和凭据使用权分开。组织管理员不自动成为所有内容的超级读者。未配置动作默认不可用，明确拒绝优先。
Agent 会执行某项技能只说明能力存在，不等于已经获得业务执行授权。权限由服务端和执行器强制校验，不交由模型自行判断。
| 问题 | 后端依据 | 产品表达 |
| --- | --- | --- |
| 谁 | 稳定主体与有效身份关系 | 人 用户组 Agent |
| 对什么 | 真实资源归属与授权范围 | 项目 工作包 资料 工具 |
| 做什么 | 动作集合及可授上限 | 查看 编辑 调用 执行 外发 |
| 什么条件 | 任务委托与组织策略 | 项目 期限 目的 额度 审批 |
# 2 组织与空间职责
替代方案是把空间做成统一安全域，让成员自动访问全部继承项目。但这会增加受限项目、迁移权限变化和跨空间例外。本版不采用该方案。若未来确需部门全量共享空间，应作为独立模式评审，不改变现有空间的默认语义。
### 2.1 组织作为租户边界
组织管理内部人员、用户组、Agent、资源归属和对外协作政策。同一平台账号可加入多个组织，但每个组织的成员关系、角色和数据权限分别判断。组织 ID 必须由可信资源记录与有效身份关系确认，不能仅相信客户端传入值。
### 2.2 组织管理与内容访问分离
组织所有者负责组织存续和最高治理；管理员按授权管理身份、策略及配置；成员参与具体业务。外部协作者是访问身份类别，不因受邀访问一个工作包而成为内部员工。接管或应急访问必须有明确策略、限定范围和审计，不能通过后台静默获得私人正文。
### 2.3 空间负责组织与展示
空间是项目集合和工作入口。空间管理者可以整理空间、维护引用或默认团队，但不能据此读取未授权项目。项目只有一个主空间，其他空间可引用；迁移所属空间须满足项目、原空间和目标空间的管理要求，不自动改项目成员。
### 2.4 批量协作通过显式用户组实现
空间可以维护推荐团队。创建项目时，创建者明确选择把某个组加入项目并指定角色，此后由组成员关系动态生效。加入空间本身不获得项目权限。界面须展示授权来源，避免把默认勾选隐藏成自动扩权。
# 3 项目角色与授权矩阵
项目是主要协作授权入口。创建者成为项目负责人，获得该项目内管理能力，但仍受组织策略和可授上限限制。项目默认仅明确加入的人、用户组和 Agent 可见。
人和 Agent 的项目角色都不能自动打开无权来源资料、独立知识库或凭据。受限工作包采用独立授权。项目成员能编辑普通业务内容，不代表能审批、发布或对外发送。
| 查看者 | 协作者 | 负责人 | 操作 |
| --- | --- | --- | --- |
| 允许 | 允许 | 允许 | 查看普通项目内容 |
| 不允许 | 允许 | 允许 | 编辑普通任务与交付草稿 |
| 不允许 | 不默认允许 | 策略与可授上限内 | 管理项目成员和分工 |
| 不允许 | 不默认允许 | 另需对外共享权限 | 邀请外部人或 Agent |
| 需对应来源授权 | 需对应来源授权 | 需对应来源授权 | 读取独立资料或受限包 |
| 按具体动作另行授权 | 按具体动作另行授权 | 按具体动作另行授权 | 审批 验收 发布 外发 导出 |
| 不由查看角色推导 | 按连接及运行授权 | 按连接及运行授权 | 工具执行与凭据使用 |
| 不允许 | 需 Agent 管理权 | 需 Agent 管理权 | 修改 Agent 配置 |
### 用户组授权
财务组、项目团队等可以作为授权主体。成员加入或退出组，影响该组来源的权限；若仍有个人直接授权，不能把组撤权误认为完全撤权。授权页面应支持查看全部来源和一并撤销。
### 角色的实现边界
三种角色是易用的业务模板，不替代细粒度动作。删除、归档、修改授权、审批和外发的具体动作清单须在开发前冻结，默认不因角色名称而扩大高风险权限。
# 4 工作包与 Task 的继承
普通工作包按项目成员角色继承对应业务权限，内部 Task 默认继承工作包。初版不开放任意 Task 自定义访问控制列表，避免形成大量难以解释和回收的例外。独立 Task 则由创建者和明确参与者访问，不借独立任务绕过来源资料权限。
受限工作包用于敏感内容或委外协作。启用受限模式后，普通项目成员不自动读取其正文、附件和讨论，必须显式加入。对父项目仅返回有权查看的最小状态，不能通过名称、统计、人员列表或进度说明泄露敏感信息。
业务协作关系与资料授权分别判断。把一个文档链接放入任务，不等于给所有任务成员开放该文档；复制、摘要和派生文件也应保留来源及输出接收范围。
| 特殊规则 | 资源 | 默认授权来源 |
| --- | --- | --- |
| 仅成员可见 | 项目 | 明确成员与用户组 |
| 不扩展独立资料权限 | 普通工作包 | 项目角色 |
| 阻断普通内容继承 | 受限工作包 | 直接授权 |
| 初版不开放任意覆写 | 包内 Task | 所属工作包 |
| 来源数据仍独立鉴权 | 独立 Task | 创建者及明确参与者 |
### 受限范围的负责人规则
项目负责人是否始终能够读取受限包正文尚需单独确定。本版不以“负责人”身份隐式绕过受限范围。实现可选择显式授权或受控接管，但必须记录依据和审计。若内容连项目负责人也必须隔离，优先建立独立项目或独立受限范围，明确内容所有者、交接和恢复机制。
### 迁移与引用
项目跨空间引用不改变权限。工作包或 Task 跨项目迁移可能改变继承来源，必须预览新旧访问范围并确认；不能把空间引用规则直接套用于跨项目数据迁移。涉及不同组织归属的迁移不纳入本版默认操作。
# 5 Agent 的身份与能力授权
每个可参与协作的 Agent 都有独立稳定身份。Agent 属于哪个组织、由谁管理、可被谁调用、可以读取哪些数据及使用哪些工具，必须可查询。组织人员或供应商的人获准参与，不自动使其所有 Agent 获准参与。
“使用权限”若只是“可以启动 Agent”的另一种说法，应合并为“可发起运行”，避免两个同义开关。Agent 管理、调用、数据访问、工具执行和输出接收应分别表达。
| 要回答的问题 | 授权维度 | 示例 |
| --- | --- | --- |
| 谁能看见名称和用途 | 发现 | 仅财务组可发现成本 Agent |
| 谁能派任务或发起 Run | 调用 | 项目负责人可启动研究 Agent |
| Agent 能读哪些对象与版本 | 数据 | 指定客户访谈与批准资料库 |
| 能用什么工具做哪些动作 | 执行 | 可写草稿 不可外发邮件 |
| 结果可交给哪些接收者 | 输出 | 利润明细仅财务授权人 |
| 谁能改提示 工具 数据范围 | 配置 | 调用者不得默认修改配置 |
### 凭据使用与读取分离
Agent 获准通过某连接执行操作，不等于可以读取或展示密钥。凭据由受控执行环境使用，日志、错误、提示和模型输出不得泄露秘密。修改连接及扩大持久访问需要独立治理流程。
### 权限包简化操作
前端可提供研究员、交付协作者和财务分析等模板，但模板最终映射为明确动作及范围。模板升级不得静默扩大已部署 Agent 的权限，应展示差异并由有权者确认。
# 6 每次 Run 的委托与输出控制
默认运行模式为代表调用者执行。一次 Run 的有效权限同时受组织政策、调用者可委托权限、Agent 已授权上限、本次任务的数据与行动范围、工具要求、期限、额度和审批状态限制。任何必需条件不满足即拒绝，明确拒绝优先。
运行开始时记录调用者、Agent、目的、资源范围、允许动作、接收者、有效期和预算。运行期间读取新资料、调用工具、外发和提交结果时重新鉴权；不能只在启动时检查一次。队列任务和长时间运行也不能保留被撤销的访问能力。
Agent A 调用 Agent B 时传递当前任务委托边界。B 的较高权限不能自动扩展 A 的任务权限。审批绑定具体动作、对象、参数、接收者与有效期；关键条件变化后不能复用旧审批。
沿用 DC-02 和 DC-06：每次运行须明确输入数据范围，并固定本次 Run 的来源版本集合。固定版本用于复现，不代表保留已撤销的访问权；当前授权变化仍约束后续读取和交付。
### 受控代读保持现有 DC 07
现行 DC-07 已允许狭窄范围的授权 Agent 代读，并向无源资料读取权的接收者提供经许可的限定输出。本版保留该路径，不能简单把所有运行都写成调用者与 Agent 原始读取权的机械交集。该例外必须来自有权主体的明确授权，并限定来源范围、任务目的、输出类型、接收者和有效期。
### 代读不能变成自由查询入口
代读结果仅开放被授权的输出，不能返回未批准的原文、隐藏上下文、运行日志或其他敏感信息。应校验输出内容及接收权限，记录授权与实际交付证据。若无法可靠限制输出，应拒绝交付或转人工审核。
### 与未来服务型 Agent 区分
面向任意调用者、能够查询广泛敏感数据的通用高权限服务不属于第一版默认能力。未来需要固定接口、输入输出契约、独立服务身份及专项测试。已有 DC-07 的受控代读并不因此推迟。
# 7 跨组织委外与权限生命周期
跨组织合作采用单一归属、显式共享。咨询项目与委外工作包仍归属发起组织；供应商通过稳定外部身份进入授权范围，不必复制为内部员工，也不把项目同时归属于多个组织。
外部参与者在“与我共享”看到入口。其只能访问明确共享的工作包任务、资料、讨论和交付物，不能浏览上级项目全文、其他工作包、组织成员目录或内部报价。供应商组织管理员也不能因员工参与而读取发起方内容。
### 邀请与生效
有邀请权限的人选择身份、工作包、角色、共享资料与到期时间；系统预览范围并检查组织政策。受邀人接受且授权生效后才能访问。沿用现有外部邀请五态：待接受、已接受、已拒绝、已取消、已失效；资源授权撤销另行记录，不混同邀请状态。接受联系人或加入外协群并不自动授予项目资料权。
### 执行与转授权
外部成员默认不能继续转邀他人。若确需供应商负责人维护名单，只授予该工作包内的受限管理权并限制可授角色。外部 Agent 必须独立审核其身份、调用关系和数据工具范围。
### 撤权与退出
项目移除、组成员退出、账号禁用、合作到期或邀请撤销后，重新校验直接和继承授权。管理界面须显示残留授权来源；可按业务需要一并撤销，而不是只删除一个入口。组织禁用身份不能保留其在该组织下的隐蔽访问通道。
### 回收的实际边界
撤权覆盖服务端读取、附件下载、搜索索引结果、通知正文、缓存和 Agent 后续步骤。采用短期链接并在下载时检查可回收资源。已下载到对方设备的资料无法靠权限回收，应在外发前限制范围并提示风险。 既有 FRM-013 要求撤权后服务端拒绝新的读取；前端推送失败时以不超过 30 秒的回退机制刷新。该要求需通过实测证明，不能将前端刷新窗口解释为服务端继续放行窗口。
