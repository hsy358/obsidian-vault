## 域 1｜全栈工程能力（前端 + 后端 + 接口 + 联调）

### ① 这技能到底是什么
"全栈"在这家公司不是"什么都写一点"，是 **能独立把一个功能从需求做到上线**：
- **前端**：Vue3 / React 之一 + 组件库 + 图表（ECharts / AntV / D3）+ 表格大数据量渲染 + 地图（这块他们可能用 Leaflet / Cesium / OpenLayers）
- **后端**：Java（Spring Boot / Spring Cloud）+ RESTful API + 鉴权 + 事务 + 定时任务 + 文件/对象存储
- **接口**：契约设计（OpenAPI）、版本兼容、错误码、分页、大字段流式返回
- **联调**：Mock、契约测试、日志追踪、灰度
- **数据库**：PostgreSQL（他们历史岗位是 Java + GIS，大概率 PostgreSQL/PostGIS）+ Redis

### ② 面试官会怎么考
- "讲一个你独立负责的完整功能，从需求到上线"
- "前端你用什么框架？为什么选它？"
- "接口设计你怎么做版本管理？"
- "前后端联调出过你负责的坑吗？"
- **本厂特有**：他们有 GIS 背景 → 可能问 **"地图上百万级点位怎么渲染？矢量数据还是栅格？"**、**"遥感影像切片怎么加载？"**

### ③ 你手里的武器
- **guyu 知识库与 Agent 平台**：Vue3 前端 + Spring Cloud Java Gateway + knowledge/im-platform/serv-web 三服务 + PostgreSQL + Redis + MQ —— **这就是一条完整的 AI 应用全栈**，而且是**企业级**的
- **岗位要求3 原文"可独立完成 AI 应用全栈搭建与迭代"** → 直接用这条话引用
- 10 年 Java 后端 + 4 个端到端项目

### ④ 危险区
- ⚠️ 不要吹前端。诚实口径："近 5 年主责架构与交付，前端以 Vue3 做过完整业务页与联调，能独立完成常规页面，但我不自封前端专家。差异化在后端 + AI 链路 + 交付治理。"
- ⚠️ 别一上来就讲架构师视角，他们要的是"能写"。

## 域 2｜大模型应用开发（**最核心、你的最强项**）

### ① 这技能到底是什么
不是"会调 API"，是**把大模型变成一个可靠的系统**。完整链路：

```
需求 → 场景定义(Agent 还是 RAG？) → 数据/知识治理 → 切分与索引 → 召回 → 重排
     → Prompt 组装(含上下文与工具) → 模型调用(流式/并发/重试) → 工具执行
     → 结果校验(幻觉/引用/格式) → 效果评测 → 上线 → 监控与成本治理 → 反馈闭环
```

具体技术点：
- **RAG**：文本切分（语义/结构/父子块）、QA 抽取、Embedding 选型与微调、向量库（Qdrant/Milvus/pgvector）、**混合检索（BM25 + 向量）**、Rerank（bge-reranker / Cohere）、Query 改写、多路召回与融合、**引用溯源**
- **Agent**：LangChain / LangGraph 状态机、Tool Calling / Function Calling、多 Agent 协作、ReAct / Plan-Execute、**记忆（短期/长期/工作区）**、上下文压缩、Checkpoint、Human-in-the-loop
- **Prompt 工程**：版本化、模板化、A/B、Few-shot、**结构化输出约束**、失败回退
- **推理与成本**：模型选型（能力/价差）、Token 预算、缓存（prompt cache）、并发与限流、降级策略
- **可观测**：调用链 Trace、Token 消耗、延迟、失败分类

### ② 面试官会怎么考（这家的考法偏"业务+落地"）
- "知识库问答效果不好，你怎么定位？"
- "你怎么减少幻觉？"
- "大模型成本怎么控？"
- "为什么用 Agent 而不是纯 RAG？"
- "你的知识库切分策略是什么？"
- "线上效果怎么衡量、怎么持续优化？"

### ③ 你手里的武器（**这是你的主牌，务必打成主牌**）
- **guyu 生产实战**：LangChain 0.2.0 + LangGraph 状态机、m3e-base Embedding（768 维，sentence-transformers 2.2.2）、Qdrant 1.10.1 主 + Milvus 2.2.8 备双写、**混合检索（BM25 + 向量）+ Rerank**、多 Agent + 工具注册 + Trace、Prompt 版本化 + A/B + 失败回退
- **落地数字**：知识查询 30 分钟 → 5 分钟内；**AI 自主解答率 76%**；人工坐席负载 -40%；智能体配置平台需求响应效率 +30%（集团多 BU 推广）
- **踩过的坑（讲坑比讲成功更显专业）**：
  - Embedding 服务 hardcode `cuda:0` → 无 GPU 节点崩溃（**讲这个：生产环境的资源假设问题**）
  - LangChain 0.1 → 0.2 的 API 变更、Pydantic v1 → v2 的 schema 迁移（**讲这个：依赖升级的破坏性变更管理**）
  - OpenAI 协议多模型切换、Prompt 注入防御、Token 预算控制

### ④ 危险区
- ⚠️ 别只讲"用了什么框架"。**必须讲"为什么这么选"和"效果怎么量出来"**。
- ⚠️ 数字要能扛住追问：76% 的自主解答率是**怎么定义的**（分母是什么）？先想好口径。

## 域 3｜AIGC 工程化落地（JD 明确点名，容易被当成"你懂工程化吗"来考）

### ① 这技能到底是什么
**AIGC 工程化 = 从"能演示"到"能上线运营"的全部工程动作**。业内常说 AIGC 项目死在这四步：
1. **Demo 能跑，生产不work**（并发、超时、限流、熔断、失败重试、脏输入）
2. **效果不可控**（没有评测集、没有回归、prompt 一改全崩）
3. **成本不可控**（Token 黑洞、无缓存、无分级路由）
4. **数据不闭环**（用户反馈收不回来、badcase 不沉淀）

工程化要补的东西：
- **评测体系**：离线评测集（黄金集）+ 自动指标（准确率/召回率/格式合规率/拒答率）+ 线上指标（采纳率/转人工率/满意度）+ **回归测试**（prompt 或模型变更必跑）
- **灰度与回滚**：影子模式 → 小流量 → 全量；版本化 prompt/模型配置；一键回退
- **成本治理**：分级路由（简单问题走小模型/规则）、缓存、Token 预算与截断、批处理、离峰
- **安全**：Prompt 注入、越权、敏感信息脱敏、输出过滤、**审计日志**（谁在什么时候用什么数据问了什么、模型答了什么）
- **可观测**：Trace、Token/延迟/失败率看板、告警

### ② 面试官会怎么考
- "你怎么保证 AI 功能上线后效果稳定？"
- "Prompt 改了怎么知道有没有变差？"
- "大模型接口挂了怎么办？"
- "怎么防止用户在输入里套指令骗你的系统？"
- "AI 功能怎么算 ROI / 怎么证明值？"

### ③ 你手里的武器
- ⭐ **AI Coding / SDD / 质量门禁** —— **这就是工程化的最强表达**
- **guyu 效果数字**（30min→5min、76%、-40%、+30%）= ROI 的证据
- **Multi-Agent + Trace** = 可观测
- **Prompt 版本化 + A/B + 失败回退** = 灰度与回归
- **注入防御 + Token 预算控制** = 安全与成本
- **DSH / super-agent 的研究沉淀**（我们 11 月做的调研）→ **若对方追问"你怎么保证团队规范"，可以说"我们内部用 SDD 把先写规格再写代码做成流程"**

### ④ 危险区
- ⚠️ 别把"工程化"说成"部署上线"。**工程化 = 效果可度量 + 变更可回归 + 成本可控 + 风险可审计**。给这四个关键词。
- ⚠️ **对方是 20-99 人的公司，很可能没有这些**。所以讲的时候用"**我来补这块**"的口气，而不是"我们公司都这样"——否则显得不接地气。

## 域 4｜数据湖 / 数仓 / 大数据服务基础架构（**你唯一的软肋，但原文门槛不高**）

### ① 这技能到底是什么（**必须先搞懂这三个词的区别**）

| 概念 | 一句话 | 关键技术 |
|---|---|---|
| **数据湖 Data Lake** | **存**：原始数据按原样存放，不预先定结构 | 对象存储（HDFS / S3 / MinIO / OSS）、Parquet/ORC、分区（按日期/地区）、**数据湖仓（Delta / Iceberg / Hudi）**做表级事务与版本 |
| **数仓 Data Warehouse** | **用**：清洗、建模、按主题聚合的结构化数据，服务分析 | Hive / Spark SQL / Doris / ClickHouse；**维度建模（事实表 + 维度表）**、**ODS/DWD/DWS/ADS 分层**、拉链表 |
| **数据服务/数据中台** | **供**：把数据变成接口/指标/标签，供上层应用调用 | 数据 API、指标平台、主数据管理（MDM）、元数据 + 血缘、数据质量规则、数据权限 |
| **ETL/调度** | 怎么搬 | DataX / SeaTunnel / Flink CDC / DataXHub + DolphinScheduler / Airflow |

**必须记住的一条主线**：**湖 → 仓 → 服务 → 应用**，四层各解决一个问题：
- 湖解决"**存得下、多源不丢**"（原始影像、传感器、气象）
- 仓解决"**算得清、口径统一**"（清洗、去噪、聚合、建模）
- 服务解决"**供得快、权限清**"（API、指标、权限、血缘）
- 应用解决"**用得好、能决策**"（慧种田的种植决策、农资推荐、AI 问答）

### ② 这家公司的特殊性（**这是你和其他候选人不一样的地方**）
数溪做的是 **时空/农业数据**，所以它的"数据湖/数仓"长这样：
- **数据源**：无人机航拍影像（RGB / 多光谱 / 高光谱）、土壤与气象传感器、物联网田间数据、遥感卫星影像、农户/合作社业务数据
- **数据特征**：**时空性**（每个观测带时间戳 + 地理坐标）、**栅格 vs 矢量混合**、**样本极度稀疏且标注昂贵**、**多源尺度不一致**、**季节性强**
- **技术栈推测（待确认，别当成事实说）**：PostgreSQL + **PostGIS**（矢量 + 空间索引 GiST）、**GeoServer**（空间服务）、**GDAL/rasterio**（栅格处理）、**GeoTiff**、**ECharts/Mapbox/Cesium**（前端可视化）、**Python（rasterio/GeoPandas/xarray/ Prophet）**做时序预测、深度学习做作物/病虫害识别
- **时空数据湖的天然适配** ⚠️ **这里有一个能直接震撼面试官的点**：
  > **何大人在 vault 里已经有《Cordis 时空可组合性编程范式》（arXiv 2608.25512），而 DeepSeek Harness 底层正是 Cordis。** 这说明"时空数据 + 时空编程"在国际一线已经是正式研究命题（时空可组合性 = spatiotemporal composability）。**你可以以此说明"时空数据系统不是小众，是有理论基础的"** —— 但要谨慎，作为"延伸阅读/行业趋势"提，不要当核心论据。

### ③ 面试官会怎么考
- "数据湖和数仓有什么区别？"（**必问**）
- "我们数据源这么杂，你会怎么设计分层？"
- "数据质量怎么保证？脏数据、缺失、传感器漂移怎么办？"
- "怎么保证口径统一？"
- "数据权限怎么做？"
- **这家特有**："遥感影像和传感器时序数据怎么一起分析？""样本很少怎么训模型？"

### ④ 你手里的武器 + 诚实边界
- ✅ **有**：集团数据中台与数据治理项目（2021.03–2023.12，**39 人团队**）—— 讲**数据治理、口径统一、数据服务化、对外供数**；智慧城市惠企平台的数据服务（面向政务/企业客户）
- ✅ **有**：金融场景的"数据→决策"链路（徽商银行财富智能推荐 = 特征数据 → 模型 → 业务决策 + 效果指标）→ **正好可以平移到"用数据做种植决策"**
- ⚠️ **边界**：底层的 Hadoop/Spark/Flink/Hive 引擎选型与运维，他不是一线 → **用"数据服务的应用侧和治理侧"口径**（见下）
- ❌ **不要**硬装大数据内核专家

### ⑤ 数据类项目的 5 大常见技术卡点（**背下来，这是他们最想听的**）
1. **口径不一致** —— 同一指标不同报表对不上 → 治理 + 指标字典 + 血缘
2. **数据质量** —— 缺失/重复/异常值/传感器漂移/设备离线 → 质量规则 + 稽核 + 血缘追踪
3. **时效与调度** —— 批 + 流混杂、依赖断裂、延迟 → 调度编排 + 幂等 + 重跑
4. **存储与成本** —— 原始影像/高频时序爆盘 → 分区 + 冷热分层 + 生命周期 + 对象存储 + 压缩
5. **权限与安全** —— 政企客户的硬要求 → 行级/列级权限 + 脱敏 + 审计 + 血缘到字段级

### ⑥ 数据湖/数仓的标准答法（可直接念）
> 我在集团数据中台与数据治理项目里负责的是**数据服务的应用侧和治理侧**：数据从底层平台出来，经过清洗、治理和口径统一，供给上层业务应用，包括后来的智慧城市惠企平台和徽商银行的财富智能推荐。
>
> **我最擅长的是"数据怎么变成业务能力"这一段**——比如惠企平台里，企业画像、政策匹配、审批加速，背后都是数据口径统一之后才能提供的服务。底层引擎的选型和运维不是我的最强项，那是我想补的部分。
>
> 我理解贵司这边是**时空数据**，跟一般业务数据比，难点会多一层：每个观测都带时间和空间坐标，数据源又是栅格、矢量、传感器、影像混杂，样本稀疏且标注昂贵。所以我的判断是——**湖这一层要解决"多源原样存下来"，仓这一层要解决"统一时空基准和口径"，服务层要把指标和图层服务化给应用**，最后 AI 是在这之上做分析与决策。这一层设计不清楚，后面模型再准也没法用。

## 域 5｜智能化分析 / 数据治理 / 智能监控（职责 2 三个关键词）

### ① 分别是什么
- **智能化分析**：让 AI/模型在数据之上产出**可执行结论**（不是展示报表）
  - 对数溪：长势评估、灾害预警（病虫害/干旱/涝渍）、产量预测、投入品（种/肥/药/水）优化建议
- **数据治理**：元数据、血缘、质量规则、主数据、指标管理、口径统一、权限
- **智能监控**：对**系统**和**数据**本身的监控（区别于业务分析）
  - 系统：接口成功率、延迟、任务堆积、GPU/资源水位
  - 数据：数据新鲜度、波动率突变（传感器异常）、分布漂移、缺失率告警
  - **模型/AI：效果漂移（回答采纳率下降）、成本突增、失败率上升**

### ② 面试官会怎么考
- "慧种田里你觉得 AI 最该先做哪一块？"
- "数据监控和业务监控有什么区别？"
- "如果传感器某天全部上报 0 值，你怎么发现？"

### ③ 你的武器
- **数据治理** → 39 人数据中台项目
- **智能化分析** → 徽商银行财富智能推荐（数据 → 决策 → 效果指标：销售额 +30%、满意度 92%）；guyu 智能问答（76% 自主解答）
- **智能监控** → ⚠️ 这块他其实**有底子但没包装过**：Agent 调用链 Trace、Token 消耗、延迟、失败分类、Prompt 注入防御、Token 预算控制 —— **翻译成对方语言就是"AI 效果监控"**
  > 话术："我们平台里有 AI 调用链的 Trace、Token 消耗、延迟、失败分类和预算告警。翻译成你们场景，就是**模型效果监控**——不只是机器监控，还有回答采纳率、人工转接率这类效果指标的看板。"

### ④ 危险区
- ⚠️ 不要空谈"AI 赋能农业"——**给一个具体的**：比如"传感器数据缺失时，先用邻近站点 + 遥感插值补齐，再进模型；模型输出给建议时必须带置信度和依据（哪个地块、哪个时段的哪个指标异常），否则农户不会信"。

## 域 6｜需求评审 / 技术方案 / 进度跟进 / 问题排查（**你的天然优势，但要点在于"翻译"**）

### ① 这技能是什么

# 第五部分：技术高频题（30 题，逐个给要点）

## A. RAG / 检索（8 题）
1. **RAG 和微调怎么选？** → 知识频繁变/需溯源/合规 → RAG；固定风格/格式/推理能力 → 微调；**生产上常常是 RAG + 少量微调/提示工程组合**
2. **切分粒度怎么定？** → 看问答对的内容结构（FAQ 一问一答 → 整块；长文档 → 父子块 + 标题路径）；**切分错，上限就低**
3. **混合检索为什么优于纯向量？** → 专有名词/编号/人名/产品型号靠关键词；语义相近靠向量；两者失效模式不同 → 互补
4. **Rerank 放哪一步？** → 召回后、精排（粗排 Top-100 → 精排 Top-5）；**换来延迟成本**
5. **怎么控幻觉？** → 检索覆盖 + 引用约束 + 生成后校验 + **无答案拒答** + 评测集回归
6. **多轮对话怎么处理上下文？** → 改写 Query + 历史摘要 + 实体指代消解；**别把全历史塞进 Prompt**
7. **知识库怎么更新/失效？** → 文档版本 + 生效时间 + 索引增量更新 + **检索时过滤时效**
8. **向量库怎么选？** → Qdrant/Milvus/pgvector/ES；过滤能力、规模、运维成本、是否已有 PG 团队

## B. Agent / 编排（8 题）
9. **什么时候用 Agent，什么时候纯 RAG？** → 流程确定 → 工作流（RAG+规则）；需要多步决策、工具调用、自主规划 → Agent；**能用工作流解决的别上 Agent**（成本与稳定性）
10. **Tool Calling 怎么设计？** → 参数 schema 严格化（类型/枚举/必填）、错误可读、幂等、超时与重试、**危险操作要人工确认**
11. **Agent 陷入死循环怎么办？** → **最大步数/最大 token 预算熔断** + 循环检测 + 超时 + 兜底转人工；**这条他们一定会问，因为"独立完成全栈"意味着 Agent 要能自己收尾**
12. **多 Agent 什么时候值得？** → 需要不同上下文/权限/专长；**不是拆得越多越好**
13. **Agent 的状态怎么存？** → 会话状态 + 外部存储 + 检查点（Checkpoint）+ 失败可恢复
14. **怎么让 Agent 干活可观测？** → Trace（每步输入输出耗时 token）+ 失败分类 + 成本看板 + 告警
15. **Agent 出错怎么定位？** → 先分清是"检索没召回"还是"模型没照做"还是"工具执行失败"——**三段式归因**
16. **Prompt 注入怎么防？** → 外部文本当数据不当指令、字段白名单、输出校验、权限隔离、审计

## C. AIGC 工程化（6 题）
17. **效果怎么保证不退化？** → 黄金评测集 + 每次 prompt/模型变更跑回归 + 分层指标（检索层 / 生成层 / 端到端）
18. **Prompt 怎么管理？** → 版本化仓库 + 变更评审 + 灰度 + A/B + 可回滚 + 跟代码一起进 CI
19. **成本怎么降？** → 缓存（prompt cache / 结果缓存）、分级路由、小模型优先、Token 预算与截断、批处理、减少无效重试
20. **模型选型？** → 能力-价差-延迟-上下文-合规；**把 70% 流量路由到便宜模型 + 复杂问题升级**
21. **上线怎么灰度？** → 影子流量 → 1% → 10% → 全量；每级有回滚条件和自动告警
22. **模型输出不稳定怎么兜底？** → 结构化输出约束 + 校验层 + 失败重试（换 prompt 不换模型）+ 降级到规则/人工

## D. 数据 / 数仓（5 题）
23. **数据湖和数仓区别？** → 存 vs 用；Schema-on-Read vs Write；**湖是原料，仓是菜**
24. **ODS/DWD/DWS/ADS 怎么分？** → 贴源 / 明细清洗 / 轻量汇总主题 / 应用指标层
25. **维度建模怎么做？** → 事实表 + 维度表；一致性维度；避免过度建模
26. **数据质量怎么保证？** → 质量规则（完整性/唯一性/有效性/一致性/及时性）+ 稽核 + 血缘 + 监控告警 + 责任到人
27. **数据权限怎么做？** → 库/表/行/列级 + 角色 + 脱敏 + 审计日志 + **字段级血缘**（政企必需）

## E. 时空数据 / 行业（3 题）
28. **栅格 vs 矢量？** → 栅格=影像/热力（像元）；矢量=点线面（要素）；**遥感影像、多光谱是栅格；地块边界是矢量**
29. **多光谱/NDVI 是什么？** → 多波段反射率；NDVI=(NIR-R)/(NIR+R) 反映植被活力；**这是长势分析最基础的指标**
30. **样本稀疏怎么训模型？** → 迁移学习/预训练模型 + 少量标注 + 物理/农学规则约束 + 时序平滑 + 不确定性量化（给置信度）

## F. 通用软技能（2 题，价值观）
31. **你最大的技术短板是什么？** → **诚实版**：数据底层引擎（Spark/Hive 的一线调优）不是我的主场，我做过的是数据的服务侧和治理侧；我能在短期内接上，因为治理和服务的逻辑是相通的。
32. **你为什么想加入？** → 不说"平台好/想学习"，说：**"我想看 AI 在一个真实行业里从数据底座一路走到田间决策——这件事只有早期公司做得了，而我最擅长把一件没人做过的事从需求推到上线，还顺手把规范留下来。"**

# 第六部分：3 道大场景题（**这类公司最爱问**）

### 场景 1｜"慧种田要做一个『病虫害预警』功能，你怎么落地？"
**答题结构（8 步，按这个顺序讲）**：
1. **先问清业务问题**（不猜）：预警给谁看？农户？农技员？决策依据是什么（虫情测报灯/孢子捕捉/无人机影像/气象）？误报成本多高？漏报代价多大？
2. **数据盘点**：多源（遥感时序、气象、土壤、设备、人工上报）→ 时空对齐 → **建"地块×时间"的宽表/时空立方体**
3. **数据质量关**：传感器漂移、缺测、影像云遮、标注稀缺 → 质量规则 + 插值 + 置信度字段
4. **模型选型**：样本少 → 先规则/专家模型 + 阈值（可解释）→ 积累标注后再上学习模型；**不要一上来就深度学习**
5. **效果指标**：提前期（提前几天）、召回/误报、农户采纳率 —— **必须有评测集**
6. **工程化**：批量跑 + 调度 + 告警 + 效果漂移监控 + 成本可控（先小模型）
7. **人机分工**：**预警是建议，不是指令**；农技员复核 + 农户反馈 → 回流标注
8. **沉淀**：预警规则和误报案例入库，成为下次的评测集与标准

### 场景 2｜"客户投诉：系统里的统计数和报表对不上，怎么查？"
**答题结构**：
1. **先复现 + 定范围**（哪个指标、哪个时间窗、哪个租户/区域、影响面）
2. **血缘追踪**：从报表 → 指标定义 → SQL/任务 → 上游表 → 源数据，**看是哪一段开始不一致**
3. **三类根因**：① 口径/逻辑变更（有人改了 SQL 或配置）② 数据处理（重复、丢失、时区、精度、join 炸裂）③ 缓存/延迟（物化视图未刷新、离线任务没跑完、缓存过期）
4. **止血**：先对齐对外口径 + 标注数据异常区间 + 给受影响的决策提供替代口径
5. **修复 + 防复发**：补数据 + 修逻辑 + **加数据质量稽核规则 + 指标变更评审流程 + 告警**
6. **沉淀**：这个案例 → 指标字典 + 变更规范（呼应"规范开发标准"）

### 场景 3｜"给你 2 周，做一个 AI 问答 Demo 支撑老板汇报，怎么做？"
**答题结构**（**面试官要的是"取舍"和"验收"**）：
1. **先界定范围**：选 1 个高频问题域，不要做全域问答（**明确说不做什么，是加分项**）
2. **数据**：挑 3–5 个高质量文档源；做不了全量治理就**先做人工精选 + 标注**
3. **技术**：先用 RAG + 混合检索跑通（不上 Agent）；评估集用 30–50 个真实问题手工标
4. **可观测 + 兜底**：每条回答带引用；无答案拒答；给一个"人工兜底"入口
5. **验收标准先写死**：准确率/召回率/格式合规率/引用正确率 + "老板会问的 10 个问题"全部要过 → **这就是 SDD 的验收标准思维**
6. **交付形态**：能演示 + 有评测报告 + 有 badcase 清单 + 有下一步路线图
7. **一句话收尾**：**"Demo 结束不是结束，而是把评测集和规范留下来，下一期从这套评测集继续。"**

# 第八部分：反问 + 谈薪（**顺序很重要**）

## 8.1 反问 8 条（按顺序问，别一次全甩）
1. **"慧种田当前最痛的 AI 场景是什么？"**（**第一个问，最能显示内行**）
2. 团队技术栈？前端/后端/数据/GIS/算法各几人？这个岗位向谁汇报？
3. AI 相关的数据基础是已有数仓/平台，还是要**从原始影像和传感器数据开始建**？
4. 遥感/时空数据这块目前是谁负责？我进来主要补哪一段？
5. 主要客户结构与合同周期？回款节奏？（**天使轮公司必问**）
6. 2025 年并购后业务怎么整合？现在产品线怎么分？
7. "沉淀经验、规范开发标准"目前有人负责吗？还是这块希望我来做？**（**直击他的反杀点，看公司认不认这个需求**）
8. 这个岗位是新增还是替补？未来 1–2 年希望他长成什么样？

## 8.2 谈薪（**脚本，注意顺序**）
- **让他先报价**。若被追问期望："我看了贵司的定位和这个岗位的职责，我更看重能不能主导一条完整链路。**如果团队需要的是能独立扛全栈的技术一号位，我的期望区间在 X–Y**。"（把话术落在"角色"上，而不是"人"上）
- **锚点建议**：以"技术负责人/架构"定位谈，**不要以"高级开发"定位**。南京天使轮 20–99 人的 AI 全栈岗常见 15K–30K；按他的资历与职责广度，**合理诉求 25K–35K 或等价职级/股权/项目奖金**。
- **保底判定**：**< 25K 且无架构/规范/带人空间 → 放弃**（不对应他的方向）；≥ 25K + 技术负责人职级 → 认真考虑；≥ 35K → 优先级上调。
- **别接受的条款**：无社保基数、无年终、把"加班强度"当文化。**要求 5 写了"抗压性强"**，务必问清楚加班与农时节点的实际强度。
