## 一、核心技能点深度讲解（11 个）

### 1.1 Embedding 模型选型与工程化

#### 是什么
把文本转成高维向量（guyu 用 **m3e-base 768 维**），让语义可计算（cosine 相似度）。

#### 为什么需要
LLM 只能处理有限上下文，不能"读完所有文档再回答"。Embedding 把全量知识压缩成可检索的向量空间。

#### guyu 怎么实现
```python
# /root/workspace/guyu/guyu_python/zhishiku/controllers/embedding_server.py
device = torch.device('cuda:0')  # ⚠️ 硬编码 GPU

dep_mode = os.getenv("deployment")
model_url = ''
if 'stg' == dep_mode:
    model_url = '/data/container/model/m3e-base'
elif 'prd' == dep_mode:
    model_url = '/opt/model/model/m3e-base'
else:
    model_url = 'D://Share/models/models/m3e-base'

model = SentenceTransformer(model_url, device=device)

@embedding_app.route('/guyu-python/embedding', methods=['get', 'post'])
def embedding():
    content = data["content"]  # 接受字符串或列表
    if isinstance(content, list):
        embedding = model.encode(content, normalize_embeddings=True)  # L2 归一化
    else:
        embedding = model.encode([content], normalize_embeddings=True)
    return jsonify({"status": "ok", "result": json.dumps(embedding.tolist())})
```

**3 个关键设计**：
1. **环境变量切换部署模式**：stg/prd/本地开发三种路径，避免改代码
2. **`normalize_embeddings=True`**：向量 L2 归一化后，cosine 相似度 = 内积，省计算
3. **Flask Blueprint 暴露 HTTP 接口**：调用方用 HTTP 调用，不绑死 Python 进程

#### 面试官可能问

**Q1：为什么选 m3e-base 而不是 BGE / OpenAI？**
- m3e-base 是 Moka 出品的中英双语模型，**768 维**，对中文场景友好
- 缺点：不是 SOTA，2024 年起 BGE-large-zh / BGE-M3 更强
- 选型原则：**文档语言 + 维度 + 部署成本 + 召回准确率**

**Q2：硬编码 `cuda:0` 有什么坑？怎么解决？**
- 坑：无 GPU 节点 → `RuntimeError: No CUDA GPUs are available`
- 解法：三级降级 `cuda → cpu → remote API`
- 永久规则：**所有 LLM 推理都要 try/catch + 降级路径 + 监控**

**Q3：Embedding 模型怎么评估好坏？**
- 准备 100-500 个 query + ground truth 文档
- 计算 Recall@K（召回率）、MRR（平均倒数排名）
- 跨模型 A/B：m3e-base vs BGE-M3 看召回差距

#### 你怎么回答（推荐话术）
> 我们选 m3e-base 主要看中三点：① 中英双语 768 维，对平安中英混合文档友好；② 自托管部署可控（平安合规要求）；③ 768 维比 1024 维省 30% 显存。
> 
> 后续如果文档变长（>2K）或多语言比例提升，我会评估 **BGE-M3**（1024 维 + 长文本 8K + 多语言）。
> 
> 实战教训：早期硬编码 `cuda:0` 导致 stg 环境（无 GPU）崩溃，后来改成三级降级。

### 1.2 RAG 完整流水线

#### 是什么
**Retrieval-Augmented Generation**——用检索到的相关文档增强 LLM 生成，避免幻觉。

#### 完整流水线
```
Documents → Document Loader → Text Splitter → Chunks 
        → Embedding Model → Vectors → Vector Store 
        → Retriever (BM25 + 向量) → Top K Documents 
        → Reranker → Top N Documents 
        → Prompt 组装 → LLM → Answer + 引用
```

#### guyu 怎么实现

```python
# /root/workspace/guyu/guyu_python/zhishiku/flow/base.py 第 437-510 行

    # ...

    limit = 5        # 单个知识库无相似度召回最大数量
    strategy = 1     # 搜索策略：1=语义 2=混合 3=文本
    
    if 'args' in knowledgeInfo:
        if 'strategy' in knowledgeInfo['args']:
            strategy = knowledgeInfo['args']['strategy']
        if 'minScore' in knowledgeInfo['args']:
            score = 1 - knowledgeInfo['args']['minScore']
        if 'topK' in knowledgeInfo['args']:
            topK = knowledgeInfo['args']['topK']
    
    for knid in knowledgeId:  # 可能多个知识库
        kg_params = {"knowledge_id": knid, "content": Query, ...}
        if strategy == "1":     # 语义
            docs.extend(serarch_milvus(kg_params))
        elif strategy == "2":   # 混合：milvus + ES
            docs.extend(serarch_milvus(kg_params))
            docs.extend(serarch_es(kg_params))
        elif strategy == "3":   # 纯文本：ES
            docs.extend(serarch_es(kg_params))
    
    # 后置 Rerank
    rk_params = {"content": Query, "docs": docs, "topK": topK}
    docs = rank(rk_params)  # bge-reranker-large 重排
```

**3 个关键设计**：
1. **3 种搜索策略**：纯语义（milvus）/ 混合（milvus + ES）/ 纯文本（ES）—— 按业务场景选择
2. **`minScore` 反向转换**：用户配置 0-1 的相似度阈值，内部转成 L2 距离阈值 `score = 1 - minScore`
3. **多知识库融合 + 全局 Rerank**：不是每个知识库独立 topK，而是合并后统一 Rerank

#### 面试官可能问

**Q4：RAG 召回率低怎么优化？**
- **切分优化**：调 `chunk_size`（256/512/1024），加 `chunk_overlap`（10-20%）
- **混合检索**：纯向量召回 + BM25 关键词检索融合
- **QA 对抽取**：长文档先抽 QA 对再入库
- **父子切分**：父块检索 + 子块上下文填充
- **Embedding 微调**：用业务 query 微调 Embedding 模型
- **HyDE**：用 LLM 生成假设答案再检索

**Q5：怎么评估 RAG 系统？**
- **检索指标**：Recall@K / MRR / NDCG
- **答案指标**：答案引用准确率 / LLM-as-judge 评分 / 人工评分
- **端到端指标**：用户满意度 / 答案被采纳率 / 反馈循环

**Q6：chunk_size 怎么选？**
- 短文档（FAQ）：128-256
- 中等文档（手册）：512
- 长文档（论文）：1024 + 父子切分
- **经验**：先用 512 跑 baseline，看 Recall@K 召回率，再调

#### 你怎么回答（推荐话术）
> RAG 召回率优化的核心是"**从单路召回变多路融合**"。我们早期纯 milvus 向量召回，召回率只有 60% 多。后来加 BM25（ES）做混合检索，召回率提到 85%。再叠 bge-reranker-large 做精排，准确率又上一档。
> 
> 关键参数：chunk_size 经验值 512，overlap 10-20%，向量召回 topK=50，Rerank 后 topN=3-5。

### 1.3 向量数据库选型与优化

#### 是什么
存储高维向量、支持近似最近邻（ANN）检索的数据库。

#### 主流对比
| 维度 | Qdrant | Milvus | Pinecone |
|---|---|---|---|
| 部署 | 自托管/云 | 自托管/云 | 仅云 |
| 性能 | 中等 | 高 | 高 |
| 过滤 | 强（payload filter） | 强 | 中 |
| 运维 | 简单 | 复杂（etcd+MinIO） | 零运维 |
| 选型建议 | 中小规模首选 | 大规模生产首选 | 不想运维首选 |

#### guyu 怎么实现（Milvus 集合设计）
```python
# /root/workspace/guyu/guyu_python/zhishiku/milvus/MilvusUtil.py 第 90-130 行
```

**4 个核心设计**：
1. **元数据 + 向量同库存储**：`knowledge_id / file_id / fragment_id / org_id` 等元数据跟向量一起存，支持 `expr` 过滤
2. **多租户隔离**：通过 `org_id` + `expr` 过滤实现按部门/BU 数据隔离
3. **数据来源分类**：`source` 字段区分文章片段 / QA 对 / 数据索引，方便后续按类型调权重
4. **`consistency_level="Strong"`**：强一致性检索（生产场景必须，避免召回已删除数据）

#### guyu 的混合检索实现

```python
# search_hub —— 按 org_id 过滤的向量检索
@staticmethod
def search_hub(milvus_source, host, port, content, limi_score, limit, expr):
    embedding_search = MilvusUtil.create_vector([content])  # 先向量化
    collection = MilvusUtil.get_collection(milvus_source.collection_name)
    collection.load()
    
    results = collection.search(
        data=embedding_search,
        anns_field=milvus_source.vector_field,
        param=milvus_source.search_params,
        limit=limit,
        expr=expr,  # ← 多租户过滤：org_id == 123
        output_fields=milvus_source.output_fields,
        consistency_level="Strong"
    )
    
    for r in results[0]:
        score = round(float(r.distance), 4)
        if score > limi_score:
            continue
        mr = {"id": r.entity.id, "distance": round(1 - score, 2), ...}
        milvus_result.append(mr)
    return milvus_result
```

#### 面试官可能问

**Q7：Milvus 和 Qdrant 怎么选？**
- **Milvus**：亿级向量、高 QPS、接受复杂运维（etcd + MinIO + Pulsar）
- **Qdrant**：百万级向量、运维简单、Rust 写的性能好
- **生产建议**：先 Qdrant 起项目，量上来再迁 Milvus

**Q8：向量数据库怎么保证数据一致性？**
- `consistency_level` 配置：`Strong`（强一致）/ `Bounded`（有界）/ `Session`（会话）/ `Eventually`（最终）
- 生产用 `Strong`，成本是 latency 略高
- 删除要 "先删向量再删元数据"，避免脏读

**Q9：IVF_FLAT 跟 HNSW 怎么选？**
- **IVF_FLAT**：训练 + 倒排索引，量大时查询快，构建慢
- **HNSW**：图索引，查询最快，构建占内存多
- **选择**：亿级用 IVF_PQ / IVF_SQ8 量化；千万级用 HNSW

#### 你怎么回答（推荐话术）
> 我们选 Milvus 主要因为业务量大（亿级向量）+ 平安内部有运维能力。索引用 IVF_FLAT + L2 距离，nlist=768（经验值，跟数据量级匹配）。
> 
> 关键教训：**生产环境必须 `consistency_level="Strong"`**——早期用 Eventually 导致用户看到已删除的文档，投诉后才改成 Strong。

### 1.4 Agent 框架（ReAct / Plan-and-Execute / Multi-Agent）

#### 是什么
让 LLM 不只生成文本，还能**调用工具、观察结果、决定下一步**——从"问答机器"升级成"数字员工"。

#### 4 种模式
1. **ReAct**：思考 + 行动 + 观察循环（适合工具调用）
2. **Plan-and-Execute**：先规划再执行（适合复杂多步任务）
3. **Reflection**：自反思 + 迭代修正（适合生成质量要求高）
4. **Multi-Agent**：多个 Agent 协同（Supervisor / Hierarchical / Collaborative）

#### 面试官可能问

**Q10：ReAct 和 Plan-and-Execute 怎么选？**
- ReAct：每步都观察结果，适合**环境变化快**的场景（Web 浏览、调试工具）
- Plan-and-Execute：一次性规划适合**步骤明确**的场景（数据 ETL、报表生成）
- 选择原则：**不确定性高用 ReAct，确定性高用 Plan-and-Execute**

**Q11：Multi-Agent 怎么协调？**
- **Supervisor 模式**：一个 supervisor agent 分发任务给 worker
- **Hierarchical**：树形层级，每层一个 supervisor
- **Collaborative**：对等 Agent 通信（guyu / SDD 用这种）
- **关键**：Agent 间通信协议要标准化（OpenSpec / 共享 State）

**Q12：Agent 死循环怎么办？**
- 设 `max_iterations`（LangChain 默认 15）
- 工具调用失败 3 次自动终止
- 状态机（LangGraph）的 `recursion_limit`

#### 你怎么回答（推荐话术）
> 我们用 LangChain 的 `create_structured_chat_agent` + AgentExecutor。关键是 `handle_parsing_errors=True`——LLM 输出格式错误的概率不低，不能直接崩。
> 
> Multi-Agent 我们走 Collaborative 路线，4 个 Agent 通过共享 State 通信（LangGraph 的 StateGraph）。**不超过 5 个 Agent**——超过协调成本爆炸。

### 1.5 工作流引擎（LangGraph StateGraph）

#### 是什么
把业务流程定义成**有向图**——节点是动作，边是流转条件。比 Chain 强在：支持循环、分支、人工介入、状态持久化。

#### 核心概念
- **StateGraph**：状态机定义
- **State**：所有节点共享的 TypedDict
- **Node**：执行单元（函数）
- **Edge**：普通边（A → B）
- **Conditional Edge**：条件边（if 满足条件 → B else → C）
- **Checkpointer**：状态持久化（可恢复）

#### guyu 怎么实现（flow/base.py 是核心）
```python
# /root/workspace/guyu/guyu_python/zhishiku/flow/base.py
from langgraph.graph import StateGraph, END
from langgraph.graph.message import add_messages

class FlowState(TypedDict):
    messages: Annotated[list, add_messages]    # 消息列表（自动合并）
    input_exts: Annotated[dict, merge_dict]    # 流程输入（字典合并）
    node_values: Annotated[dict, last_dect]    # 节点输出（最后写入胜出）

def graph_by_builder(data, chat_run_id=None):
    """根据 JSON 配置构建 LangGraph 图"""
    flow_builder = FlowBuilder(data, chat_run_id)
    for node in data['nodes']:
        node_type = node['type']
        if node_type == 'start':    flow_builder.build_start(node)
        elif node_type == 'end':    flow_builder.build_end(node)
        elif node_type == 'model':  flow_builder.build_llm(node)
        elif node_type == 'knowledge': flow_builder.build_knowledge(node)
        elif node_type == 'selector': flow_builder.build_condition(node)
        elif node_type == 'text':   flow_builder.build_text(node)
        elif node_type == 'plugin': flow_builder.build_tool(node)
    
    for edge in data['edges']:
        flow_builder.build_edges(edge['sourceNodeID'], edge['targetNodeID'])
    
    return flow_builder.compile_graph()
```

**7 种节点类型**：
- `start` / `end` — 流程入口出口
- `model` — LLM 节点（支持多模型切换 + JSON 输出模式）
- `knowledge` — 知识库检索（3 种策略）

#### guyu 怎么实现（Token 缓存 + CyberArk）

```python
# /root/workspace/guyu/guyu_python/zhishiku/llm/llmFactory.py 第 110-140 行
class SimpleCache:
    def __init__(self, ttl=1800):  # 30 分钟 TTL
        self.cache = {}
        self.ttl = ttl

    def get(self, key):
        if key in self.cache:
            value, expiry_time = self.cache[key]
            if time.time() < expiry_time:
                return value
            else:
                del self.cache[key]   # 过期清理
        return None

cache = SimpleCache(ttl=1800)  # ← token 缓存

def query_qa(data):
    token = cache.get("token")
    if token:
        logger.info("get token from cache")
    else:
        token = get_token()        # ← 调 CyberArk 拿密码，调用 auth API
        cache.set("token", token)  # ← 缓存 30 分钟
```

- 过期自动清理，避免脏 token

#### SDD 的 ReAct Loop（agent_graph.py 核心）
```python

def run_stage_react_agent(state: ExploreJudgeState) -> ExploreJudgeState:
    """ReAct 循环：每轮 decide → ANSWER_CC/ASK_USER/PASS/FAIL"""
    graph = StateGraph(ExploreJudgeState)
    graph.add_node("decide", stage_react_decide)
    graph.add_node("continue_main", stage_react_continue_main)
    graph.set_entry_point("decide")
    graph.add_conditional_edges("decide", route_explore_react, {
        "continue_main": "continue_main",
        "end": END
    })
    graph.add_edge("continue_main", "decide")  # 循环回到 decide
    app = graph.compile()
    return app.invoke(state)
```

### 1.11 安全设计（SafeUnpickler）

#### 是什么
pickle 反序列化是 Python 的**最大安全漏洞**之一——恶意 pickle 可以执行任意代码。

#### guyu 怎么实现（自定义 SafeUnpickler）
```python
# /root/workspace/guyu/guyu_python/zhishiku/Agent/base.py 第 22-37 行
class SafeUnpickler(pickle.Unpickler):
    """只允许特定类的反序列化"""
    ALLOWED_CLASSES = {
        "langchain_core.prompts.chat": ["ChatPromptTemplate", "ChatMessage", ...],
        "langchain_core.messages.system": ["SystemMessage", "ChatMessage"],
        "langchain_core.messages.ai": ["AIMessage"],
        "langchain_core.messages.human": ["HumanMessage"],
        "builtins": ["set", "frozenset"],
        "_operator": ["getitem"],
        "typing": ["List", "Union"]
    }

    def find_class(self, module, name):
        if module in SafeUnpickler.ALLOWED_CLASSES and \
           name in SafeUnpickler.ALLOWED_CLASSES[module]:
            return super().find_class(module, name)
        else:
            raise pickle.UnpicklingError(f"Global '{name}' is forbidden.")

# 使用前还要验证文件 hash
SAFE_HASH = 'cda9dd02b1e8007189c755dbe174d7be7ebe6c0f41796733d5c0443d842c81c0'

@staticmethod
def verify_file_integrity(file_path, expected_hash):
    with open(file_path, "rb") as file:
        file_data = file.read()
        file_hash = hashlib.sha256(file_data).hexdigest()
    return file_hash == expected_hash

def set_prompt(self):
    if not AgentBuilder.verify_file_integrity("/app/prompt_backup.pkl", SAFE_HASH):
        raise ValueError("The file's hash does not match the expected secure hash.")
    
    with open("/app/prompt_backup.pkl", "rb") as file:
        unpickler = SafeUnpickler(file)
        prompt = unpickler.load()
```

**3 层安全**：
1. **SHA256 哈希校验**：文件被篡改就拒加载
2. **类白名单**：只允许 LangChain 消息类 + typing/builtins
3. **路径硬编码**：只能加载 `/app/prompt_backup.pkl`，不接受外部路径

- **必须**用 pickle 时，加 hash 校验 + SafeUnpickler

#### 你怎么回答（推荐话术）
> pickle 反序列化是企业 AI 的**隐性炸弹**——LLM 应用常把 Prompt / Skill 存 pickle 文件，攻击者只要能上传就能 RCE。
> 
> 我们的防御：① SHA256 哈希校验文件完整性；② SafeUnpickler 类白名单只允许 LangChain 消息类；③ 路径硬编码不接受外部输入。
> 
> 实战教训：早期用 JSON 存 Prompt 没事，后来为了性能切 pickle 才暴露风险——补了 SafeUnpickler 才上线。
