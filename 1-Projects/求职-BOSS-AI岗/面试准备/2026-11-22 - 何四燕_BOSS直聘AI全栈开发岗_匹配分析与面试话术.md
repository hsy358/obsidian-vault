## 四、公司画像与战略判断

### 4.1 这家公司要的是什么人？
从 JD 的三条线索反推：
1. 要求写"**独立完成**从需求到上线的完整开发交付" + "**可独立完成** AI 应用全栈搭建与迭代" → **他们没有配齐前端/后端/算法团队，要一个人扛整条链路**。
2. 要求写"3年以上" + "**了解**数据湖、数仓基础架构" + "**可快速适配**业务与产品需求" → **他们知道这活不好招，所以主动放宽了数据侧门槛**，找的是"**AI 应用全栈 + 能落地 + 能自己把数据用起来**"的人，而不是数据架构师。
3. 职责 3 写"配合 AI 产品经理、数据项目PM及架构师团队" + 职责 4 写"**沉淀经验、规范开发标准**" → **要么团队小、缺规范；要么想要一个能带规范的人**。

> 🎯 **结论**：这是一个「**找一个人把 AI 真正塞进现有 GIS/农业数据系统**」的岗位。对何大人意味着：**不是降级使用，是被当成技术一号位**。而"沉淀规范"恰好是他 SDD/AI Coding 的看家本领 —— **这是他能力结构与这家公司需求重合度最高的一次**。

### 4.2 行业同构性（何大人独有的加分）

| 数溪的"慧种田" | 何大人的对应项目 | 同构点 |
|---|---|---|
| 政企/合作社客户、政府数字化 | **智慧城市惠企综合服务平台** | 政务/政企客户 + 审批流程 + 补贴/资质数据 |
| 农业多源时空数据 + 数据服务 | **集团数据中台与数据治理**（39 人团队） | 数据底座 + 数据治理 + 口径统一 + 对外数据服务 |
| 深度学习优化水肥药种（决策模型） | **徽商银行财富智能推荐系统** | 数据驱动的业务决策/推荐模型 + 效果指标（销售额 +30%、满意度 92%） |
| 知识/问答与智能体 | **平安云知识库 + Agent 智能体平台** | RAG + Agent 编排 + 知识治理（自主解答率 76%、查询 30min→5min） |

> 🎯 **"把行业知识变成可用的数据服务"** —— 这是两边的共同命题。而且**农业比金融更缺知识工程能力**（知识非结构化、农户不会用、样本稀疏、季节性强），他金融/政务那套"高要求场景交付"是降维打击。

### 4.4 一句话结论

> **这是一个"位置极好（雨花台区·同址）、场景高度同构（政企+数据治理+知识工程）、要求与能力高度重合（独立全栈+AI落地+沉淀规范）、但公司体量小、天花板低"的机会。**
> **建议：认真聊、认真谈薪，但不当主战场。** 它的价值是：**① 本地零通勤成本的保底；② 用他 SDD/AI Coding 这套"第二曲线"换一个能完全主导的位子；③ 一个能立刻开口的对话，用来校准市场报价。**

## 五、可直接用的话术

### 5.1 60 秒开场（针对数溪定制）

> 您好，我叫何四燕，14 年软件研发和大型项目交付经验，长期服务金融科技、政务数字化和智慧城市场景，也在南京工作。
>
> 我看贵司这个岗位写的是"独立完成从需求到上线的完整交付"和"沉淀经验、规范开发标准"，这两块正好是我最近几年的主线。
>
> **技术上**：这三年我负责平安云的知识库与 Agent 智能体平台——前端 Vue3、后端 Spring Cloud，AI 侧用 LangChain / LangGraph 做 RAG 和 Agent 编排（切分、QA 抽取、向量化、混合检索、Rerank、工具调用、Prompt 版本化、多模型切换、Token 预算、注入防御），从需求评审、方案设计、联调到上线运维全程负责，**这是我独立跑通的一条完整 AI 应用链路**。
>
> **数据侧**：2021 到 2023 年我带 39 人团队做集团数据中台与数据治理，把数据能力做成可复用的中台，供给下游的智慧城市惠企平台（政企客户）和徽商银行财富智能推荐系统。**数据怎么变成业务能力这一段，是我的主场**。
>
> **场景侧**：慧种田是政企/合作社客户、政府数字化、农业数据服务——这跟我做过的智慧城市惠企平台几乎是同一个问题域，只是行业数据更稀疏、更依赖领域知识。
>
> 我还想多说一句可能和常见候选人不太一样的地方：除了做功能，我更擅长**把落地经验沉淀成规范**。我们内部用 SDD（规格驱动开发）和 AI Coding 质量门禁，把"先写规格再写代码"做成可执行流程，交付质量和复用效率明显提升。如果 JD 里"规范开发标准"是真需求，这块我可以直接上手。

### 5.2 「数据湖 / 数仓」怎么答（这家的真实语境）

> 我在集团数据中台与数据治理项目里负责的是**数据服务的应用侧和治理侧**：数据从底层平台出来，经过治理和口径统一，供给上层业务应用，包括后来的智慧城市惠企平台和徽商银行的智能推荐。
>
> **我最强的是"数据怎么变成业务能力"这一段**；底层的选型和引擎运维不是我最强项，那是我想补的部分。你们这边是空间/遥感这类时空数据，我理解它对数据治理口径、对时空索引、对样本稀疏度的要求会比一般业务数据更高 —— 这也是我觉得有意思的地方。

### 5.3 「为什么 14 年经验投这个岗」

> 我带过 20–40 人的跨职能团队，但**一直不想放弃一线**。AI 落地那段路——需求怎么变成规格、模型怎么接进系统、效果怎么验收、上线怎么运维——必须自己写过才敢说。所以这不是降级，是回到我最想深耕的那一段；而协同和交付，本来也是我一直在做的。
>
> 另外说实话，我看到贵司写"独立完成全栈搭建"，我反而**挺想做**——早期产品里能自己把一条链路从头打通的机会不多，我想看看在时空数据这个场景上，AI 到底能落到实处哪一步。
