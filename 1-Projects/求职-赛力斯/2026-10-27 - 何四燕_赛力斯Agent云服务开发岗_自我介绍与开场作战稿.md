# 自我介绍与开场作战稿（3 版本 + 开场规则）

> **写于 2026-10-27**
> **用途**：补齐求职包最后一块拼图——**开场 90 秒**。前面几份文档（匹配分析 / 硬骨头 / 反问 / 题库 / 关键词）都假设"你已经自我介绍完了"，这一份负责开头。
> **铁律**：三版说的是**同一套事实**，只是压缩比不同。**不许为了顺口加任何没做过的经历**——车端、座舱、HMI 一个字都不编。

## 〇、公式：自我介绍 = 定位 → 硬证据 → 岗位连接 → 钩子

| 段 | 时长占比 | 内容 | 反例（别这么讲） |
|---|---|---|---|
| **① 定位** | 15% | 14 年后端 + 近三年 Agent 平台 0→1，一句话点出赛道 | "我是一个热爱技术的开发者…" |
| **② 硬证据** | 45% | 只讲 **1 个项目（guyu）** + **1 个数字**，讲出"底层是我写的" | 罗列五个项目流水账 |
| **③ 岗位连接** | 30% | 明确说出"你们 JD 的第 X 条，我做过对应的 Y" | "贵司平台很有前景，希望加入" |
| **④ 钩子** | 10% | 一句让对方想追问的话 | "以上是我的介绍，谢谢" |

> **为什么只讲一个项目**：14 年经历最容易犯的错是"面面俱到 = 面面不深"。技术面官只记得住**一个有细节的故事**。guyu 是你最硬的牌，也是唯一能覆盖 JD ①②③⑤⑥ 的牌。

## 一、版本 A：60 秒（HR 初筛 / 群面 / 时间被压缩）

> **场景**：HR 电话初筛、群面轮流自我介绍、对方明确说"简单介绍一下"。
> **目标**：让对方记住 3 个词——**平安云 Agent 平台、LangChain/LangGraph、14 年 Java 后端**。

> 面试官好，我是何四燕，本科毕业于中原工学院信息与计算科学专业，做后端开发 14 年，其中最近三年主要在做 **AI Agent 平台的从 0 到 1**。
>
> 最有代表性的一段是在平安云科技做 **guyu 知识库与 Agent 智能体平台**——可以理解为平安内部的 Coze。**平台的 Agent 编排底层，包括 LangChain/LangGraph 状态机、配置驱动的 Tool 动态 Schema、提示词版本化与完整性校验、RAG 混合检索加重排、以及 Redis/MySQL/Kafka/Milvus 这一套数据层，都是我这一侧负责的。**
>
> 之前在润和软件做金融科技基础平台，是 Java 和 Spring 体系，**14 年主线是 Java 后端 + 高并发与稳定性**；再往前在数据中台做平台化 0 到 1。
>
> 看到贵司这个岗位是**座舱 Agent 的云端中台**，我判断我的匹配点很集中：Agent 工程化、Tool 服务、并发调度、上下文与记忆治理、埋点回流这五块我都做过。**座舱和车联网我没有行业经验**，但座舱最难的端云一致性和弱网降级，我在生产环境踩过坑，能直接讲。
>
> 以上，谢谢。

**这段话的设计**：最后一段**主动承认空白**，但立刻接上"能直接讲"。这比等对方问出来更可信，也把话题引向你准备最熟的地方。

## 二、版本 B：90–120 秒（技术面主用版 ⭐ 默认用这版）

> **场景**：技术一面、简历已投递并被翻过、标准开场。
> **目标**：讲清 guyu 的**技术分层**，并逐条对上 JD。

> 面试官好，我是何四燕，信息与计算科学本科，做后端 14 年，**主线是 Java/Spring 的高并发与平台化，近三年转到 AI Agent 工程化**。
>
> 我讲一个最能代表我的项目——**平安云的 guyu 知识库与 Agent 智能体平台**，是平安内部的自建 Coze。我在里面负责 **Agent 执行侧的底层链路**：
>
> **第一是编排层**，用 LangChain 0.2.0 加 LangGraph 状态机，把多 Agent 协作、工具注册、上下文组装都建模成节点和状态转移，不是简单地套一个 chain。
>
> **第二是稳定性**，这块我踩坑最多：模型调用做了**分级超时、限流、熔断降级和失败回退**，工具异常不阻断主链路；高并发走 Flask 加 gevent 协程，长响应走流式保首字时延，异步任务走 Kafka 削峰。
>
> **第三是上下文与记忆治理**，我把上下文拆成**固定指令、会话状态、检索片段、长期记忆、护栏**五层，用 Token 预算做三级裁剪和丢弃优先级，短期态放 Redis、长期记忆和业务数据分别落在向量库和 SQL 上。
>
> **第四是数据层与可观测**，Redis、MySQL、Milvus、Elasticsearch、Kafka 多模型工厂，配 Trace 和命中日志，用来做运营反馈闭环。
>
> 这四层其实正好对应贵司 JD 里的 **Skill 提示词工程、Tool 服务、并发调度、K-V 与 SQL 数据层、检索与记忆集成**。我们做的是企业侧，座舱场景我没有行业经验，**但端云职责怎么切、记忆怎么同步、弱网怎么降级，我按这套方法论能给出一套具体方案，而不是空谈。**
>
> 另外我也在交付侧带过团队，做过 39 人平台化交付和大模型应用落地方案。**您想先听哪块，我把细节展开。**

**最后一句是关键**：把"选哪块讲"的主动权交给面试官，同时暗示你有多个可讲的深度区。

## 三、版本 C：3 分钟深讲（技术负责人 / 交叉面 / 对方说"详细讲讲"）

> **场景**：总监面、二面、对方明确要架构视角、或第一句就是"你讲讲 Agent 平台怎么设计的"。
> **目标**：从**架构分层 + 一个真实故障 + 一个取舍**三段推进，而不是功能罗列。

> 面试官好，我是何四燕，14 年后端，最近三年做 Agent 平台的 0 到 1。我按**架构分层 → 真实问题 → 取舍**三段讲，三分钟。
>
> **一、分层。** 我做的这类平台，抽象上是四层：**接入层**（对话入口、API、埋点）、**编排层**（LangGraph 状态机、Skill/Prompt 资产管理、Tool 注册与调用）、**能力层**（RAG 检索、记忆读写、业务工具服务）、**数据层**（Redis 会话态、MySQL 业务与配置、Milvus/ES 向量与检索、Kafka 异步）。这四层之间用**明确的契约**隔开：编排层只认 Tool 的 schema 契约，不关心工具背后是 Java 还是 Python；数据层的更换不影响编排层。
>
> **二、真实问题。** 最有代表性的一次是在生产环境里，Embedding 服务把设备写死成 `cuda:0`，多实例一起跑就开始互相抢显存，请求大面积超时。**当时的处理是三步**：先把 Embedding 调用从模型工厂里解耦出来、走可配置路由；再加**分级超时**——检索类调用给短超时、生成类给长超时，超时降级为"跳过检索、走纯提示词回答"；最后是**失败回退**，工具和检索都不允许阻断主链路，宁可答得糙一点也不能白屏。这个坑让我形成了一个判断：**Agent 平台的稳定性不在模型侧，在编排层对每一步的超时、隔离和降级设计上。**
>
> **三、取舍。** 举两个：一是我们**没有把所有知识都塞进上下文**，而是用 Token 预算做三级裁剪，宁可丢检索片段也不丢指令，因为指令错一次会错很多轮；二是**长期记忆我们做了保守策略**——宁可少记不错记，因为错误记忆会持续污染后续所有对话，正确记忆的收益是边际递减的。这两个取舍都不是技术最优，是**业务风险最优**。
>
> 座舱场景我确实没做过。但您这个岗位的四个难点——**端云职责切分、上下文同步、弱网降级、大模型时延稳定性**——在方法论层面是通的：我的做法是端侧持有可独立工作的能力子集，云端做复杂推理和跨域数据，同步用**版本号 + 增量 + 幂等键**做契约，车机侧用**最后写入者胜出**做不了，得按业务域做字段级合并。
>
> 以上是我的核心经历。您想深挖哪一层，我配合源码级细节讲。

## 四、开场破冰规则（自我介绍之外的前 30 秒）

| 场景 | 做法 | 话术 |
|---|---|---|
| 对方还没看简历 | **主动给定位**，别问"您看我简历了吗" | "我先用一分钟给个定位，然后您随便问——我猜您最想听的是 Agent 平台那块。" |
| 简历已看 | **顺着简历里最刺眼的一条接** | "我看到您标了 LangChain/LangGraph。我这套正好是在 LangGraph 状态机上做多 Agent 协作，最有意思的是中断恢复那块。" |
| 对方是 HR（不懂技术） | **把技术词翻译成业务词** | "简单说，我做的是**让企业自己搭 AI 助手**的平台，类似 Coze。我负责的是底下让它跑得稳的那一层。" |
| 对方是技术负责人 | **直接抛架构判断** | "先说我的判断：这类平台真正的难点不是模型效果，是**上下文预算和失败降级**。我按这个思路展开。" |
| 对方明显赶时间 | **用版本 A，说完主动问优先级** | "我先简单说下，您告诉我最关心 Agent 平台还是高并发，我直接展开。" |

## 五、项目开场钩子（对方点名某个项目时怎么起头）

### 5.1 讲 guyu（一句话定调，10 秒内说完）

> "guyu 是平安云的知识库与 Agent 智能体平台，可以理解为**平安版的 Coze**。我负责的是**执行侧的底层链路**——从用户提问进来，到编排、检索、调工具、拼上下文、调模型、流式吐字、落库与埋点，这一整条我自己写过。"

→ 这句话定调之后，面试官通常会问"那举个具体的"或"难点在哪"，你已经站在了自己的主场。

### 5.2 讲润和金融科技平台（稳扎稳打型）

> "润和那段是金融科技基础平台，纯 Java/Spring，**高并发、高可用、数据一致性**是我在那儿的基本功。做了缓存和负载均衡优化，响应时间降了约 40%。"

→ 只讲机制和数字，不展开。技术面官对第二段经历只需要确认"基本功扎实"，不需要细节。

### 5.3 讲数据中台（0→1 平台化，讲架构不讲功能）

> "数据中台是我第一次做**从 0 到 1 的平台**，核心是数据标准、资产治理和给上层业务提供统一口径的数据服务。当时支撑 39 人团队的交付。"

### 5.4 讲惠企平台（对应 JD 的"场景引擎"）

> "惠企平台是政务场景的**政策匹配与兑现流程系统**：政策标签化、条件结构化、匹配规则引擎、审批流自动流转、兑现进度可视化。我做的是**架构和规则引擎这一层**，前端控制台和进度看板是我带的 Vue 团队做的。"

→ 这段是**给 JD"场景引擎"准备的**，务必主动讲，别等对方问。

## 六、不能说 / 不要主动说的清单（红线）

| 不说 | 原因 | 正确替代 |
|---|---|---|
| QPS、并发数、日调用量等具体数字 | 无可验证数据，一问就穿 | 讲机制："限流 + 优先级队列 + 超时熔断" |
| "我做过座舱 / 车端 / HMI" | 纯空白 | "行业没做过，但端云一致性和弱网降级我在生产踩过坑" |
| Kotlin | 不熟，JD 写 "Java 或 Kotlin" 已达标 | 只讲 14 年 Java |
| TypeScript / React | 未写过 | 只说 Vue，"可快速迁移" |
| "我带过 40 人团队" | 39 人是**项目交付团队**，不是汇报线团队 | "带过 39 人规模的交付团队" |
| 主动提"我想做管理" | 技术岗减分 | 讲技术决策权 |
| 说"贵司这个岗位要求太高我可能不够" | 自我否定 | 不确定的地方统一说"这块我没做过，我的思路是……" |
