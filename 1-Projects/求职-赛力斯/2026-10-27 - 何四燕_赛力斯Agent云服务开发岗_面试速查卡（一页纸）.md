# 🎯 面试速查卡（一页纸 · 打印版）

> **写于 2026-10-27** ｜ 面试前 10 分钟默念一遍 ｜ 打印或手机备忘录存一份

---

## 一、四个必带数字（只这四个，别多背）

| 数字 | 含义 |
|---|---|
| **14 年** | 后端研发总年限 |
| **LangChain 0.2.0 + LangGraph** | 编排层技术栈（guyu） |
| **40%** | 润和缓存/负载均衡优化 → 响应时间下降 |
| **39 人** | 数据中台时期支撑的交付团队规模 |

---

## 二、guyu 四层速记（讲什么、怎么讲）

```
接入层  → 对话入口 / API / 埋点
编排层  → LangGraph 状态机 · Skill(Prompt 版本化+SHA256) · Tool 动态 Schema · 上下文组装
能力层  → RAG 混合检索+Rerank · 记忆读写 · 业务工具服务
数据层  → Redis 会话态 · MySQL 业务/配置 · Milvus/ES 检索 · Kafka 异步 · 多模型工厂
```

**一句话定位**：*平安版 Coze，Agent 执行侧底层链路是我写的。*

---

## 三、上下文五层 + Token 三级裁剪

| 层 | 内容 | 存哪 |
|---|---|---|
| 固定指令 | System Prompt / 护栏 | Prompt 资产 |
| 会话状态 | 多轮短期对话 | Redis |
| 检索片段 | RAG 命中知识 | 向量库/ES（上下文内只是片段） |
| 长期记忆 | 用户偏好、情景记忆 | 向量库 |
| 业务数据 | 权限、订单等实时数据 | SQL |

**裁剪优先级（先丢什么）**：检索片段 → 历史对话 →（**指令与护栏永不丢**）
**理由**：指令错一次，错很多轮。

---

## 四、稳定性四件套（讲机制，不报数字）

1. **限流**：令牌桶，保护模型与下游
2. **分级超时**：检索短超时 / 生成长超时
3. **熔断降级**：超时即跳过检索，走纯提示词回答
4. **失败回退**：工具/检索异常**不阻断主链路**

**真实坑（最好讲的一个）**：Embedding 服务设备写死 `cuda:0` → 多实例抢显存 → 大面积超时 → 解耦路由 + 分级超时 + 失败回退。

---

## 五、Tool 服务六步

```
注册（配置驱动动态 Schema）→ 路由 → 鉴权/签名 → 执行（超时·重试·幂等）→ 结果组装 → 埋点/Trace
```

**关键原则**：编排层只认 **schema 契约**，不关心工具背后是 Java 还是 Python。

---

## 六、端云三条同步策略（座舱专属）

| 策略 | 用法 |
|---|---|
| 版本号 | 端云上下文带版本，防乱序覆盖 |
| 增量同步 | 只传差异，不全量 |
| 幂等键 | 重放不产生副作用 |

**⚠️ 车机侧不能用 LWW（最后写入者胜出）**：车机断网时间长，晚到的云端消息会覆盖车机新状态 → 需按业务域做**字段级合并**。
**底线**：端侧要持有一份可独立工作的能力子集——**离线也能开空调、导航**。

---

## 七、五个红线（讲完对照检查）

- ❌ 不编 QPS / 并发数 / 日调用量 → 只讲机制
- ❌ 不说做过座舱 / 车端 / HMI → 如实说行业空白
- ❌ 不主动提 Kotlin、TS/React
- ❌ 不说"带过 40 人团队" → 说"支撑 39 人交付"
- ❌ 不说"岗位要求太高我可能不够"

---

## 八、反问首问（挑一个即可，别问薪资）

> **"目前座舱 Agent 的端云职责是怎么划分的？哪些能力端侧必须持有一份（离线也要能用）？"**

后手：*"云端做编排不代表端侧是薄的——车机断网是常态。"*

---

## 九、面试当天动线

1. **进房间前**：默念红线清单 + 四个数字 + 自选版本（默认版本 B，90–120 秒）
2. **开场**：定位 → guyu 四层 → 岗位连接 → 钩子
3. **正题**：每题用万能收束句——*"这个问题我拆成三层看：**数据存哪、链路怎么走、失败怎么兜**。"*
4. **被问不会的**：*"这块我没做过。我的思路是……"* —— 不编、不慌、不沉默
5. **反问**：Q1 端云职责 → Q2 Tool 服务形态 → Q3 上下文存储选型
6. **结束**：*"我今天讲的都是我自己写过的东西，具体代码和文档我都可以展开。"*
