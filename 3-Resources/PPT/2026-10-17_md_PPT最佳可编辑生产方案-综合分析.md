# PPT 最佳可编辑生产方案 —— 全库综合分析

> 结论先行：**"可编辑"是红线，原生 PPTX 路线是正解；质量靠"结构先行 + 内容视觉分离 + 渲染自检闭环"保证；最高效的方案不是某个单一工具，而是一条"受众蒸馏 → 结构规划 → 参数化风格 → 素材级生图 → 原生装配 → 逐页质检"的流水线。**

## 二、选型决策树（写 PPT 前先答两问）

**第 1 问：出稿还是磨稿？**（源自 05-13 实测文）
- 出稿（快速能用的简报/概览）：AI 替你做完 —— 模板填充类即可
- 磨稿（汇报/路演/长期资产）：AI 陪你做 —— 逐页可介入的流水线 ⭐ 我们的主战场

**第 2 问：交付物是什么？**（源自 07-25 十大神级）
- 浏览器播放 / PDF → HTML 路线（guizang / frontend-slides）
- **客户要改 / 要汇报 → 原生 PPTX 路线（默认选项）**
- 要 AI 操作已打开的 PowerPoint → MCP 自动化（mcp-server-ppt，仅 Windows + 桌面 Office）

**可编辑性光谱**（从高到低）：
```
原生操作(PowerPointCOM) > 原生对象生成(SVG→形状/python-pptx/PptxGenJS)
> HTML→文本框翻译(huashu) > HTML 路线(图片式导出) > 整页生图(不可编辑)
```
⚠️ 一票否决：**整页 AI 生图合入 PPTX = 文字画进图片 = 不可编辑**（baoyu-slide-deck 类，只用于科普卡片场景）。图像派 PPT 的官方评价："本质是图像级仿写，不是原生级复刻——成品可编辑性受限"。

## 三、推荐主方案：七阶段可编辑 PPT 流水线

```
阶段0 资料入库 → 阶段1 受众评审蒸馏 → 阶段2 结构与页型 → 阶段3 风格参数化
→ 阶段4 素材级生图 → 阶段5 原生装配 → 阶段6 渲染质检闭环 → 阶段7 交付与沉淀
```

### 阶段 0：资料入库（上游预处理）
- 旧 PPT/PDF/Word → **MarkItDown** 转干净 Markdown（`pip install 'markitdown[pdf,docx,pptx]'`），或 vault 内 knowledge-to-deck 整理成观点/证据/来源地图
- 原则：先让 AI "读懂资料"，再谈"做 PPT"

### 阶段 1：受众与评审蒸馏（先搞清楚"看的人脑子怎么转"）
产出三张卡（蒸馏一次，反复复用，建 `audiences/ + reviewers/ + styles/` 库）：
- **audience-card.md**：他想听什么 —— 注意力分配（前 3 页看什么）、决策启发式、信息呈现偏好（先总后分/数据优先）
- **reviewer-card.md**：他会挑什么毛病 —— 审查维度、合格标准、否决点、加分项（例：政府汇报→数据闭环+抓手逻辑；融资→商业逻辑+否决原因）
- **style-card.md**：视觉参数化 —— 色值/字号/间距/禁忌全部写死（生成阶段零自由发挥）
- 同一人可双角色一次蒸馏；红蓝对抗：重要汇报前用双卡逐页打分

### 阶段 2：结构与页型（PPT 的"施工图"，不急着做页面）
- 故事线总控：consulting-deck-os 定受众/目标/页面结构
- **页型映射**：每页挂标准页型（封面/目录/过渡/观点/数据图表/对比/流程/架构/案例/大数字/图文/引言/矩阵/列表/地图/时间轴/总结）
- 每页五要素：**观点型标题**（"三年缩短办事时间 87%"不是"项目背景"）+ ≤3 要点 + 视觉建议 + 素材 prompt + 讲稿备注
- 证据链完整：每个观点有数据/案例；数据必须标注来源（否则 P0 风险）
- 每页 ≤50 字（达标线 45 字）；复杂单页图（架构/流程/能力地图）→ editable-architecture-ppt

### 阶段 3：风格参数化
- 用 style-card 对五种常见风格一句话切换：蓝色汇报（深蓝#003366+橙强调）/ 苹果风 / 麦肯锡风 / TED 风 / 数据驱动
- 品牌合规提效法（huashu-design 实测方差降 5 倍）：抓官方品牌页 → 脚本抠色值按频率排序 → 固化进 style-card → 后续全部引用真实色值

### 阶段 4：素材级生图（内容与视觉分离的关键）
- **生图只做"素材"，不做"整页"**：封面主视觉（无文字+暗色+留白）、概念插图、模块化图标、信息图单元素
- 成品整页图 ≠ PPT；文字、数据、表格必须在 PPT 里靠原生对象承载（"图片里的文字再好，也不如原生文本可控"）
- 截图类素材过一遍生图模型重绘：比例留白统一，整册像同一个人做的

### 阶段 5：原生装配（可编辑性的核心实现）
技术选型（任选其一，环境里都已具备）：
- **ppt-production-engine + pptx skill**（本环境已装，html2pptx/PptxGenJS）→ 真 PowerPoint 原生对象
- **python-pptx**（需模板时首选）：读 template.pptx 复用母版品牌色；**原生 chart 生成**（改数图表跟着变，这是可编辑的验金石）
- SVG 中间页 → 转换为 PowerPoint 原生形状/文本框/表格（ppt-master 思路；SVG 复杂效果不能保证全保留，图表优先原生）
- 存量图片稿要改字 → GordenSuperPPTSkills 思路拆解还原（能挪不能改内部线条；以后要更新数据的页应重做原生图表）
- 一稿多版：同一结构文档批量出 full（汇报）/ brief（邮件）/ summary（电梯）

### 阶段 6：渲染质检闭环（所有文章的共同命门）
三条纪律：
1. **第一版不是最终版** —— 渲染 → 截图 → 逐页检查 → 修正 → 再生成
2. **生成成功 ≠ 交付完成** —— 交付前必须真打开验证四件事：改一个标题、换一张图、更新一个图表数字、播放一遍
3. **三页先行** —— 封面 + 普通正文 + 最复杂的一页，确认后才批量生成

配套动作：
- 评审三检查（受众/评审/风格三视角） → 输出 **P0/P1/P2 修改清单** → 先改 P0 → 重生成 → 复检；**1-2 轮收敛，3 轮封顶**
- 某页放不下 → **删减或拆页，永不缩字号**
- 本环境落点：ppt-quality-review（逻辑/版式/可编辑性/文字可抽取/是否整页图片）+ verification-before-completion（文件存在/包结构/文本抽取/对象数量）

### 阶段 7：交付与沉淀
固定交付物（在原 5 件套上补三张卡）：
```
project/
├── deck-plan.md              # 故事线与受众定位
├── slides.json / structure   # 页级结构（页型+观点+素材prompt+备注）
├── audience-card.md          # 受众卡（沉淀复用）
├── reviewer-card.md          # 评审卡（沉淀复用）
├── style-card.md             # 风格卡（品牌色值固化）
├── assets/                   # 生图素材（PNG，非整页图）
├── preview.html              # 高保真预览
├── build/generate-*.js|py    # 生成脚本（可复用）
├── project-editable.pptx     # 最终交付（可编辑 PPTX）
├── project-full/brief/summary# 多版本（按需）
└── process.md                # 过程记录 + 质检结果 + 迭代清单
```
volta 规范：vault 内只存 md/素材说明，`.pptx` 走 sidecar 命名规范，产物文件存工程目录并在笔记中登记路径。

## 四、场景 × 方案速查表

| 场景 | 模式 | 首选路线 | 说明 |
|---|---|---|---|
| 政府汇报 / 重要领导汇报 | 磨稿 | 原生 PPTX + 双卡蒸馏 + 达尔文打磨 | 否决点：数据不闭环、回避困难、只讲理念 |
| 融资路演 BP | 磨稿 | 原生 PPTX premium（10 页内）+ 投资人否决蒸馏 | 蒸馏沈南鹏式评审做红蓝对抗 |
| 客户咨询交付 | 磨稿 | 原生 PPTX（麦肯锡风 style-card） | 客户要能改=压倒性需求 |
| 科研/技术汇报（公式多） | 磨稿 | PptxGenJS + OMML/LaTeX（powerpoint-skill） | 图表用原生 |
| 产品/架构/能力地图单页图 | — | editable-architecture-ppt → 插入正文 | 复杂单页图专用 |
| 内部周报/培训概览（出稿） | 出稿 | 模板填充即可，不用全套流水线 | 达尔文/蒸馏都不必开 |
| 分享会/品牌发布（PPT 当作品） | 磨稿 | HTML 路线（guizang/瑞士风） | 放弃逐字框可编辑性换视觉冲击 |
| 只有图片稿要改 | — | Image2PPTX 拆解还原 | 最后手段；要更新数据的页应重做原生图表 |
| 让 AI 操作已打开的 PPT | — | mcp-server-ppt（COM） | 仅 Windows + 装了桌面 PowerPoint |

## 六、十条"金律"（从 20+ 篇文章高频共识中提炼）

1. 可编辑是红线：客户要改 → 原生 PPTX，别走整页生图
2. 出稿磨稿先分明，模式错了工具再好也白搭
3. 高质量 PPT 是工程项目：结构 → 素材 → 装配 → 审校，不是一句话生成
4. 先蒸馏再动笔：受众怎么决策 ≠ 你想讲什么
5. 观点型标题 + 每页 ≤3 要点 + ≤50 字 + 数据必标来源
6. 生图是素材不是页面；文字/图表永远是原生对象
7. 第一版不是最终版；渲染→逐页截图检查→修正是交付前必经环节
8. 三页先行，确认后批量；改不动就拆页，永不缩字号
9. 迭代有终点：P0/P1/P2 清单，1-2 轮收敛，3 轮封顶
10. 每次生产沉淀三卡 + 页型库 + style 卡，下一次从 70 分起步
