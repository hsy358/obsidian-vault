# Rakazo —— 自托管的持久化 AI 队友平台

> **核心定位**：开源的 **Grok Bot 替代品** —— 给每个 bot 一个 **sandboxed browser + shell**，让它像"队友"一样持续运行、保存可复用的 Markdown 例程、定时执行，越权时主动停下等你确认。
> **官方原话**："Open-source Grok Bot alternative for persistent AI teammates that run on infrastructure you control."

> **2026-10-28 更新**：版本 v0.1.0-beta → **v0.3.5**，stars 1.7k → **6.1k**，forks 290 → **1.1k**，license 仍是 Apache-2.0。
> **重大变化**：官方 README 现在明确把自己定位为 **Grok Bot / Meta Muse / OpenAI Dots / Instinct / OpenClaw / Hermes Agent / Claude Duet 的开源自托管替代品**（9 月时还没提 OpenClaw 和 Hermes）。

---

## 一句话价值主张

- 跟一次性聊天的 ChatGPT 不一样：每个 bot 有**持久化上下文**（durable context），能跑完一次聊天后**继续工作**
- 每个 bot 都有 **sandboxed browser + shell**（浏览器和 shell 都在沙箱里跑，不会污染宿主）
- 例程保存为**可读的 Markdown**（不是黑盒 prompt），方便审计/复用/分享
- **自带调度器**（cron-like schedule）和**边界审批**（approval when crossing boundary）
- **自带你自己的模型 key**（BYO model key）+ **自选部署位置**（云/本地/桌面/手机）
- **多端一致**：Web / Electron 桌面 / iOS / Android 都是同一套 Rakazo API 的客户端

## 技术栈（TypeScript monorepo）

| 层级 | 选型 | 用途 |
|---|---|---|

| 数据库 | PostgreSQL + Prisma | 持久化 bot/context/routine |
| 任务队列 | Graphile Worker | 调度例程执行 |

> 跟 Hermes/OpenClaw 风格对比：同样是 TS-first monorepo，同样把"调度器 + 沙箱 + 持久化"做成一等公民。

## 核心特性

### 1. Persistent AI teammates（持久化 AI 队友）
- 不是一次性 chat，是**长生命周期 bot**
- 每个 bot 有**自己的 context store**（durable memory）
- 例程保存为**人类可读的 Markdown**（不是 JSON 配置）

### 2. Sandboxed browser + shell
- 浏览器自动化在**隔离沙箱**里跑
- Shell 命令在**受限沙箱**里执行（不是直接 root）
- 跨边界（写文件 / 调外部 API / 删数据）会**主动停下等审批**
- **Take control**：用户随时接管 bot 屏幕；Team bot 正在跑时会返回 HTTP 409（"Stop the bot first"）
- `request_takeover`：模型主动请求人工判断（登录 / 2FA / CAPTCHA），等待期间 computer 保持唤醒 **30 分钟**

### 3. Multi-surface deploy
- **Web**（浏览器直接用）
- **Electron 桌面**（本地跑，支持 **This computer** 本地起栈 / **Existing instance** 连远程）
- **Expo 移动**（iOS / Android）
- **自托管**（Hono + Postgres + Docker）

### 4. BYO everything
- 你带模型 API key（经 **Pi** 接入，OpenAI / Anthropic / OpenRouter / 自建都行）
- 你选部署位置（Railway / 自家机房 / 桌面 / 手机）
- 数据全部在你控制下（合规友好）

### 5. 多语言 UI
- Web UI：en / de / ko / tr / hi / pt-BR / **zh-CN** / 繁中 / es / ru / fr / he / nl / ja
- Expo App：en / **zh-CN** / 繁中 / de / nl / ja（7 个）

### 6. 生态扩展（v0.3.x 新增）
- **Composio** / **Pipedream Connect** —— 应用集成目录
- **Treg**（用量计费）、**远程 MCP**、**OpenAPI** 工具源 —— 用户可自行添加 HTTPS MCP server / Treg endpoint / OpenAPI JSON
- **Bots 可以互相委派**（delegate to peer bots）或派**短命 subagents**
- **共享 Team Computer** vs **隔离 Private Computer** 两种隔离级别
- **语音模式**：语音回复、听写、打电话（自带 ElevenLabs / OpenAI / Cartesia / Fish Audio key）

## 🆕 Computer Runtime 架构（v0.3.x 最重要的一节，2026-10-28 抓取）

> 这一节对德勤「执行器抽象层」**最有借鉴价值**。

### 分层：agent runtime 与 computer runtime 分离

```
chat/API -> one Pi agent session -> Rakazo computer tools -> SandboxProvider -> E2B / Daytona / Boat
                                                   |-> Docker
                                                   |-> desktop/fake
SandboxProvider workspace <-> AgentHomeStore <-> Rakazo-owned DATA_DIR
```

**关键点**：
- **Pi 跑在 Rakazo API/worker 进程里**，不装在 E2B 里、也不由 E2B 执行
- 内置工具是**普通 Pi 工具**，不是 Claude/MCP 专属工具 → **任何经 Pi 暴露的模型都能调用**
- 屏幕操作仍要求模型能接收图片工具结果并推理截图

### SandboxProvider 是 provider 边界

后端必须实现：
- **lifecycle**：provision/reconnect、stop、destroy
- **desktop**：observe、有序批量 action、用户输入、实时屏幕会话
- **execution**：机器内命令执行
- **files**：list/read/write + 完整工作区导入导出

### Team vs Private Computer

- 每个 workspace 默认一个 **Team Computer**，bots 共享其文件和已装工具
- 每个 Team bot 从 `bots/<bot-id>/` 启动，共享工作放 `shared/`
- ⚠️ **这些目录不是安全边界** —— 每个 Team bot 都能访问整个 Team workspace
- 改用 **Private Computer** 时，整个 workspace 就是它自己的 home
- 每个活跃 Team bot 有**自己的 X display 和 Chrome 进程**，**持久 Chrome profile 以 bot 身份为 key**
  → 登录、cookie、浏览历史互相独立；profile 不会从别的 bot 克隆、合并或删除
- Team runs 用 **fenced per-bot database leases**：不同 bot 可并发，一个 bot 同时只有一个 computer driver
- **安全边界是计算机容器本身**：Team bots 共享 OS 用户、workspace、浏览器 profile、shell/X11 访问
  → **需要真正隔离的负载必须用独立 computer**

### 浏览器工具

支持图形界面的 computer 上，模型可用：
`browser_navigate` / `browser_snapshot` / `browser_act`（取页面文本和元素 ref）

- 默认 `computer` browser provider 驱动可见的 Chromium 标签页，走沙箱的 `pageBrowser` 契约
- Docker 通过同一套 managed-screen + lease 检查实现该契约（需更新 computer image 装 helper）
- helper 使用**隔离 script world**、**遮蔽密码值**、**拒绝 stale refs**（不会指向已替换的元素）
- Snapshot 含受限页面文本 + 最多 **80 个**可交互元素
- 无视觉模型 → `request_takeover` 请人工操作
- 重复相同视觉动作而画面无变化 → `computer_act` 拒绝重复该动作，引导改用页面文本工具

### 屏幕租约与多桌面

- 所有桌面共享**一个 token 保护的 screen gateway** → 加桌面不需要发布更多端口
- 每个 view/control capability 指向唯一 local Unix socket；回收 display 不会把旧连接重定向给下一个 bot
- Docker 可设 `SANDBOX_TEAM_SCREEN_LIMIT` 限制活跃桌面数，超限返回 `MULTI_SCREEN_UNAVAILABLE`（shell 和文件工具仍可用）
- 桌面**懒启动**（bot 用图形工具时才起）；**不活跃的 bot 不会各跑一个 Chrome**
- 成功跑完后**保留该 bot 的屏幕和浏览器**（含已登录会话），下次复用

### Terminal

- Activity 视图实时记录 bot 在电脑上做了什么：每条 `computer.command` 事件（shell 命令脱敏 + 输出尾部；write_file / attach_file / open_path / launch_app 各一行）
- 只读工具（read_file / list_files）不记录
- 用户接管时可用交互式 shell：`computer.terminalUrl` 在 computer 内起小 PTY server
  - 绑定 display 的 control token，走同一条 sealed capability
  - **以 workspace 用户身份运行，绝不是 root**
  - 释放控制 / 过期 / 屏幕 teardown 时停止并清理 session 文件

## 与德勤项目的实质借鉴点 ⭐

何大人 2026-06-29 明确：**德勤 Agent 框架 = Hermes v0.14（唯一选择）**，但**整个工程栈要做成"每个组件可插拔 + 可独立部署"**。

> ⚠️ **2026-10-28 提醒**：Rakazo 官方 README 现在把 **OpenClaw 和 Hermes Agent** 列为自己的替代品之一。
> 这**不改变**「Hermes v0.14 是德勤唯一框架」的决策（6-29 决策不变），
> 但说明 Rakazo 已是同赛道竞品，**架构借鉴价值上升，替代风险也需评估**。

### 借鉴 1：SandboxProvider 抽象 ⭐⭐⭐（v0.3.x 新增，最有价值）

这几乎是**德勤执行器抽象层的现成范式**：

```
德勤 ExecutorAdapter          ←→  Rakazo SandboxProvider
  provision / reconnect          provision / reconnect
  stop / destroy                  stop / destroy
  observe / act / user input      observe / ordered batched actions / user input / live screen
  exec command                    execution: commands inside the machine
  read/write file + import/export files: list/read/write + workspace import/export
```

**要点**：provider 只负责"怎么在机器里干活"，**agent runtime（Pi）跑在上层**。
这跟德勤「Hermes 是唯一框架、但每种 harness 都能接」的思路完全同构。

### 借鉴 2：Markdown-as-Routine（例程可读化）
- 德勤的"AI Native 组织 Workspace"需要**让业务人员能看懂 Agent 在干嘛**
- Rakazo 把 routine 保存成 **可读 Markdown**（不是 JSON/YAML）—— 这个 UX 思路可以直接搬到德勤 MVP
- 业务专家能 review / edit / audit agent 的工作流程

### 借鉴 3：Agent runtime 与 computer runtime 分离 ⭐⭐
- 德勤 MVP 若也做"执行器适配"，就该学这一刀：**编排层不绑沙箱实现**
- Pi 在 API 进程，E2B/Docker 在外面 —— 德勤可以照搬：**执行器 adapter 与调度层解耦**

### 借鉴 4：自托管 + BYO model 的合规故事
- 德勤客户（金融/政府）**最在乎数据主权** —— Rakazo 的"全部在你控制下"卖点正好契合
- 可以作为**德勤 AI Native 方案对外宣讲**的参考架构（"对标 Rakazo 的合规能力，但加 Hermes 的组织能力"）

### 借鉴 5：调度器（Graphile Worker + Postgres）
- Postgres-native 调度方案，比 Celery/Redis 简单很多
- 可作为 **Hermes dispatcher 的 Postgres 后端**参考实现

### 借鉴 6：Team vs Private 双层隔离 ⭐
- 「共享 vs 独占」两级 computer 模型，对应德勤客户的**部门级共享 vs 个人专属**场景
- ⚠️ 但要注意 Rakazo 官方明确说 **Team workspace 的目录不是安全边界** —— 德勤交付时必须对客户讲清楚

### 借鉴 7：Computer Lease 模型 ⭐
- **fenced per-bot lease**：一个 bot 同时只有一个 computer driver，不同 bot 可并发
- 屏幕 view/control 用**可撤销的独立 websocket capability**
- 「回收 display 不会把旧连接重定向给下一个 bot」——这个防串号设计很值得抄

### 借鉴 8：审批护栏的粒度
- 官方最近提交有 `Preview approval rule changes on tool samples`（#2421）和
  `Name the saved rule that blocked a tool in the agent's refusal`（#2466）
- → **审批拒绝时要说清是哪条规则挡的**。德勤合规护栏应该同样给出**可读的规则来源**

## 部署快速通道

### 官方镜像（无需 clone，无需装 Node）

```bash
mkdir -p rakazo && cd rakazo
curl -fsSLO https://raw.githubusercontent.com/elie222/rakazo/main/infra/compose/install-images.sh
bash install-images.sh
```
- 需要 Docker Engine + Compose plugin + curl + OpenSSL
- 安装器下载 Compose 文件、生成含随机密钥的 `.env`、启动 Rakazo
- 重跑会**保留已有 `.env`**
- 打开 `http://127.0.0.1:5173`，建账号，连模型
- 默认镜像 tag 是 `edge`（main 构建，linux/amd64 + linux/arm64）

### 跑在服务器上（我们的场景）

```bash
bash install-images.sh --prepare-only
# 编辑 .env：SANDBOX_PROVIDER=boat（或 e2b / daytona / createos）+ API key，RAKAZO_HOST=your.domain
bash install-images.sh
```
- **端口 5173 前必须上 HTTPS**（Caddy 配置见 `docs/self-host.md` 的 public single-VM 部署章节）
- 桌面端选 **Existing instance** 输入 `https://` 地址
- 也可直接部署到 Railway（`rakazo-template`）

### 源码开发
- Node.js **22.22.2+（22.x 线）/ 24.x / 26+**；**不支持 23.x 和 25.x**
- pnpm 9 + Docker
- `POSTGRES_PASSWORD` 和 `POSTGRES_APP_PASSWORD` 要两个不同的 `openssl rand -hex 16`
- `BETTER_AUTH_SECRET` / `ENCRYPTION_KEY` / `SCREEN_PROXY_SECRET` 三个独立长随机值
- Docker sandbox 另需 `SANDBOX_SUPERVISOR_TOKEN`

### 受限网络
- `RAKAZO_DOWNLOAD_BASE` 覆盖下载源
- `--local` / `RAKAZO_DOWNLOAD_SKIP_EXISTING` 跳过已有 Compose 文件
- 可镜像 bootstrap 脚本 URL

### Linux 桌面 AppImage 的坑
- 需要 **FUSE 2**（`libfuse.so.2`）。只有 FUSE 3 的发行版（Fedora Silverblue、Ubuntu 24.04）会报
  `dlopen(): error loading libfuse.so.2`
- 装 `fuse-libs`（Fedora）/ `libfuse2t64`（Ubuntu 24.04）/ `libfuse2`（旧 Ubuntu/Debian）
- 或直接绕过 FUSE：
  ```bash
  chmod +x Rakazo-*.AppImage
  ./Rakazo-*.AppImage --appimage-extract-and-run
  ```
- **不认 Podman**，只找 `docker` CLI；可用 `RAKAZO_DOCKER_BINARY` 指定其他兼容 CLI

## 与 OpenWork 的横向对比（2026-10-28 新增）

> 何大人同时在看 OpenWork（`different-ai/openwork`，MIT，Claude Cowork 替代品），两者定位不同但有交集。

| 维度 | **Rakazo** | **OpenWork** |
|---|---|---|
| 定位 | 持久化 AI 队友（Grok Bot 替代） | Claude Cowork 替代（Agent 工作台） |
| License | Apache-2.0 | MIT（`ee/` 目录 source-available） |
| 语言/栈 | TypeScript monorepo | TypeScript |
| 数据库 | Postgres + Prisma（自带 RLS） | SQLite / MySQL（自托管） |
| 调度 | Graphile Worker（Postgres-native） | 无（cron 交给外部） |
| Sandbox | **一等公民**：Docker/E2B/Daytona/CreateOS/Boat/Railway + SandboxProvider 抽象 | 无（桌面端直接用本机 OS 权限） |
| 浏览器 | **sandboxed browser + 持久 Chrome profile per bot** | 内置浏览器（**仅桌面端**，Web 端没有） |
| 语音 | ✅（ElevenLabs/OpenAI/Cartesia/Fish Audio） | ❌ |
| 移动端 | ✅ iOS + Android（Expo） | ❌ |
| 多 bot 协作 | ✅ bot 互委派 + 短命 subagents | ❌ |
| 团队能力 | RBAC 弱 | **强**：SSO/SAML/SCIM/RBAC/审计日志/白标/花费限额 |
| MCP | ✅ 远程 MCP + Composio + Pipedream + OpenAPI + Treg | ✅ MCP Gateway（但只有 OpenCode 客户端 Verified） |
| 模型 | BYO（经 Pi） | BYO + 官方托管模型 + Auto Routing |
| 部署门槛 | Docker Compose + Postgres（中等） | 桌面 App 零门槛 / Web 托管 / Helm（完整但重） |
| Web 端 | ✅ 有（多端统一 API） | ✅ 有，但**读不到本地文件**（Rakazo 也有此限制：读的是 sandbox workspace） |

**结论**：Rakazo 更像「**有沙箱的运维自动化平台**」，OpenWork 更像「**有团队治理的 AI 工作台**」。
德勤要做的 AI Native Workspace，**Rakazo 的 SandboxProvider + OpenWork 的 RBAC/AI Gateway 两头都值得抄**。
