# Rakazo —— 自托管的持久化 AI 队友平台

> **核心定位**：开源的 **Grok Bot 替代品** —— 给每个 bot 一个 **sandboxed browser + shell**，让它能像"队友"一样持续运行、保存可复用的 Markdown 例程、定时执行，越权时主动停下等你确认。
> **官方原话**："Open-source Grok Bot alternative for persistent AI teammates that run on infrastructure you control."

## 一句话价值主张

- 跟一次性聊天的 ChatGPT 不一样：每个 bot 有**持久化上下文**（durable context），能跑完一次聊天后**继续工作**
- 每个 bot 都有 **sandboxed browser + shell**（浏览器和 shell 都在沙箱里跑，不会污染宿主）
- 例程保存为**可读的 Markdown**（不是黑盒 prompt），方便审计/复用/分享
- **自带调度器**（cron-like schedule）和**边界审批**（approval when crossing boundary）
- **自带你自己的模型 key**（BYO model key）+ **自选部署位置**（云/本地/桌面/手机）

## 技术栈（TypeScript monorepo）

| 层级 | 选型 | 用途 |
|---|---|---|
| 前端 Web | React | Web 控制台 |
| 桌面端 | Electron | 把 Web 打包成桌面 app |
| 移动端 | Expo | iOS/Android 客户端 |
| 后端 | Hono | 轻量 API 服务 |
| 数据库 | Postgres + Prisma | 持久化 bot/context/routine |
| 任务队列 | Graphile Worker | 调度例程执行 |
| Agent runtime | Pi | 沙箱内执行 |
| 容器化 | Docker | sandbox 隔离 |

> 跟 Hermes/OpenClaw 风格对比：同样是 TS-first monorepo，同样把"调度器 + 沙箱 + 持久化"做成一等公民。

## 核心特性

### 1. Persistent AI teammates（持久化 AI 队友）
- 不是一次性 chat，是**长生命周期 bot**
- 每个 bot 有**自己的 context store**（durable memory）
- 例程保存为**人类可读的 Markdown**（不是 JSON 配置）

### 2. Sandboxed browser + shell
- 浏览器自动化（Puppeteer/Playwright 类）在**隔离沙箱**里跑
- Shell 命令在**受限沙箱**里执行（不是直接 root）
- 跨边界（写文件 / 调外部 API / 删数据）会**主动停下等审批**

### 3. Multi-surface deploy
- **Web**（浏览器直接用）
- **Electron 桌面**（本地跑）
- **Expo 移动**（iOS/Android）
- **自托管**（Hono + Postgres + Docker）

### 4. BYO everything
- 你带模型 API key（OpenAI / Anthropic / 自托管都行）
- 你选部署位置（Vercel / 自家机房 / 桌面）
- 数据全部在你控制下（合规友好）

### 5. 多语言 UI
- Web UI 支持：en / de / ko / tr / hi / pt-BR / **zh-CN**
- 国际化做得不错（中文也原生支持）

## 与德勤项目的实质借鉴点 ⭐

何大人 2026-06-29 明确：**德勤 Agent 框架 = Hermes v0.14（唯一选择）**，但**整个工程栈要做成"每个组件可插拔 + 可独立部署"**。Rakazo 有几个组件正好可以**借鉴到德勤 MVP**：

### 借鉴 1：Sandbox 设计（Hono + Docker + Graphile Worker 三件套）
- 德勤 MVP 现在还**没明确 sandbox 层**用什么。Rakazo 的方案是 **Docker 容器 + Graphile Worker 调度**，可以做 Hermes 的 `ExecutorAdapter` 子层
- 重点：sandbox 边界审批（approval boundary）可以借鉴为德勤的**合规护栏**

### 借鉴 2：Markdown-as-Routine（例程可读化）
- 德勤的"AI Native 组织 Workspace"需要**让业务人员能看懂 Agent 在干嘛**
- Rakazo 把 routine 保存成 **可读 Markdown**（不是 JSON/YAML）—— 这个 UX 思路可以直接搬到德勤 MVP
- 业务专家能 review / edit / audit agent 的工作流程

### 借鉴 3：自托管 + BYO model 的合规故事
- 德勤客户（金融/政府）**最在乎数据主权** —— Rakazo 的"全部在你控制下"卖点正好契合
- 可以作为**德勤 AI Native 方案对外宣讲**的参考架构（"对标 Rakazo 的合规能力，但加 Hermes 的组织能力"）

### 借鉴 4：调度器（cron + boundary approval）
- 德勤 MVP 计划做**定时任务 + 越权审批**（M3 任务里提过）
- Graphile Worker + Postgres 是个**成熟稳定的 Postgres-native 调度方案**，比 Celery/Redis 简单很多
- 可以作为**Hermes dispatcher 的 Postgres 后端**参考实现

## 适用场景（官方 best-fit jobs）

- **重复性浏览器/Shell 工作流**：跑完一次聊天还想继续跑
- **Inbox / Sales / Recruiting / Expense / Support 等运营例程**：需要持久化上下文
- **自托管 AI 自动化**：凭证、会话、审计日志、模型选择必须可控

> 跟德勤目标客户画像高度重合 —— **金融/政府客户做运营自动化，最在乎合规和数据主权**。
